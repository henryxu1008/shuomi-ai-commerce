执行 [#1158](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1158)，关联 [#1092](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1092)。Design Basis 为 Independent Architecture。Admission Status 为 IMPLEMENTATION_READY。独立架构复核针对 `3cc20bb12` 完成且无剩余 finding，详见 [#1159 评审记录](https://github.com/henryxu1008/shuomi-ai-commerce/pull/1159#issuecomment-6710219951)。

## 用户结果

在「添加自有商品」上传图片、填写已知资料和文案偏好，生成一份可编辑候选。单规格和多规格共用现有图库、表单及保存。用户选用建议、确认图和 SKU 归属，点现有「保存商品」后得到一条可搜索和回读的自有商品。依据 2026-11-08 用户确认的首版范围，以及 Figma `11905:6356` 所表达的资料上传与按 SKU 整理流程。页面布局和导航沿当前产品决定。

范围只包含单件新增商品的资料整理。人工录入路径继续可用。批量导入、表格/链接/API 作为 AI 来源、已有商品自动覆盖、自动插正文、生成图片、绑定店铺及平台刊登留在现有各自路径。真实模型路由、价格及试用部署各自准入。无新增 Accepted Risk。

## 资料和候选合同

- 表单提交本次自然语言说明和当前图库中明确选中的有限图片引用。说明包含用户事实与表达偏好。服务端重验当前企业/成员、商品写权限和现有智能体使用权限，验证图片属于本次操作者在当前企业可读取的 SourceMedia。模型只接收有界预读的数据，图片文件走原字节、类型、归属和体积校验。链接可继续供图库使用，只有原 owner 证明可读的对象可进入模型。无可用路由时显示原因，手填和已选图片可继续使用。
- 现有内容智能体读取已保存的准确来源版本，本次输入还没有商品事实。新操作 `product.own.intake.generate` 在现受治理模型/Agent 运行中独立注册，使用现有文本与单图预读、配置/预算/确认、调用记录、Quote/InputHash 和结果读回机制。V1 对用户提供多张图库图，单次生成最多送入一张由用户选定的图片，沿现已支持的单图能力。其他图片保留在图库，仍能手工分配。没有适配证据的模型组合保持不可用。模型调用不用商品保存、平台工具或其他写工具。
- 结构化结果限定为商品名称、描述、通用属性、规格与在售组合、逐行字段建议、图库图片索引建议以及待确认项。价格是待确认建议，采用下文分层合同；库存、SKU、品牌、规格等字段只允许从用户明确提供的资料提取，引用输入片段并可供用户核对。图片识别值只作有图片来源的待确认建议。描述文案可以润色，证据不足或冲突显式标记。无法匹配的图片、重复组合、额外模型字段和越界值拒绝进入表单。缺项留空，保存时执行现有合同和下文的库存例外。
- 以显式组合清单为候选事实，规格维度只作编辑投影。用户说明「黑色 M/L，白色 M」时只有黑 M、黑 L、白 M。只有在界面上确认全部组合时才复用现有全组合生成。对候选组合按现有规范化规格身份匹配，重生成不覆盖非空人工值、不重新添加已明确移除的组合、不重分配已确认图片。用户可单独采用冲突建议。新候选不能绕过现有预算和重复校验。
- 公共图和 SKU 专属图继续由现有图库与逐行选择管理。候选只引用当前图号，不带新 URL 或自动写图。每个图号在确认时重新绑定当前图库条目，已移除或替换时提示重选。用户确认后才写入对应图片引用。正文仍由现有编辑器显式插图。

库存采用[库存建议与人工确认合同](own-product-intake-stock-review.md)：模型只输出带来源的 `stockSuggestion: {quantity, evidence}`，程序只校验严格结构、显式非负安全整数及原说明中逐字来源。所有库存建议须逐行确认才可填入空白表单，已有人工值含 0 不覆盖；未确认不妨碍其他有效资料采纳。省略表示未知，0 仅为明确的建议值，不默认确认。完整原说明可核对，输入变化、重新生成和原键读回替换清除确认。旧库存语义正则、直接 `stock` 字段、`stockReviewRows` 与 `ForReview` 投影退休；结构错误及伪造来源仍按原受限错误合同失败，原键、UNKNOWN、预算及保存协议不变。

价格采用[价格建议与人工确认合同](own-product-intake-price-review.md)：模型只提出带原文来源的 `priceSuggestion`，程序只校验结构、有限非负金额、币种格式和来源存在，不用自由文本语义正则证明价格。所有价格建议须逐行确认才可合入空白金额/币种对，缺币种只能手填；未确认不妨碍采纳其他有效字段，任何已有人工金额或币种均整对保留。完整原说明供用户核对，输入变化和候选替换清除确认。语义歧义不再造成整份候选失败，结构错误或伪造来源仍拒绝。

## 保存及库存声明

当前表单和 `ownProductSchema` 要求每个 SKU 填库存，HTTP 的库存验证和 Collection 发布对整次变更设置统一已声明标记。这会阻止真实保存三行中部分库存未知的商品。V1 在现有手工 `create_product` 和 `revise_product` 合同内按 SKU 表达缺省。库存字段缺省表示未填写，显式 `0` 和正整数表示用户已声明。拒绝 `null`、非整数、负值、越界。新增和编辑采用同一语义，编码和请求指纹区分省略与 `0`。可使用有存在性的数字字段，已有明确数字继续编码为原数字。

Collection owner 发布时逐行产生 Catalog 的可空库存及 `OwnStockDeclared`。显式 `0` 对应数值 `0` 且已声明，省略对应没有库存值且未声明。原 Excel 导入仍按原入口要求提供库存。价格、币种和 SKU 编码仍沿原 SKU 保存规则，缺项在候选显示，用户填写后才能保存相应行。详情和编辑回填保持未知与零的区别。平台侧继续按 `OwnStockDeclared` 和原规则决定是否要求补库存，不能从缺省数据派生可发布库存。已有发布版本不迁移、不重放，已声明数值的原编码与读回保持原语义。

## 接线与运行边界

| 合同与 owner | 接线与消费 |
| --- | --- |
| [图库与 SourceMedia](rich-description-simple-editor-images.md) 持有已确认媒体 | 原上传及核实 → 表单图库。原 owner 校验的图片字节和摘要经窄 reader 注入资料整理调用。 |
| 现 [内容智能体](product-content-localization.md)、[单图](product-image-visual-analysis.md)、商业调用与 Agent Run owner | 新资料整理适配器冻结本次输入、图片身份、配置和运行键，注册新操作和限定候选 validator。现有 Go 应用注入，前端沿同源 API 消费实际结果。 |
| [Collection 和 Catalog](own-product-entry.md) 持有商品版本和保存回执 | 候选仅合入现有可编辑表单。用户显式提交原商品命令，经原鉴权和 UoW 写入并返回一个商品标识。 |

### 未保存录入的绑定和快照

- `agent.Binding` 增加互斥类型 `own-product-intake-v1`，`ContextID` 为本次规范 UUID 命令键，`TargetPlatform` 固定 `product`。`ProductKey`、`CatalogVersion`、`PublicationID` 与其他专用 Binding 字段必须为空。其类型专属引用 `OwnProductIntakeRef` 只携带规范输入的 SHA-256，以及可空的已选图片内容 SHA-256。其他 ContextKind 禁止携带该引用。请求验证进一步要求 `Binding.ContextID == Request.Key`，同一个键不能通过另一个 ContextID 另开一次生成。该键既不代表商品，也不代表存储对象。
- 录入应用从可信身份解析企业、操作者、当前成员，重验 Collection 写和智能体执行权限。服务端规范化 UTF-8 说明（最多 4096 字节）、图库图片的稳定图号和顺序，以及单张预读图的图号和内容摘要，按固定 `own-product-intake-input-v1` 编码计算输入摘要。预读由 SourceMedia owner 以当前企业、当前操作者和内容哈希重建对象身份，再校验当前图片字节。客户端传入的 URL 或图号不能决定租户和存储键，也不作为任意外链拉取。用户在图库中的其他图片只提供有界图号与显式描述作为资料。
- `agentconfig` 新增仅面向 `product.own.intake.agent` 的固定 Agent/Policy/Prompt/候选 Schema 版本组合。`Prepare` 和 `LoadSnapshot` 对该组合显式匹配上述绑定、无模板/知识库/写工具、有界预算及已准入的模型 Profile。执行模式由现有 Agent 配置 owner 冻结，录入仅采用人工核对。`agent_configuration` 原配置快照记录成员、绑定和摘要、Agent/Prompt/Schema、模式及路由预算元数据，经现有 `ConfigurationSnapshotRef` 传入 Run。输入原文和图片字节仅存在于本次获准调用的请求内存，只有摘要进入配置快照，配置加载保持现有大小和完整性检查。使用 `product_agent_runs` 原作用域、ContextKind、ContextID、键和持久化状态；无需修改表或借用 `ImageAnalysisBinding`。复用后者下游有界单图传输和计量基础，保持商品图分析操作原校验独立。
- 准备和确认分别重验成员、权限、绑定和原输入。确认必须带原请求与所确认 Quote，服务端重新计算输入摘要并核对原快照；同键异输入拒绝，不能替换模型输入。Governed Model 的 `InputHash` 和 Quote 绑定快照摘要、当前执行身份、原调用键和可信路由/价格。尚未确认或能证明从未派发时，可重新提交原输入继续准备；如果发送结果不确定，只按原调用及 Run 键核实，未知不自动重发。Agent 的候选作为有界 `DomainProposal` 存在原 Run；专属 validator 匹配 Scope/Member、Binding、Snapshot 和真实调用回执，返回前验证类型、事实证据和冻结图库身份，表单采纳前复核当前图库。重开页面可凭原键读取同一运行及结果，鉴权需重新检查，读取不要求重新发送资料或触发模型。迟到结果只可应用在同一当前表单、相同企业成员和输入快照，输入/选图变化需重新生成。结果读取沿现有 Run 保留规则。

取消、超时和结果未知沿原运行和调用记录核实。已确认的用户表单值保留，失败可继续手工录入。商品保存、AI 调用和已确认媒体分别沿原 owner，失败不伪装成共同提交。无新业务事实表、跨库事务、迁移或第二运行系统。Legacy decision 为 N/A。

## 独立验收

隔离环境注入受控模型响应，走实际图库、表单、API、Collection/Catalog 保存与读取。输入黑 M、黑 L、白 M 和公共图、白色专属图，确认仅三行。补齐每行 SKU、币种和价格，黑 M 填库存 0，黑 L 或白 M 留空。保存前核对公共图、白 M 专属图与库存显示，保存一次后刷新、重新打开详情及编辑逐项核对。覆盖重生成保持人工值、缺省与 0 的请求指纹和发布投影、现有导入和平台未声明库存路径。录入绑定验证准备、确认、原键回读均不需要商品 ID，同键改说明/选图返回冲突，换企业或成员拒绝，调用未知时无第二次发送。正式模型及真实试用另行验证。

当前配置沿共享多模态路由消费 `product.own.intake.generate`，发布配置在 `productAgent.ownIntakePolicies` 声明该操作的独立配置。企业需启用「自有商品资料整理智能体」。没有当前路由、权限或额度时停止相应操作，现有手工录入仍可使用。

现有 PostgreSQL 隔离测试入口为 `TestOwnIntakeHTTPAndIsolatedBrowser`。使用任务自有的 `ISSUE398_TEST_DSN`，并在前端依赖与 Chromium 已准备时设置 `OWN_INTAKE_BROWSER=1`，可运行同一测试的浏览器路径。该路径通过 Next 转发和真实上传、生成、保存与读取接口，注入受控模型响应和临时媒体存储。
