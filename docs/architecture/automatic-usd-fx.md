# 平台美元参考汇率自动更新候选

状态：**NOT_READY，待独立架构评审**。执行任务 [#1249](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1249)。本文是设计候选，不表示代码、部署、现场发布或用户验收完成。

## 用户结果与范围

平台维护的美元模型参考价需要有效的人民币汇率，否则 Chat 等使用方无法报价。用户于 2026-11-12 同意平台统一自动更新：正常中间价变化无需逐次询问，仍须保持旧请求冻结、有效期保护和账本原语义。此决定在本任务范围取代[企业统一模型配置](enterprise-shared-model-configuration.md)中禁止自动抓取汇率的条款，不改变其他适用合同。

首期只处理 CFETS USD/CNY；不抓模型价、不新增货币配置平台、不访问模型或账单、不为每个企业维护汇率。实际接线、实例变更和真实模型调用另按用户授权执行。人工平台维护入口仍可使用；已确认的非美元记录、模型价和历史事实必须保留。

## 所有权与路径

`PlatformPricesService` 和现有 `ai_route_config` current/revision 是唯一价格事实 owner；本功能从固定官方来源取得一个候选，严格解析后读取当前快照，以原 `Publish` 的 expectedRevision、事务和回执发布修改后的完整快照，所有消费者继续使用原引用、校验与结算。不建立第二汇率表或旁路写库。新调度器默认关闭，采用仓库现有运行与调度能力；以下生命周期及注入方案须独立评审，不能通过构建启动时自动启用。

具体候选：在现有 Temporal 部署中使用单一平台专用 schedule 和专用任务队列，每小时触发一次无模型采集工作流；采用 schedule 重叠跳过和固定 schedule ID，失败后下次触发再读，不创建通用调度服务。已启用的后端启动时显式核对/创建该 schedule 并启动专用 worker；从未启用时不创建 schedule、不启动 worker、不读取来源。采集得到合格公告后，以平台、USD 和公告日构造确定性发布 workflow ID，使用拒绝重复执行策略启动持久发布工作流；保留期内拒绝重用，跨保留期另核对持久回执及当前公告日期。采集工作流只发现候选，公告与输入以发布工作流持久历史为准。多副本由 Temporal 的 schedule ID 和 workflow ID 去重，状态未知时遵守原回执规则。由启用转停用须先暂停已有 schedule，阻止积压新的采集，再有界停止 worker 并保留在途历史；恢复时先核对当前版本与原 UNKNOWN，不能直接执行积压的过期候选。启用、停止、重启、多副本与已有 schedule 的一致性必须验证，不能默默丢弃 UNKNOWN。该方案不改变统一汇率事实 owner。

全局停用只有在 schedule 已暂停、所有副本均不再领取工作、已开始的活动及其数据库事务全部终结且每笔原键结果已确认后，才能显示停用完成；随后不得继续写汇率。单个实例停止不代表全局停用；剩余副本、在途事务或回执不能确认时显示 UNKNOWN，不声称已停止。不得以取消 worker 推断提交回滚。启停和配置的全局协调及无新增事实源的可行性必须由实现验证，不能证明时停留 NOT_READY。

2026-11-12 用户决定：继续使用中国外汇交易中心 USD/CNY 中间价，允许通过其他接口获取，不转换为第三方混合参考汇率。获取渠道候选为 [Frankfurter](https://frankfurter.dev/) 的固定 provider 端点 `https://api.frankfurter.dev/v2/providers/cfets/rate/usd/cny`，不得使用默认混合报价或其他 provider。2026-11-12 只读观察为 `{"date":"2026-11-12","base":"USD","quote":"CNY","rate":6.7174}`；11 月 5、6、9、10、11、12 日与交易中心当日原始公告数值逐日相符。这是六日抽样而非持续准确性或服务承诺。

固定 HTTPS 主机及路径，不接受浏览器或配置传入任意 URL；设置超时、响应大小限制并拒绝异常重定向。必须严格校验日期、`base=USD`、`quote=CNY`、正的十进制数，精确乘 1,000,000 后成为整数；超过六位小数或溢出拒绝，不使用二进制浮点或四舍五入。日期不能为未来或早于当前已接受公告；HTTP 非 200、空响应、结构变化或无法判明币种时失败关闭。记录**实际获取渠道 Frankfurter、provider CFETS 和原始公告日期**；现有价格 `SourceURL` 表示原始公告来源而非声称直接从官方站点下载，实际渠道须有可持久核对的事实依据。必须验证这一来源表达符合当前合同，不能伪造来源。

该接口无需 API key、由第三方提供，可能延迟、缺失或更正；接口及原始数据条款分别适用，不能因开源或一次匹配就假定具有无限服务保障或官方授权。部署前核对适用条款及渠道稳定性；禁止以 Frankfurter 默认混合汇率、其他商业中间价或另一供应商静默兜底。

独立复核发现该第三方 [CFETS 适配器](https://github.com/lineofflight/frankfurter/blob/main/lib/provider/adapters/cfets.rb)使用浮点处理；本系统精确解析仅保证**接收到的数字**换算不引入额外误差，不能据此证明第三方转录全链逐位无误。固定 provider 仍可能晚到、缺失或修订；有效期结束后新价尚未可用时应停报，小时调度也可能增加等待。换渠道不会自动提供公告日历或保证不间断服务。

Temporal 已结束工作流历史按 namespace retention 清理，不能作为获取渠道永久唯一证据，也不能单凭拒绝重复 workflow ID 保证跨 retention 的永久去重。实现需优先验证现有不可变 revision 中固定可信 actor 能否区分采集渠道，加上官方 `SourceURL`、公告日、数值及持久 receipt 原键是否足以记录事实并核对重复；若不能，另设计原 owner 内最小来源字段，不默认新增归档或表。短期原始响应可保留在 Temporal 历史，但不能声称永久可查。该项为实现验证，若实际无法如实记录来源或安全去重，须停止并按具体后果重新分类。

## 版本、有效期及冲突

发布时保留全部模型价和其他币种；对 USD 合并新的不重叠时间段，不改写已冻结的引用。新公告的切换时刻为成功核验后服务端当前时间；在新 revision 中将覆盖该时刻的旧 USD 区间结束时间截短到切换时刻，再插入新 USD 区间。区间为左闭右开；切换时刻须晚于旧区间起点，且小于新公告按有效期计算的上界，否则停止。旧 revision 和已冻结请求的汇率、版本不修改。若已有未来生效的 USD 区间与候选重叠，不覆盖或截短未来预约，停止并通知维护者；同一日期不同价格视为更正候选，同样停下核对。

发布前将来源公告与当前已接受的最新 USD 公告比较：更旧日期一律不发布；相同日期和值为 no-op；相同日期但不同值停下核对。只有日期严格更新、且通过时效与来源校验的公告才可自动发布，CAS 冲突重新读取后必须再次比较，防止缓存或乱序使汇率倒退。

`FreezePlatformPrices` 当前限制快照最多 8 条 FX；不能每天无限追加。须确认历史请求从原 revision 或其冻结事实可恢复后，只在当前快照中裁剪已结束且不再影响当前解析的旧区间，历史 revision 和用量事实不修改；无法证明时停止发布并报告。新公告重复读取须幂等，不重复产生无意义版本。

发布输入从 current 快照复制所有价目和 FX 的原字段，但移除每条记录的 `Version`；现有 `FreezePlatformPrices` 对未变化项按内容保留原版本。不得将带版本的 current 直接提交，也不得重置未变化记录的其他字段。

周末或节假日若官方没有新公告，可继续使用最近公告，但不能在下一个公告工作日的发布窗口后沿用前一工作日价格。候选的失效时间为下一个已核验的中间价公告工作日上海时间 09:15；工作日及休市日须来自适用于该公告的官方日历，且覆盖相应日期，不能仅按周六周日猜测，遇调休也不猜测。日历不可证实时只给予至下一个自然日 09:15 的保守有效期，到期后停止报价。官方长假期间可在已核验休市日期内使用最近公告，恢复公告日到点仍未取到新价则停报。网络失败、响应异常或日期不可证实时不延长有效期，不清除既有记录；过期后沿原保护拒绝新报价。定时刷新与过期检查不改变已预留或已结算请求。

候选日历作为受限服务器配置，由平台维护者根据与中间价发布日直接相关的交易中心年度官方公告核验后提供，包含适用年份、来源和明确的开放/休市日期；不是另一份汇率账本，不自动下载未知年份或从其他市场日历推断。配置缺年、缺日、重叠或来源无法核验时走上述保守失效规则；到年末提前维护下一年，运行管理页应提示日历缺失。具体官方公告是否覆盖中间价发布日须在实际接线前核实，不能将拆借市场或外币对日历直接当成中间价日历。

并发人工发布必须以当前版本 CAS：冲突时重新读取并合并新快照，不能覆盖人工价格或其他币种；若人工更新同一 USD 生效区间或来源无法判断则停止并报告。发布身份必须是受限、可审计的平台服务身份，人工权限不因而放宽。由于 `PlatformPricesService.Publish` 本身不校验权限，服务 actor、价格 writer 数据库连接和启用开关只能在可信服务端装配中注入；不得接受浏览器或普通请求传入 actor、writer 或调度参数，也不借用用户会话。接线默认关闭，现有其他业务账号和权限不变。

候选执行采用现有 Temporal 持久工作流：唯一 workflow identity 包含平台、币种、官方公告日；同一天不同公告值不创建第二个自动发布。每个发布尝试在调用前将精确 actor、原幂等键、expectedRevision 和包含 VerifiedAt、切换时间、所有价格及 FX 的完整原输入固定到持久历史，重启恢复必须使用该原载荷和原键，不能用新的当前时间或重抓结果重建。发布成功、失败和未知按原回执对账：先 `Receipt`，回执匹配原命令则完成；无回执且原调用可能仍在途时保持 UNKNOWN，不使用新键或新载荷；只有原 owner 明确返回且可确认未提交的 CAS conflict，才允许重新读取、核对并以新的尝试身份合并提交。无法证明未提交则停下供维护者核对。重复调度、多副本、关闭和重启均遵循同一工作流身份及恢复协议，不能旁路持久历史或原回执。

工作流完成后同一公告不得产生第二次生效发布；活动超时后旧活动可能仍在途，其他活动的冲突不能证明原活动未提交。无法排除在途事务时继续保持 UNKNOWN。

## 运行与验证

面向维护者至少显示最近公告日期、适用汇率、有效期及更新失败/过期状态，复用已有管理入口；状态不得声称实时或成功，系统不可用时显示未知。调度与观测只服务本功能，不建设通用告警系统。

采用合成来源与隔离数据库验证：成功与无新公告、周末及长假、坏格式和异常来源、超时/不可用、过期、重复/并发与人工冲突、未知提交后的原键恢复、8 条限制、其他价格和其他币种保留、既有冻结请求与预留不变。还须验证关停后不会写入以及所有实例默认关闭。真实源只作只读访问，不调用模型；现场发布、部署和用户验收分别为 NOT_RUN。

## 评审待决

1. 官方数据源的稳定性与允许自动获取的依据，以及准确适用于中间价的官方公告日历、维护方式与不可用时的保守处理。
2. 使用现有调度能力的可重复执行、服务身份与启停边界；不能以人工权限或任意 URL 冒用平台 owner。
3. 历史汇率裁剪、精确冻结引用及未知结果恢复是否完整复用现有存储和回执。
4. 自动更新与人工 USD 发布冲突时的最终行为，以及有限界状态展示是否足以让维护者处理失败。
