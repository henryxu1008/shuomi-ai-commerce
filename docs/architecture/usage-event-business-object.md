# 用量明细的关联业务对象

Issue: [#1349](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1349)

Design Basis: Independent Architecture

Admission Status: IMPLEMENTATION_READY — 2026-11-17 独立 Reviewer `usage_arch_review` 复核，未发现 BLOCKER。权限拒绝、字段遮蔽、跨企业隔离及无准确任务关联作为实现验证。

## 用户结果和范围

2026-11-17 用户要求在现有用量详情中显示准确关联的店铺名、Amazon 商品和 AI 任务，并在 35444 试用。继续沿用原分类、账本及 1688 原商品查看路径。仅对有明确原始关联且当前有权查看的记录显示名称。资料未取得时可继续查看用量变动和原关联编号。

不新增写入、计费、存储、筛选、历史回填、通用关联服务或扩大已有权限；不以名称、时间、商品文案、任意前缀或客户端给出的候选编号推断对象。Amazon 首版显示原结果的商品名或 ASIN，AI 对象覆盖原调用能准确绑定的商品标题或内容任务。AI 模型调用详情使用「调用编号」。没有任务绑定时，原调用确认为聊天规划或自有商品录入的可显示该用途。图片调用沿用各自来源。

## 当前合同和事实 owner

复用[统一基础方案与预付资源](unified-base-prepaid-resources.md#6-权益用量与账户资源)、[当前领域 owner](project-boundaries.md)及原 Store、Amazon 结果、AI 任务权限合同。用量事实依然只由 orgresource 签发。对象事实从原 owner 待读取，名称为当时查询到的当前可读名称，账本不保存对象副本。

| 用量来源 | 固定精确关联 | 对象权限和返回 |
| --- | --- | --- |
| `store_service_v1`，店铺期数 | `source_identity` 为原操作编号。按企业及该编号读取 Store 服务意图，核对意图中的企业、操作及店铺 ID | 通过现有成员范围 Store 读库检查 `workbench.store.read` 和店铺分配关系，返回同一个店铺的 ID 与名称。只读 Store 行，不读取连接凭据或平台 |
| `amazon_data_v1`，数据条数 | `source_identity` 为已保存条目 ID。Data Acquisition 以当前企业、操作者、成员身份精确读取，核对原 job/item、Amazon 来源、发布 ID 与原商品凭据 | 复用 Amazon 结果的 live read 和已保存发布证明校验。只显示原结果允许展示的标题或 ASIN。原调用记录没有这些可显示字段时维持无对象 |
| `model_invocation_v1`，AI 点数 | `source_identity` 为原调用 ID。读取同企业原调用，核对用户、成员与标题/内容操作。以调用中的 Agent run ID 读取同企业同操作者的原运行，再按运行执行请求键精确查找唯一任务，核对任务类型及完整执行请求与运行一致。若调用同时带任务 ID，必须与查找到的 ID 一致 | 复用 AI 工作台 `bind` 的现有请求能力和实时 `workbench.task.read`、同企业和调用人任务读取及详情现有业务范围/商品遮蔽规则。拒绝范围或历史不可见的响应，原任务当前可见时返回 ID 和标题 |

## 调用路径和边界

- 页面打开单条详情后，请求 `GET /api/workbench/commercial/resources/events/:event_id/object`。BFF 继续使用当前登录身份、期望用户和企业校验以及固定 Commercial 上游。只接受原事件 UUID、无查询/请求体、同源固定路径、严格响应与大小限制。后端同名 `/api/v1` 路由使用原 Commercial Read + 实时企业校验。必须从 Resource owner 按当前企业及事件 ID 取原事件，不能信任客户端提供的来源类型或对象 ID。
- 组装仅装配当前实例已运行的 owner。每次只执行一个来源的读取。Resource 原事件不存在时返回同一通用未找到，其他企业的事件不能到达后续对象 reader。已核对事件而对象缺失、未启用、无权限、不适用或对应信息无法证实时，统一返回空对象，避免用差异响应探测对象是否存在。
- 返回包含企业、事件和可空对象。对象由允许的类别、业务名称和可选导航身份组成。同企业、同操作者和同成员的原 AI 调用没有任务绑定，且操作是已批准的聊天规划或自有商品录入时，允许返回对应的固定用途枚举。用途与对象只会出现一项。前端核对企业、事件、类别，使用现有内部路径构造 Store/AI 任务链接，Amazon 只显示商品。原 1688 商品继续通过其已授权 GET，不走新查询。前端只在打开对应详情时调用，无表格逐条请求，无持久缓存；关闭、换记录或切换企业时取消请求并清除名称，错误保持原账本可读。
- 一次短时有界读取使用已有 owner 池，沿用 Store 成员读取的本地权限校验，无新增事务或锁，无跨库锁、连接写入、会话更改、重复结算或恢复任务。取消、超时和重试均只允许重新读取，UI 不自动重试。营业记录、预留、订单、回执和余额不因这次查询发生变化。对 name、响应大小和超时设上限，无未校验重定向和任意链接。
- 权限撤销以各既有实时入口的校验为准。特别是商业读权限不等于店铺、采集条目或任务权限，对象解析不得读取或投影其他操作者的 Amazon、AI 记录。Store 按其当前店铺分配语义。认证已过期、企业/member 不符或不可用时按原拒绝行为处理。
- Legacy decision: N/A。无 schema、迁移、回填、历史兼容层或第二事实源。只读部署沿 35444 原配置及两份组件回退镜像，先部署兼容旧 UI 的后台，再切换前端。

## 验证

最小验证覆盖跨企业事件拒绝、无原对象权限、书面关联不一致、已保存 Amazon 结果/请求字段、AI 缺少任务 ID 及任务不可见、未启用 owner、响应限制、浏览器详情显示与切换后清除。使用合成数据验证，不制造真实消费。已授权 35444 只更新所需组件，保持配置、登录、挂载与原后台工作单元，登录后实际效果由用户验收。
