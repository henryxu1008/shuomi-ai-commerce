执行 [#1215](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1215)。Design Basis: Independent Architecture。Admission Status: IMPLEMENTATION_READY。2026-11-09 独立只读复核基线 c2a0439c、设计及真实接线，无 BLOCKER；数量存在性、独立确认、完整原说明、确认失效与版本接线作为 IMPLEMENTATION_TEST 落实。复用[价格建议与人工确认](own-product-intake-price-review.md)及[录入 V1](own-product-ai-intake.md)的 owner 和接线，仅替换库存候选、隔离投影与采纳合同。

## 产品决定、范围与结果

2026-11-09 用户同意“把库存也改为建议值加明确确认，保留 0 与未知的区别，并移除这部分自然语言语义穷举”。运营人员可逐行确认 AI 建议库存；未确认的库存保持空白或已有人工值，标题、SKU、规格等有效字段仍能采纳。模型的语义判断不是程序验证过的商品事实。

本次不做真实模型、保留实例、账务、部署、第二模型互验、语义词表、新框架或跨模块重构。币种代码、图片编号等确定格式检查继续保留；同流程扫描只报告超出范围的疑点，不自行扩张。

## 合同与确认

- 模型行字段改为可选 `stockSuggestion: {quantity, evidence}`。数量必须显式存在，是 0 到 9007199254740991 的整数；省略整个建议表示未知。0 只是建议的零，不因数值为零获得特殊信任。`evidence` 为原输入说明中逐字存在的非空有界片段，最多 512 字节。
- 程序只验证严格 JSON、已知字段、数量范围/整数、来源片段存在及原有行/规格/图库结构约束。不以关键词、否定、范围、千分位、费用词、SKU 或另一字段的文字判断库存是否“明确”。全部库存建议统一交由人工核对，不再自动采纳“看起来明确”的值。
- 候选 wire schema / prompt / Agent 版本同步升级；旧行级 `stock` 与 `stockReviewRows` 严格拒绝，删除保守 `ForReview` 投影，不增加迁移或双合同。原模型输出仍按现有方式存放在原 Run，读取已验证回执后返回相同候选结构，不新增持久化字段或事实 owner。
- 页面逐行显示建议数量、原文引用及完整输入说明。每行独立的“确认第 N 个 SKU 的库存数量”复选框默认未选。价格和库存分别确认，无全选、无模型自称已确认标记。未知库存提示未提供建议，可以在商品表单手填。
- “采纳到商品表单”只把用户已勾选行的库存建议填入空白库存字段。已有人工库存（含字符串 `0`）始终保留，不覆盖已移除组合。取消勾选不填入；未确认库存不影响其他字段、价格确认或图片选择。采纳后仍由原表单编辑及显式保存。
- 确认选择只属于当前候选对象及输入快照。新生成、原键读回替换、输入/图库变化立即清除价格和库存确认；改变再恢复输入也不能复活旧确认。重复采纳不覆盖人工值。确认或取消确认不发起模型、保存、预算或结算请求。
- 非整数、负数、越界、缺数量、非法字段或伪造来源仍按原受限结构错误合同拒绝整个候选，不能靠清空字段掩盖错误。程序不声称语义正确，用户负责核对建议是否属于该规格及当前可用库存。

## Owner、状态、权限与恢复

`internal/product/collection/intake` 持有候选合同，`agentconfig` 固定当前版本，HTTP 的 GenerateWithGate / Decode → DomainProposal → 原键 GET 接线不变，前端 contract → 逐行确认 → applyIntakeVariants → Collection/Catalog 原保存命令消费建议。正式商品事实仍由用户提交的保存命令持有。

不改变租户、成员、SourceMedia、商品写权限、预算/Quote/预留、InputHash、ConfigurationDigest、Run 状态机、回执校验、原键一次调用与 UNKNOWN 不重发。GET/重复确认不新建模型派发；旧运行或配置按当前版本和摘要校验拒绝，不转换为新合同。无新增事务、表、恢复协议或外部副作用。Legacy decision: RETIRE 旧库存解析与临时隔离投影。
