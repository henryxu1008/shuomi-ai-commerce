## 用户结果与范围

有原研究项目写权限的成员在「智能选品 → 同一研究项目 → 评估与选品决定」打开一个已关联的 Amazon 美国站候选。看当前选中的原版商品资料，填写一组有出处、单位、币种、日期的经营假设。页面显示已有输入、缺项，条件齐备时给出每次销售尝试的期望贡献利润和参考保本售价。用户单独在同一候选记录原人工决定和理由。已批准且仍可读的商品按现有准确子集进入「我的数据 → 核对转入我的供应链」。输入不足仍可人工研究，既有批准测试、放弃及重新评估各沿当前权限和 CAS 语义。正利润不会替用户批准或给出合规结论。

依据为 [#1074](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1074)、[原产品规划](../product/research-commercial-assessment-v1.md#5-本批范围与后续)、[原技术提案 §4/§6/§10](research-commercial-assessment-v1.md#6-确定性单位经济模型)、协调方 2026-11-06 对现有已准入候选及人工输入的明确范围，以及 [#1075 固定产品路径](https://github.com/henryxu1008/shuomi-ai-commerce/blob/4045310770891e1fc4569b5156f1bcc896c7e806/docs/product/market-research-selection-centers-v1.md)。Figma 仅参考原候选评估和人工决定的业务顺序。复用现有工作页、候选和转入入口，试算表单折叠在该候选内；取消回原候选，保留原选择和列表位置。同一时刻只编辑一个候选。填写时清楚区分「商品资料」「经营假设」「参考试算」「人工决定」。

本段限定一个销售市场、一个规格、每单一件、一个显式履约方式和一组假设。支持用户手填 USD 单件固定金额、按 USD 售价比例费用，以及可选 CNY 单件采购价与人工汇率。其余币种、多件套装、组合订单、分段和最低收费等无法按当前口径表达时标记 `UNSUPPORTED_COST_RULE`，不输出保本价或完整利润。无通用费用编辑器、批量试算、报价撮合、持久化条件/结果、跨设备历史或建议自动生成。当前页面关闭或离开上下文后，草稿和结果消失；历史人工理由沿原 Research 合同，系统不把临时试算当成已保存评估。需要持久化输入、历史结果或绑定决策回执时另做 Research 准入。

## 人工输入与金额合同

- 顶部冻结目标 US、销售币 USD、每单一件。填写计划销售渠道、履约方式、规格说明与采购数量（正整数，采购价单位为单件）。渠道/履约/规格的说明仅为本次假设标签，不用于自动匹配供应商、推导费率或确认可采购。已保存商品的观察价/时间与用户的假设、假设时间分区。
- 明确填写 USD 商品售价（优惠后、剔除代收税）、全额退款概率及其依据；保留正常完成和全额退款两种结果。两种结果逐项填写采购包装消耗、物流/履约（包括各情景发生的退运）、平台固定费用和按售价比例费用、卖家税费的固定额及按售价比例额、广告分摊及额外换汇成本。金额填写该情景实际负担，退款以收入为 0 表达，不能再把退款金额当成本。退款情景与采购回收及费返由人明确输入，不能从另一情景偷偷复制。只有显式概率 0 的情景可不填写，但切回非零会重新检查。每项已有数值附简短出处和有效日期（YYYY-MM-DD），可用同一条明确声明的来源和日期覆盖一组；不可由程序自动补当天。费率按原输入售价计算，退款情景可明确填零或保留不可退费用。仅允同一 CNY→USD 手填汇率、有自己的出处/日期，用于所有 CNY 采购项，其他成本直接填 USD。
- 区分空白/未知、已输入零、以及勾选「不适用」并给理由。采购价、售价和概率只接受数值或缺失。两种采购情景可录入实际消耗 0，但正常成交的采购假设须明确确认其适用性。缺采购价或未提供费率等，回 `INSUFFICIENT_INPUT` 和明确字段缺项；保留已知金额，仅在全部有效时显示完整数字。值存在但单位/币种/范围/日期无效时返回字段校验错误，不偷偷降级成缺项。用户手填的成本统一标记「经营假设」，来源可以是商家自行核实的报价、合同或明确估计，系统不自动读取链接或认定是有效 SKU 阶梯价。万邦固定版本、指定 SKU＋数量适用报价、MOQ、混批未证实，阻止自动供应商报价与依赖该报价的结论；本段完全独立。
- 只解析非负十进制字符串，USD/CNY 最多两位小数，概率/费率用百分数且最多两位小数，汇率最多六位且大于零，禁止指数与隐式浮点。每项金额上界 USD/CNY 1,000,000.00，售价另有 USD 0.01 下界，率 0–100%，汇率上界 1000，采购数量 1–1,000,000。出处/理由每项最多 240 字，规格和模式最多 120 字。计算使用 JS 标准 `BigInt()` 构造整数和统一固定分母 `10^10`（以美元分为单位，覆盖概率、费率和汇率的小数位），无 `number` 金额运算；不用高于当前 TypeScript ES2017 target 的 BigInt 字面量，不改编译配置；输出按美元分格式化，不给 JS JSON 传大整数。仅有这一个试算实现。精确中间值用于决策展示的符号与保本求解，最后展示金额按美元分就近取整、恰好半分远离零。金额显示接近零时仍由精确值区分微亏与真正不亏。

## 公式与保本边界

用 `P` 表示 USD 售价。每个情景的已确认概率为 `q_s`，收入系数 `m_s` 为正常成交 1 或全额退款 0。全部固定成本合计 `K_s`，适用售价比例成本合计 `r_s`。USD 成本和按人工汇率换算的 CNY 采购成本进入同一 `K_s`。单件期望贡献利润为 `A*P-B`，其中 `A=sum(q_s*(m_s-r_s))`，`B=sum(q_s*K_s)`。商品毛利仅扣采购包装，贡献未扣企业固定开支。当前只算一组条件，改变售价可以重试算；多个完整对照情景和批量敏感性留在后续切片。

参考保本价是模型价格域 USD 0.01–1,000,000.00、按分的首个不亏价格；该域只是本次试算数值边界，并非平台定价政策。若斜率为正，对精确阈值向上取到分，再与模型下界取较大值并验证可行。若斜率为零或为负，检查模型下界；下界不亏时它就是首个，其他情况无可行保本价。等于上界可行，超过上界明确无可行值。非线性/最低收费/阶梯规则保留未支持状态。结果文案使用「按当前假设估算」，不触发自动推荐、批准测试或合规豁免。
