## 3. 已获用户确认的产品决定 D1–D4

**D1 价格范围。** 每个独立部署只有一份当前 DATA_ROW 标准售价，所有企业的新报价共用；35447 的调试零价不会跨部署影响 35444/35446。不做企业特价。平台管理员发布价格，企业管理员只能按获准价格购买。新空系统由原安装器建立初始价目，不由运行启动覆盖。

**D2 报价与调价时序。** 原有效报价保留现有 15 分钟有效期，期间按原版本成交，调价不追溯改变它；过期未下单必须重新确认。已创建订单永久绑定原报价，UNKNOWN 恢复不依赖当前是否仍零价。采集任务冻结自身准入时的同源价目用于预算折算，已准入任务不因后续调价重算；旧请求键不会按新价变成新任务。

**D3 零价按数量领取。** DATA_ROW 可以有明确 `0` 单价；用户输入有界正整数数量、预览后显式确认。此次获准目标是 3 条，不代表系统自动给每家企业发 3 条，也不新增“每企业一次”的试用资格合同。同一请求键只入账一次；有意使用新键创建另一笔订单是另一笔领取，需符合现有数量上限和当次授权，不用 UI 刷新自动触发。正式金额输入模式仅用于正价。

**D4 费用含义。** 资源购买价和采集时按条数折算的预算都来自 Commercial 的版本化价格，但不是两次收费。真正购买金额只在资源订单记录一次，采集只消费 DATA_ROW；任务金额明确标“按本次价目折算”，不冒充这批预付资源的实际采购成本或外部厂商成本。零价时 3 条购买额为 ¥0，采集仍消费最多 3 条；原 ¥0.15 外部总费用上限不提高，外部成本缺证仍禁止真实执行。

## 4. Owner、持久化与最小接线

### 4.1 平台价格发布

价格唯一 owner 仍为 Commercial DB 的 `commercial_offers`；每次发布插入新 `offer_id` 和 `pricing_version`，金额/币种/数量界限不可覆写。旧 offer 仅退出当前可售状态，原报价/订单内快照不变。

在同一 Commercial 事务内：校验原当前版本 → 锁原当前 DATA_ROW offer → 比较版本/可售状态 → 原 offer 退出可售 → 插入新当前 offer → 写发布回执/审计。并发首次发布不自行补安装，缺少原初始价目时返回未配置；并发替换只允许一方成功，另一方重读后重新确认。数据库还需对 DATA_ROW 当前可售项施加唯一性约束；首期不开放未来排期或停用整个价目的另一套操作。

最小新增持久化是 Commercial 内一份价格发布回执/审计记录，引用旧/新 offer（不另存第二套当前价格）：actor、所属身份上下文、时间、预期版本、新版本、原因、请求键、规范化指纹及结果。价格仍只读 offer；金额变化和回执同事务。请求键在部署内绑定原操作者及完整请求，异操作者或异载荷复用拒绝。

发布时只接受非负整数人民币分；`0` 必须是显式值，缺失/解析失败/目录读取失败不是免费。此版本不改变原数量界限、币种或其他资源价格。负数、溢出、未知字段、任意企业参数均拒绝。

### 4.2 零价资源订单

继续使用原 `RESOURCE_PURCHASE` 类型和原订单/订单项表。在现有 `settlement_mode` 字段上窄扩 DATA_ROW 的 `WALLET | ZERO_PRICE`；新 DATA_ROW 报价与订单显式冻结模式并纳入指纹。该模式由服务端价目推导，浏览器不能指定或覆盖。

- `WALLET`：数量 > 0、金额 > 0，完整沿原钱包预留 → Resource grant → 钱包 commit；不放宽 Money 的正金额合同。
- `ZERO_PRICE`：仅 DATA_ROW、数量 > 0、单价和总额严格为 0，原资源订单仍存在，但钱包 reservation/payment ID/扣款/退款证据必须为空。充值和支付未配置不阻塞此模式。不能把失败支付降级成免费。
- 其他资源、充值、服务购买和退款维持原严格正金额条件。

零价状态复用 `PENDING → FULFILLING → FULFILLED`，不伪造 `FUNDS_RESERVED`。Commercial 在确认原报价并持久化订单后，调用原可信 `GrantPurchasedResource`，以 `grant:<原订单ID>` 及原 order/item source 为唯一授予身份。核对企业、DATA_ROW、数量、source、event 和原回执全部一致，才标完成。

订单写入和资源授予仍是现有两个一致性边界；不声称跨库原子。不新建赠送账本、outbox、队列或 reconciler，复用现有 recoverable resource orders 扫描与订单 CAS，按冻结结算模式分流。

### 4.3 采集、预算和页面同源

Commercial 注入只读 DATA_ROW 价目 reader；数据服务的 options/新任务准入、1688 费用提示、资源购买、公开价格和企业额度页均通过原组合根消费同一价目。Resource 继续只认数量，不存售价或扣人民币；不把商业数据库连接传给 UI/采集 provider。

新任务保存 `offer_id/pricing_version/unit_price_minor/currency` 及已确认最大条数/折算总额。金额取整只用现有整数分和溢出检查。新请求须明确确认所见版本，版本变化返回需重新准备；不按浏览器传入单价决定金额。

跨 Commercial/Product 的并发边界以准入价目读取时点为准：请求读到新版本则拒绝旧版本确认；已读到并校验旧版本的同一次准入允许冻结旧快照，不承诺发布响应之后全局没有旧版本任务落库。读取器失败则不准入，不用常量兜底；不跨库持锁、不在数据库事务内调用外部 provider。

原键查找先通过当前身份/原企业/原权限，再比较原业务输入及其冻结快照；不得先用当前价目重算后才查原键。原键不能换输入/换价格，调价后的新准备使用新键。历史读取和 UNKNOWN 核对沿原 owner，不要求当前价格仍可售。

Amazon 每任务最大折算金额为 `条数 × 冻结单价`；API 月金额额度的预留/消费/释放、任务 confirmed/pending 金额以及条目指纹全用同一冻结快照。日条数、每任务条数、有效权限、deadline、并发预留和 DATA_ROW 余额仍独立检查；零价不能绕过这些限制。既有 API 月费用上限不提高或改成无限，原零值准入语义不擅自变化。

1688 服务端仍每原操作预留 1 条，原键回执优先；当前“插件/本地免费且不消费条数”合同不变。零价的服务端渠道仍有订单和资源消费记录，不能冒充插件渠道。

## 5. 权限、租户和页面顺序

- 平台调价复用实际生效的 `listingkit.platform_admin` 资格与 `listingkit.admin.write`，沿当前 authorizer/原身份校验；不可只查 `listingkit_admin` 字符串、企业管理员身份或前端按钮。35447 当前测试管理员不会因此自动获得平台权限，本轮不授予任何角色。
- 发布/查询回执复核当前平台资格；撤权后的下一请求拒绝。回执绑定原操作者，跨操作者读取按同一平台管理权限核验，不暴露企业钱包/订单。
- 企业报价/下单沿当前 `workbench.commercial.purchase` 和 live organization access，企业 ID 只从验证身份取。读订单/原键恢复继续查当前企业和原权限；回执不充当授权。
- 平台页复用现有后台管理壳、表单、预览/发布/回执交互，名称“数据条数价格”；已有平台设置里进入，不另造 Console。展示当前版本、单价、影响部署、调整原因和历史；0 价确认明确“后续有效报价可按数量免费领取，仍记录订单和条数”。
- 企业页在原资源购买处按数量输入 `3`，显示“3 条／合计 ¥0／价格版本”；按钮“确认领取3条”。正价显示正常购买。完成后可从原订单读入账回执，再读企业资源池；不自动采集。
- 未配置、无权限、价格变化、提交结果待核实分别显示。待核实时仅沿原键核对，不自动生成新订单。切企业后迟到响应不能落到另一企业。

## 6. 故障、并发和原键恢复

| 故障位置 | 唯一恢复行为 |
| --- | --- |
| 调价提交响应丢失 | 原键查发布回执及实际当前版本；不可换键重复发布 |
| 其他管理员已调价 | 预期版本冲突，无部分更改，重新预览；旧成功回执不代表仍为当前版本 |
| 报价成功但尚未下单 | 原报价在有效期内按原价；过期重新确认，不重写原报价 |
| 零价订单创建响应丢失 | 按原企业/原键查同一订单，异载荷冲突；不能用新价替代原价 |
| 授予前中断 | 原订单进入原恢复扫描，沿原 grant 身份继续；不创建新订单 |
| 授予已完成但响应/订单标记丢失 | 同一 grant 的原不可变回执证明已入账，CAS 补齐原订单；不重复入账 |
| 授予结果未知 | `RECONCILIATION_REQUIRED`，保留原 order/item/source；不当失败重领，不伪造已到账 |
| 已证明确无授予的确定拒绝 | 原订单取消并保留原因；只有确定终态后才允许用户明确发起另一新订单 |
| 零价期间切回正价 | 新报价用新价；原有效报价、原订单和原 UNKNOWN 按 D2 恢复，不追加扣款 |
| 权限撤销/企业切换 | 下次读写先按原权限合同拒绝；原在途授予的事实不删除，后台仅完成原订单收敛，不以恢复授权新领取 |

## 8. 有限实施义务与独立验收边界

1. 平台权限与发布并发：企业管理员拒绝、撤权拒绝、原版本 CAS、同键同载荷回执、异载荷冲突、0 合法/负价和溢出拒绝；发布和审计同事务。
2. 数量报价/模式：仅 DATA_ROW 的 3×0 可售；金额换算在 0 价明确禁用；其他资源/充值仍拒绝 0；价格缺失不当 0；正价原回归继续有效。
3. 零价入账：0 钱包/支付未配置，3 条只入账一次；零 Money 写入；同键并发、grant 响应丢失、重启和恢复扫描均只得到原 grant/event。
4. 同源费用：options、API/控制台准入、API 月费用 quota、confirmed/pending/释放及页面都用同一冻结版本，调价后原任务/原键不重新计算；零价条数与权限限制仍有效。
5. 有效报价跨调价与过期、冻结订单跨 0→正价恢复、跨企业/伪造零价模式拒绝、原已通过的正价钱包与插件免费路径无回归。
6. 未来指定独立验证者在获准空库/合成传输核对：平台发布零价 → 测试企业数量3 → ¥0订单 → 原资源回执/余额3 → 同键找回；真实采集、外部费用、用户产品验收分别报告，不能以 CI 代替。

现场价格/余额、外部渠道费用和真实补采准入保持原状态。运行、零价领取、真实采集和产品验收均 NOT_RUN；缺证据 UNKNOWN。

- 平台维护入口：现有企业空间平台管理区 → 数据条数价格，页面 `/workbench/account/organization/data-row-pricing`。当前价、预览、发布及原发布回执复用既有权限、同源写门禁和原键交互；API 位于 `/api/v1/workbench/commercial/data-row-pricing`。
- 企业资源购买继续走原数量报价和订单入口，明确显示价格版本；零价时金额换算禁用，选择数量后显式确认。成员资源页读取同一零价；原按金额分配入口在零价时说明不能换算，不以除零、未知价或伪造报价替代。
- 采集 options 返回 `price={offerId,pricingVersion,currency,unitPriceFen}`；新任务确认 `pricingVersion` 与十进制字符串 `maximumCostFen`。Job 固定 `price`；相关金额投影使用十进制字符串，避免浏览器丢失整数精度。没有当前价时不能提交新任务，原键读回先核原请求。
- 新空 Commercial schema 新增不可变价格发布回执表和当前 DATA_ROW 唯一约束；原运行角色只增加所需 offer INSERT/status UPDATE、发布回执 SELECT/INSERT，不授予通用 grant、钱包写入或 schema owner。Product 新空 schema 固定任务 `price_snapshot`，旧保留库不迁移、不补默认快照。
- 单元测试与任务自有 PostgreSQL/SQLite 测试是工程证据；不表示平台真实改价、真实领取、采集、部署或产品验收通过。
