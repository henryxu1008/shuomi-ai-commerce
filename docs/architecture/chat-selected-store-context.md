# 硕米 Chat 会话内选择店铺

状态：**IMPLEMENTATION_READY**。执行 Issue #1267；独立复核通过，下列行为在实现测试中验证。

## 用户结果和范围

用户在同一会话选择、切换或取消已连接店铺；选择器只呈现当前用户有权查看且官方连接状态明确为 connected 的店铺。连接新店铺跳转现有店铺中心，由用户自行完成创建与官方授权。选择动作本身不发送消息、读取订单或流量、调用模型、发布商品或扣点。返回后可继续选择。店铺选择不代表订单、流量查询已经可用。

沿用当前会话及项目的既有业务范围；店铺是用于后续用户显式操作的可变选择，不修改已有范围或旧消息的归属，不影响店铺中心原有事实。没有可信连接状态时不标记为已连接。当前阶段不新增对第三方平台的操作。

## 事实、调用路径和边界

- 店铺的名称、连接状态和访问权限由 store center 负责。用户主动展开后逐页读取现有授权 scope-options，并按当前身份逐项读取已保存的官方连接详情，不访问平台、不写观察记录，也不读取商品、订单或库存摘要。只有明确 connected 才可选；保留观察时间，缺失、过期、错误或不可用不视作 connected。分页或局部失败需提示，不能把部分结果当成全部。禁止使用可能查询平台并写观察值的 Status 或读取业务摘要的 catalog。
- 新连接直接进入 `/workbench/stores`，使用既有 `绑定新店铺` 与各平台官方连接；不得自动创建店铺、填写凭据或开始平台授权。Chat 中不保存平台凭据。
- 用户选择状态是当前用户、企业、会话或新建入口下的临时 UI 状态，保存在该浏览器标签页，刷新可恢复；不是店铺事实，也不更改既有会话的不可变 business scope。恢复时必须重新向 store center 确认权限和 connected，失败时保留不可用提示，不展示旧名称或自动选其他店铺。不同用户/企业/会话的选择互不继承。
- 创建和发送在当前用户主动操作后执行。未决创建、发送或正在恢复原请求时禁止更改店铺；重试沿用原键、原载荷和原店铺快照，不创建新键或替换店铺。选择变化与输入草稿分离，不重载或覆盖已输入文字。

## 后续显式发送的合同（实施前必须完成）

选择不是纯装饰。增加受类型校验的可选店铺引用及其确认信息至当前消息输入；当前用户明确发送时，服务端重新检查会话身份、成员店铺权限及连接状态，读取 store owner 事实并将选定店铺与该次命令的不可变上下文一起绑定；失败明确拒绝，不能退回未选店铺或另一店铺。绑定必须纳入原请求的内容摘要、事务、幂等与重试合同。后续提案、任务、模型输入只能使用该次已绑定事实，而非读取当前选择。保留现有额度和模型调用门禁。对未接入店铺数据的路径应明确提示不可用，不能把普通店铺概况误作所选店铺查询或伪造数据。

独立复核发现原 `AppendUser` 和 `ReadFrozenScope` 强制冻结范围等于会话固定范围；不能用新店铺替换基础范围。原范围必须保留，新店铺需在同一原命令单独冻结为依赖，绑定 owner、member、conversation、key 和版本，进入 wire fingerprint 与模型输入 hash；具体承载方式见下文。原本绑定店铺 A 的会话选 B 时，A 是会话原归属与历史依赖，B 是本次明确选择；不得把 B 的标签放在实际使用 A 的请求上。项目绑定不得被选店写回或覆盖，存在歧义时明确提示并等待选择。

承载方式：在原命令的 FrozenScope JSON 尾部增加 `SelectedStore` 可选指针字段（`omitempty`），包含有界 store ID、店铺版本、连接观察版本/时间/状态、名称和平台；owner、member、conversation 沿用外层冻结值，命令 key 在原命令引用中绑定。未选择时不输出该字段，保持原 JSON 字节和摘要；有选择时进入现有 ScopeDigest。服务端在锁外读取已授权的本地官方连接观察及店铺事实，按原 planner 准入方式冻结，事务内将其连同原命令、wire fingerprint 和 planner input hash 一次提交。发送前重读校验；原请求恢复先查原回执而不是用当前选择重算。现有 DB 约束只限定 JSON 对象和 16 KiB 上限，实施测试验证旧摘要、上限和完整回读，不新建表或迁移。

基础 Scope 和相等校验不变。通用会话、原店铺 A 会话和项目关联 A 的会话均可选择 B：B 是当前请求的唯一目标店铺，A 仅是会话原归属、项目绑定及历史权限依赖；不得将 A 作为 B 的替身，也不得写回项目绑定。取消选择后没有当前目标，原归属不变。planner 输入须显式区分原项目/会话归属和当前目标，不能以原 ModelInput.StoreName 冒充当前目标。若某条现有执行或路由路径不能表达两者，应阻止该路径并保留输入，明确提示暂不支持，不能报告其已支持 B。旧版程序的严格 JSON 解析不能读取新字段；有新消息写入后不得盲目回退旧二进制，更新和回退策略在实现验证中明确，不改或删除试用数据。

现有固定范围与项目绑定不能被选店动作替换：项目或已固定店铺的历史及当前权限仍按其原依赖校验。各路径都必须按上述方式区分原归属和当前目标；尚不能表达该区别的现有路径不得发送，保留草稿并说明，不得静默覆盖。

## 历史和撤权

已经发送或完成的消息、方案及任务继续引用原命令冻结的上下文；切换不改写历史。历史读回、模型历史组装、通知和任务投影均须对每个依赖重新鉴权；失权或连接不可用时隐藏相应名称和内容，不把新选择套用到旧结果。不得因为一条历史依赖失权泄露内容，也不得为了显示历史而绕过已有项目、商品和店铺依赖校验。

当前 `AppendUser` 在锁内读取历史前缀供 planner 使用，后续回复可能消费不同店铺的历史。须沿 `ProductDependencies(..., throughSequence)` 模式收集并绑定本次实际消费的全部店铺依赖；历史显示、模型输入、提案和任务的读侧按各自前缀重新鉴权，失权内容不能送回模型。用户自己输入的原文不作伪造性清洗。

## 失败、并发和恢复

店铺列表或校验失败：显示不可用并允许用户重试，不创建记录。两次选择快速切换时，仅采用最新有效读取结果，旧请求结果不能覆盖。身份或企业变化时中止旧读取，清除旧选择可见信息。跨标签页状态彼此独立；原消息同键并发、丢失响应沿用现有 owner 的恢复策略，但同键不同店铺载荷必须拒绝。服务端若不能证明原请求未受理，不得另起请求。锁定选择的 UI 不代替服务端校验。

## 验证与交付

使用现有受控测试，覆盖 connected/expired/unknown 及分页、撤权与身份切换、选择与取消、草稿保留、同一会话切换不串历史、未决期间锁定及原键恢复、用户主动进入店铺中心。确认未发生自动消息、经营查询、模型或平台写操作；项目/固定店铺冲突不静默降级。原 35444 仅在授权范围更新并供用户试用，不调用真实模型、不发布、不释放预留。独立架构与最终实现检查不等于用户验收。
