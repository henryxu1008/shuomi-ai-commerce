# SHEIN 离线诊断的库存和 SKU 包装缺项

Design Basis 为 **Independent Architecture**。基线为 `d12b8c7633a8e3a6f02e4c19f4a29344b14c8d34`。准入状态和评审记录由关联执行 Issue 承载。

## 产品结果与范围

企业成员在现有「我的数据 → 生成 SHEIN 离线包」操作中，能看到库存是已声明的数字（含 0），还是待补。缺少 SKU 包装重量或某个尺寸时，原诊断列出待补字段及对应 SKU。已有「保存草稿」允许带缺项保存。已保存离线包、保存时诊断和报告按原版本读取。

用户确认的范围是库存、包装重量和长宽高的事实保留，以及新诊断规则与已保存结果的边界。复用现有离线诊断列表和报告阅读界面，页面和入口依据 [原离线包诊断设计](report-center-shein-offline-package-source.md)、[既有诊断操作政策](shein-submit-readiness-action-policy.md)和[现行 UI/IA](../product/final-ui-ia-authority.md)。只调整诊断字段、文案与接收版本，沿用该设计引用的 [Figma 报告权威](https://www.figma.com/design/tg48P46SSXl6TBy9lZwg63?node-id=31-463)。

本批范围限正常来源发布、Catalog、离线包、诊断与报告读取。TargetRecord、SHEIN 官方 Save Draft／Publish、SKU 图片分配、仓库库存分配与同步、额外采集、包装录入页及历史数据回填另行定范围。实际环境启用与平台验收另行授权。

## 已复现的现状

三个合成 SKU 经当前 Catalog JSON 与正常 `draft.Builder`。显式 0 和未提供库存的 `stock` 都从 Catalog JSON 省略，原预览两项都出现库存 0，随后诊断副本两项都变成 1000。正库存 7 保留。无 SKU 包装数据时诊断副本补成 1 × 1 × 1 英寸和 0.01 g，即使商品级重量尺寸与它不同。副本修改没有回写原包。根据源码可定位为来源标记丢失、构包为未知 SKU 创建库存行、校验前填补业务字段三个步骤。

普通 Catalog Variant 当前没有 SKU 级重量和尺寸。缺包装是现行正常来源的真实结果。此批先让它如实进入诊断。完整且有同 SKU 归属的数据沿已有离线包字段接受检验，完整样例用于检查现有包合同，无需为测试新增运行时录入能力。

## 权威事实与调用路径

| 事实或结果 | 当前 owner 与连接 |

### 库存表达与生产者

- 保留 Source `ProductVariantCandidate.Stock` 的原数字编码。添加可省略的证据标记 `OwnStockDeclared`，表示该 SKU 的现有 `Stock` 来自经营者明确声明，包含 0 和正数。只在 Collection 新建、修订、导入的正常命令入口发出标记，先通过严格 JSON 明确数字字段检查，或已有 XLSX 非负数库存解析，再由该命令构建自己的 Source envelope。证明来自同一已验证输入与同一 SKU。复用的 `OwnEnvelope` 本身不发标记，直接构造 Go 整数值也不授予声明。
- 声明标记只接受 `own_product/v1` 已准入生产者和匹配的自有商品来源身份，且 `Stock` 满足原 Collection 非负整数及安全范围。将约束放在 Source 的生成、持久化与证据验证公共边界。通用采集、受控样本、浏览器、属性、供应商及 HTTP 客户端输入均不能通过伪造同名标记声明库存。自定义数据 `custom_dataset/v1` 通过独立交付入口复用 `OwnEnvelope`，它的 JSON 入口现有行为会把未提供或 null 库存转为整数零。保留该入口的交付格式、接收条件、原键和摘要。缺少声明证据时，SHEIN 的经营者库存检查显示待补。
- 同一 Catalog 字段 `stock` 改为可空的数值表示，另携带可省略的原声明标记。现有非零数值和字段顺序保持相同编码。新且有来源证据的零值编码为 `"stock":0`。旧 Source 记录没有标记，重算仍生成原快照字节。缺少经营者声明标记时，数值可以按其原意义展示，SHEIN 库存检查仍显示待补。例如供应市场 SKU 的 `7` 继续是供应商声明，不能填入经营者 SKU 库存。旧记录仅有数值而缺少该声明证据时同样处理。新发布仍在原事务记录 Source、Catalog 和回执，Collection 在原事务按原输入摘要及作用域先恢复已提交键。
- Catalog 同字段消费者按事实处理。原页面若仅从快照取值，未知显示未填或留空。当前自有商品编辑入口能读到已核对的同版本原始声明时可以展示其数字，否则沿用现有必填校验等待用户明确填值。核对已有 `?? 0` 的自有商品编辑、差异显示、补全页，以及供应市场和选品证据消费者。可空数值在投影和手工克隆中按值复制。只处理由本次同一字段造成的行为差异，供应商声明或正式目标仓库存的定义和公共写接口另有 owner。

### 诊断输入、字段与报告

- 构包用现有 SKU 库存字段表达已声明的数量。明确 0 保留为 0。缺经营者声明时省略草稿库存行，原预览的可空 `StockCount` 保持空值。保留原草稿 `StockCount` 整数和原 JSON 编码，在同一离线草稿 SKU 对象附加可省略的 `own_stock_declared` 布尔证据，仅在对应 Catalog SKU 有明确经营者声明时写入。该标记只用于离线包，不进入平台载荷，必须与同一 SKC/SKU 的原库存行和预览数值一致。标记与库存行不一致、草稿与预览的对应关系不明时拒绝推断。已有 `DEFAULT` 技术标识不能当作目标仓库证据。
- SHEIN validator 先检查原包同 SKU 的库存、重量、长宽高与单位，再走既有发布载荷结构检查。未提供与已提供但无效分别提示。库存 0 通过「库存已声明」检查，不推导可售、发布准入或仓库授权。缺库存、重量或尺寸时给出离线发布准备阻断，`save_draft` 保留现有允许缺项策略。仅在同 SKU、有原值且单位明确时做合法单位转换，禁止把 0、负数、未知单位及缺失尺寸归为有效值。已有包装尺寸必须对应同 SKU，商品级、兄弟 SKU 和供应来源观察值不能代填。
- 本次从验证副本移除库存 1000、缺尺寸 1 英寸及非正重量转最小正数的路径。传输字段整形、图片规则及与事实无关的默认值仍由原 owner 负责。字段提示同时放进现有 `message`／`guidance` 和 `paths`。报告正文当前只消费前两者，不能靠 `paths` 展示 SKU。按确定的 SKC/SKU 顺序汇总缺项及明确的零库存，限制展示数量并提供总数，遵守原包体、结果和请求上限。
- 新诊断启用新规则版本，适用的 `Validator` 与持久化 `DiagnosticValidator` 版本同步核对。沿用原绑定算法，哈希主体包含实际规则版本和严格解码后的包。新包的可选声明证据参与摘要，旧包缺标记时重新编码仍得到原规范字节。相同新规则与包摘要始终得到相同字段结论。新计算入口只接受当前规则，旧包中没有证据的库存行在新诊断中显示待补。已保存快照按记录中的已知版本用同一算法复核摘要，验证作用域、Action、Binding、结果与包字节。旧规则只作为已提交快照的证据标识。BFF 和 Report Center 接收并显示已明确登记的保存版本。旧包明确发起新诊断时，带旧 expected digest 返回现有 `stale_input`，用户从现有入口重新发起新检查后，再以新摘要复核同一内容。expected digest 不能选择规则或授予库存证据。

## 事务、重试与安全边界

Collection 原事务继续是 Source/Catalog 唯一发布路径，既有请求键、命令哈希、快照版本、权限和上限继续作为准入。原 Source 证据重算、校验与目录事实一致，旧 envelope 无标记时保持原哈希。相同键与不同输入继续冲突。

Listing Record 的已保存结果继续绑定企业、用户、原操作键、精确商品版本、批准素材、诊断规则和摘要。规则更新后，同一个已提交操作按原作用域和同一精确请求重读。原店铺、来源与 ApprovedAsset 照原合同核对。用已核验的原规则及绑定版本与当前精确输入重算命令哈希，保持输入／素材漂移拒绝。返回原回执前再次执行原 live guard。核对成立时仅返回原回执。新操作走新规则，原 Insert 事务仍是并发仲裁点，响应丢失沿原键查询。读失败或权限撤销走原错误处理。

分开验证新写和保存读取。发布时先具备两版保存结果的严格读取，版本切换需确保同一路径只有一种当前写规则，避免同一键被不同规则同时受理。实际部署与操作窗口另行准入。领域权限、企业隔离、批准素材、存储表、Provider、计费与发布权限均沿现有边界。

Legacy decision 为 **RETIRE**，退休虚构库存与包装数据的路径。已保存当代产品结果按其记录的合同验证，沿用同一 owner、原数据和原摘要算法。

## 验收

1. 复用三 SKU 离线复现作为回归。通过真实 Collection 发布、快照读回、SHEIN 生成与诊断，分别核对明确 0、7 和未知。覆盖自有新建、导入、修订，以及自定义数据的 JSON 未声明／null、CSV/XLSX 明确 0 和伪造标记拒绝。自定义数据交付与原键恢复保留原合同。1688 可订量和供应市场 SKU 的正库存均不能通过经营者库存检查。
2. 包装重量缺失、单维度缺失、无效值和完整实测样例走同一 validator。核对待补 SKU 与字段、保存可用、完整原值可通过对应检查，原商品级数据没有填入 SKU。
3. 原 Catalog 快照与 Source 回执保留固定字节、版本和摘要。原 Collection 请求原键找回。验证原包的占位 0 与新包的明确 0 生成可区分的当前诊断摘要，旧包保存时摘要保持可核验。覆盖新诊断无摘要请求、旧摘要失效和新摘要复核。已保存离线包和报告用原规则摘要读取，同键重复保存仅返回原回执，输入漂移、撤权、跨企业、未知版本与篡改摘要拒绝。
4. 检查现有后端、BFF 和浏览器诊断／报告路径，明确字段提示和版本一致；按最终 PR 的提交留定向回归、独立复核、CI 与独立验收证据。真实环境、外部平台与发布验收另行记录。
