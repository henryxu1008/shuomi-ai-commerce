# SHEIN 离线诊断的库存和 SKU 包装缺项

Design Basis 为 **Independent Architecture**。基线为 `d12b8c7633a8e3a6f02e4c19f4a29344b14c8d34`。准入状态和评审记录由关联执行 Issue 承载。

## 产品结果与范围

企业成员在现有「我的数据 → 生成 SHEIN 离线包」操作中，能看到库存是已声明的数字（含 0），还是待补。缺少 SKU 包装重量或某个尺寸时，原诊断列出待补字段及对应 SKU。已有「保存草稿」允许带缺项保存。已保存离线包、保存时诊断和报告按原版本读取。

用户确认的范围是库存、包装重量和长宽高的事实保留，以及新诊断规则与已保存结果的边界。复用现有离线诊断列表和报告阅读界面，页面和入口依据 [原离线包诊断设计](report-center-shein-offline-package-source.md)、[既有诊断操作政策](shein-submit-readiness-action-policy.md)和[现行 UI/IA](../product/final-ui-ia-authority.md)。只调整诊断字段、文案与接收版本，沿用该设计引用的 [Figma 报告权威](https://www.figma.com/design/tg48P46SSXl6TBy9lZwg63?node-id=31-463)。

本批范围限正常来源发布、Catalog、离线包、诊断与报告读取。TargetRecord、SHEIN 官方 Save Draft／Publish、SKU 图片分配、仓库库存分配与同步、额外采集、包装录入页及历史数据回填另行定范围。实际环境启用与平台验收另行授权。

## 已复现的现状

三个合成 SKU 经当前 Catalog JSON 与正常 `draft.Builder`。显式 0 和未提供库存的 `stock` 都从 Catalog JSON 省略，原预览两项都出现库存 0，随后诊断副本两项都变成 1000。正库存 7 保留。无 SKU 包装数据时诊断副本补成 1 × 1 × 1 英寸和 0.01 g，即使商品级重量尺寸与它不同。副本修改没有回写原包。根据源码可定位为来源标记丢失、构包为未知 SKU 创建库存行、校验前填补业务字段三个步骤。

普通 Catalog Variant 当前没有 SKU 级重量和尺寸。缺包装是现行正常来源的真实结果。此批先让它如实进入诊断。完整且有同 SKU 归属的数据沿已有离线包字段接受检验，完整样例用于检查现有包合同，无需为测试新增运行时录入能力。

## 权威事实与调用路径

| 事实或结果 | 当前 owner 与连接 |
| --- | --- |
| 自有商品显式库存 | Collection 的严格 JSON、导入和修订入口 → 同一 `OwnEnvelope` → Source/Catalog 原事务发布。数字 0 必须来自通过原校验的该 SKU 声明 |
| 商品事实 | Source 保留原声明证据，Catalog 按准确版本提供同一 `Variant.stock` → `ProjectCanonical` → `draft.Builder`。1688 可订量保留为带来源的观察值，供应商观察值不建立经营者库存 |
| 离线包与诊断 | Listing Record 原精确来源、ApprovedAsset 与店铺准入 → 现有 SHEIN Builder 与 Validator → 原记录和回执；应用只装配。SHEIN marketplace owner 解释缺项并验证离线载荷 |
| 已保存结果 | Listing Record 原读取与操作查询 → 已保存的包、诊断、规则及摘要 → 原 API/BFF 与 Report Center。Report Center 按原快照呈现 |

### 库存表达与生产者

- 保留 Source `ProductVariantCandidate.Stock` 的原数字编码，避免把当前已存 envelope 内常规出现的 `Stock:0` 当成新证据。添加一个只用于明确零值且可省略的标记 `ExplicitZeroStock`。经验证的自有商品生产者在构造新声明时设置该标记，覆盖现有新建、导入、修订及复用该入口的自定义数据导入。正数继续走现有 `Stock`。未取得的值保持原 envelope 的未声明形态。
- 显式零标记只接受 `own_product/v1` 已准入生产者和匹配的自有商品来源身份，且 `Stock == 0`。将约束放在 Source 的生成与持久化验收公共边界。通用采集、受控样本、浏览器、属性、供应商及 HTTP 客户端输入均不能通过伪造同名标记声明零库存。现有严格客户端输入合同保持。若后续有其它明确声明零值的生产者，需按其 owner 独立确认。
- 同一 Catalog 字段 `stock` 改为可空的数值表示。当前已编码的非零数值保持相同 JSON 与顺序。新且有来源证据的零值编码为 `"stock":0`，无证据时省略。旧 Source 记录无标记，重算仍生成原快照字节。快照没有 `stock` 时读取为未知，原历史资料保持只读，禁止由今天的资料反推并重写原版本。新发布仍在原事务记录 Source、Catalog 和回执；同 Collection 原键重试仍以原命令输入与作用域恢复。
- Catalog 同字段消费者按事实处理。原页面若仅从快照取值，未知显示未填或留空。当前自有商品编辑入口能读到已核对的同版本原始声明时可以展示其数字，否则沿用现有必填校验等待用户明确填值。核对已有 `?? 0` 的自有商品编辑、差异显示、补全页，以及供应市场和选品证据消费者，保证未知不会经旧默认再写成新声明。只处理由本次同一字段造成的行为差异，供应商声明或正式目标仓库存的定义和公共写接口另有 owner。

### 诊断输入、字段与报告

- 构包用现有 SKU 库存字段表达已声明的数量。已知 0 保留为 0。未知时省略草稿库存行，原预览的可空 `StockCount` 保持空值。原草稿 `StockCount` 整数和 JSON 编码保留，通过现有库存行表达已知（包括 0），避免旧包经解码重算时字节含义改变。已有 `DEFAULT` 技术标识不能当作目标仓库证据。
- SHEIN validator 先检查原包同 SKU 的库存、重量、长宽高与单位，再走既有发布载荷结构检查。未提供与已提供但无效分别提示。库存 0 通过「库存已声明」检查，不推导可售、发布准入或仓库授权。缺库存、重量或尺寸时给出离线发布准备阻断，`save_draft` 保留现有允许缺项策略。仅在同 SKU、有原值且单位明确时做合法单位转换，禁止把 0、负数、未知单位及缺失尺寸归为有效值。已有包装尺寸必须对应同 SKU，商品级、兄弟 SKU 和供应来源观察值不能代填。
- 本次从验证副本移除库存 1000、缺尺寸 1 英寸及非正重量转最小正数的路径。传输字段整形、图片规则及与事实无关的默认值仍由原 owner 负责。发现报表对相同字段做重复判断时统一用现有诊断结果。字段提示沿既有检查列表、`paths` 与 `guidance` 渲染。按确定的 SKC/SKU 顺序汇总受影响字段，限制展示数量并提供总数，遵守原包体、结果和请求上限。
- 新诊断启用新规则版本，适用的 `Validator` 与持久化 `DiagnosticValidator` 版本同步核对。沿用原绑定算法，哈希主体包含实际规则版本。新计算入口只接受当前规则。保存时快照读取按记录中的已知版本用同一算法复核摘要，验证作用域、Action、Binding、结果与包字节，对未知版本、摘要漂移及错误作用域保持拒绝。旧规则只作为已提交快照的证据标识，历史读不重新执行旧规则或回写历史。BFF 和 Report Center 接收并显示已明确登记的保存版本。对旧包显式执行新诊断时，旧包生成的 0 行无法独立证明曾明确声明 0，必须按该包版本保留未知或由用户在新来源版本明确填写。

## 事务、重试与安全边界

Collection 原事务继续是 Source/Catalog 唯一发布路径，既有请求键、命令哈希、快照版本、权限和上限继续作为准入。原 Source 证据重算、校验与目录事实一致，旧 envelope 无标记时保持原哈希。相同键与不同输入继续冲突。

Listing Record 的已保存结果继续绑定企业、用户、原操作键、精确商品版本、批准素材、诊断规则和摘要。规则更新后，同一个已提交操作按原作用域和同一精确请求重读。原店铺、来源、ApprovedAsset 和 live guard 照原合同核对。按原记录的规则、绑定及当前精确输入哈希核对，保持输入／素材漂移拒绝。核对成立时返回原回执，不重新计算或写第二条记录。新操作走新规则，原 Insert 事务仍是并发仲裁点，响应丢失沿原原键查询。读失败或权限撤销走原错误处理。

分开验证新写和保存读取。发布时先具备两版保存结果的严格读取，版本切换需确保同一路径只有一种当前写规则，避免同一键被不同规则同时受理。实际部署与操作窗口另行准入。领域权限、企业隔离、批准素材、存储表、Provider、计费与发布权限均沿现有边界。

Legacy decision 为 **RETIRE**，退休虚构库存与包装数据的路径。已保存当代产品结果按其记录的合同验证，沿用同一 owner、原数据和原摘要算法。

## 验收

1. 复用三 SKU 离线复现作为回归。通过真实 Collection 发布、快照读回、SHEIN 生成与诊断，分别核对明确 0、7 和未知；1688 可订数量与伪造的零标记不能进入 SKU 库存。覆盖自有新建、导入、修订中同一 owner 的共用路径。
2. 包装重量缺失、单维度缺失、无效值和完整实测样例走同一 validator。核对待补 SKU 与字段、保存可用、完整原值可通过对应检查，原商品级数据没有填入 SKU。
3. 原 Catalog 快照与 Source 回执保留固定字节、版本和摘要。原 Collection 请求原键找回；已保存离线包和报告用原规则摘要读取，同键重复保存仅返回原回执，输入漂移、撤权、跨企业、未知版本与篡改摘要拒绝。
4. 检查现有后端、BFF 和浏览器诊断／报告路径，明确字段提示和版本一致；按最终 PR 的提交留定向回归、独立复核、CI 与独立验收证据。真实环境、外部平台与发布验收另行记录。
