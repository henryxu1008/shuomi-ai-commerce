# 编辑资料预置地区目录 V1

执行 [#1320](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1320)。依据 2026-11-16 用户批准：共享地区目录、三级联动、只选预置数据、后端校验。首批只供「编辑资料」使用，更新 35444 供试用。供应市场、平台站点、仓库配送区域、真实资料修改、生产发布均待后续授权。

## Owner、合同与实现

- 新增只读地名参考目录，落在 `internal/geography`。账户资料仍由 Account Profile 按现有登录主体保存。目录既不持有个人资料，也不承担供应地、物流地址或平台权限的事实 owner。
- 目录使用一份随应用代码发布的 GeoNames 快照，由 countryInfo、admin1CodesASCII 和 cities500 生成，使用 admin2 名称区分同名城市，中国候选采用 GeoNames 提供的中文名称。国家和地区使用源数据的两字母代码，省州和城市使用 GeoNames ID。目录为预置地点覆盖，不宣称包含所有聚落。无有效一级辖区映射的城市可从目录中的直属分组选择，选择省州时不得提交直属城市。新加坡直接选择城市，不将规划区作为省州。
- 数据生成 → Go 嵌入目录 → 现有应用路由注册只读 `GET /api/v1/account/region-catalog` → 同源 BFF → 共享联动组件 → 地区表单。GET 不带查询返回版本和国家列表；`?country=XX` 返回指定国家的省州和城市，限一个合法参数。请求仅发生在打开地区表单及选择国家时；不加载全球城市到浏览器。目录为固定数据，无外部运行时调用。按现有账户登录策略，BFF 校验当前会话并附访问令牌。读取有限大小的 JSON，设置现有账户超时和拒绝非 GET 的路径策略。
- 现有 preferences GET、保存响应及持久化结构保留。PUT 严格要求 `catalogVersion,country,province,city` 四个字段，后三项传目录 ID；服务端校验快照版本、父子组合和完整性，通过后转换为目录规范显示文本并调用原有账户仓库。一条记录可保存全部为空（清空可选地区）。有效的国家和省州必须选到目录有选项的最低层级；无省州时可直接选归属国家的城市，没有城市的分组可以留空。不接受用户新写自由文本。已保存文本原样读取，唯有逐级在相应分组中唯一匹配时才自动恢复选择；无法匹配时原文仍可见，须由用户重新选或显式清空，无批量改写。快照里同父级同名项补足区分后再导出，持久化名称必须能在原父级唯一反查。
- 前端逐级联动清空子级，国家切换不保留上一国家响应。通过原生选择控件配合搜索筛选长列表；搜索文字不作为提交值。目录加载失败时不能保存，根据原页面反馈重试。个人资料、换绑、密码和地区保存相互独立。
- 后端用已验证个人身份，不接收请求指定身份、企业或租户。原 BFF 的同源写保护、登录边界、请求限制、隔离和查询更新仍适用。拒绝目录不一致、未知或错配选择时不访问写入。持久化仍一次原子账户覆盖写，无新表。相同有效选择重复保存仍写同一地址；无新增外部副作用、补偿、任务或恢复协议，结果未知时沿原流程刷新核实。
- 由于新 PUT 有强制版本字段，旧 UI 到新后端、新 UI 到旧后端的写请求都会被拒绝而非误保存。35444 从当前两个服务版本分别叠加补丁，保留原配置和数据，按后端再前端切换。回退先前端再后端。读旧记录适用原 GET。无历史数据迁移与第二地名事实源。

## 验证与交接

后续供应市场通过[发货地视图](supply-region-catalog.md)复用目录入口。该读视图沿用供货名称和层级，账户地区仍使用原地名视图。

编辑资料没有已保存的地区时，国家／地区默认选中中国，独立于目录来源和校验规则。省／州和城市仍需选择，默认值不会自动提交。已有地区（包括无法匹配的旧文本）不应用默认值。

验证真实数据源结构和绑定，覆盖中国、美国、新加坡、同名城市、非法及跨父级 ID、快照版本漂移、清空和旧文本读回。前端覆盖搜索筛选、级联清除、现有表单原提交、加载错误和已存值。后端拒绝路径验证无写入，合法路径由现有仓库接线和隔离测试核对。试用仅替换两个受影响的服务镜像，核对原配置、新镜像、路由和受控目录读取，登录后实际填写由用户试用。

目录快照由 `python scripts/generate-region-catalog.py <GeoNames 原始文件目录>` 生成，输入文件及 SHA-256 记录于 `internal/geography/sources.json`。数据来自 [GeoNames 下载站](https://download.geonames.org/export/dump/)（`CN.zip` 来自其 `alternatenames/` 子目录），按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 使用。对原数据作了人居点筛选、父子归类、中文名称选择和同名区分。生产及试用运行时均使用随代码发布的快照。
