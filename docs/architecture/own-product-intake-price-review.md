# 自有商品录入价格建议与人工确认

执行 #1198，复用 PR #1212。Design Basis: Independent Architecture。Admission Status: IMPLEMENTATION_READY。2026-11-09 独立只读复核已核对真实 Decode → DomainProposal → API → 表单采纳 → 保存路径，无 BLOCKER；缺币种禁止填价、确认状态不可复活、人工价格整对保护、金额存在性和来源快照绑定作为 IMPLEMENTATION_TEST 落实，评审证据见 PR。本文件仅替换 `own-product-ai-intake.md` 中价格候选与采纳合同，其他 owner、权限、库存、图库、保存和运行约束继续有效。

## 产品决定与结果

2026-11-09 用户明确同意“AI 提取建议、程序校验确定规则、不确定价格交给用户确认”的分层方案，并要求今后不再用持续穷举语义正则解决此类问题。运营人员可以先采纳其他有效资料，不因范围、否定、冲突或币种归属难以自动判断而丢失整份候选。

## 合同与责任

- 模型只输出每行可选 `priceSuggestion: {amount, currency?, evidence}`。`amount` 是有限、非负数字，缺失建议代表未知；0 是明确的建议值，不能从缺省生成。`currency` 若提供，须为三个大写 ASCII 字母。`evidence` 必须是原说明中逐字存在的有界片段。模型不得声明“已确认”。删除行级直接 `price` / `currency` 字段，旧 schema 不自动转换为已确认建议。
- 程序校验 JSON、字段/数量限制、数值格式、币种格式和来源片段确实存在。它不从自由文本推断价格归属、费用类型、否定、范围、冲突或语义可信度，不把数字或币种在原文出现当作其已正确绑定的证明。既有其他字段校验不扩展语义规则。
- 所有价格建议都待人工确认，不由模型的置信度或自称“明确”跳过确认。每行展示建议金额、币种、引用片段，并提供完整原说明以防裁剪掉上下文。逐行复选框默认为未选中，明确说明用户是在确认该规格的商品单价和币种，而非确认 AI 已校验。缺少币种时仍展示建议，但不能勾选或自动填价，提示在原表单手工填写金额和币种；不默认 CNY 或只填半组价格。
- “采纳到商品表单”只填入该次候选中用户逐行确认的价格建议。未确认行价格和币种保持原状，其他有效字段仍可采纳。价格与币种成对应用：已有任一非空人工金额或币种时，不覆盖或把新金额与旧币种拼接；用户继续通过原表单手动修改。已移除组合、已确认图片、SKU、标题和其他人工值继续按原保护规则处理。
- 确认选择只属于当前候选对象及输入快照，重新生成、读回替换、输入/图库变化后不能复用。取消勾选不填价；关闭/展开同一未变候选不丢失表单值。相同候选的重复采纳不会覆盖已有人工价格。
- 无法解析的 JSON、未知字段、越界值、伪造来源和结构性无效候选仍按现有失败合同拒绝。自由文本的语义歧义不再触发 `price_evidence` 整体拒绝，而是留在带来源的待确认建议中。该分层不声称能自动识别所有歧义或证明建议正确。

### 库存的保守字段隔离

受控测试发现既有库存证据检查会把同一行价格的“尚未确认”当作库存不确定。本次不追加库存语义正则、不遮蔽模型引用的价格片段，也不把库存静默放行。价格合同实施中的这一交叉作用按相同原则隔离：数值合法但现库存证据检查不通过时，只移除该行的库存建议，并在返回的程序投影 `stockReviewRows` 中列出该行；UI 明确显示“库存需核对，未填入，请在商品表单手工确认填写”。库存负数、越界值、类型错误以及伪造行来源等结构错误仍整体拒绝。其他有效字段继续可用，原有人工库存继续保留。省略仍是未知，明确且通过原检查的 0 保持 0。该局部合同增量经独立复核可在当前准入内实施，无新 BLOCKER。

模型 wire Candidate 不能提供 `stockReviewRows`。严格 JSON 解码后，intake owner 的纯 `ForReview` 投影复制行并移除未通过原检查的库存，再验证余下结构/来源。原 Run 仍只持有原 provider 输出与回执，DomainProposal 不增加持久字段。原键 GET 在回执验证后从同一原输出运行同一投影，确保首次返回、重复确认与读回一致。此增量不改变 Run 状态机、收费、模型调用、保存、租户或事实 owner；不确定库存需要用户在原表单明确填写，不增加独立自动确认机制。库存结构本身无法解码的 JSON 仍按结构错误处理。

## 接线、安全和恢复

owner 仍是 `internal/product/collection/intake`，正式商品价格事实仍由用户提交的 Collection/Catalog 命令持有。不增加保存接口、数据库表、第二事实源或外部副作用。新候选 schema / prompt 版本整体更新，Agent 配置使用当前版本；不迁移旧运行或伪造兼容结果。

继续使用原 Prepare → 确认生成 → GenerateWithGate / Decode → DomainProposal → 原键 GET → 人工采纳路径。一次原键最多一个模型调用，原输入摘要、Quote、预算、预留、UNKNOWN 不重发与回执校验不变。价格确认仅是本地表单动作，不调用模型、不新建请求、不结算/释放预留，也不自动保存商品。旧配置/运行按既有版本与摘要规则拒绝不匹配，不从旧价格字段推导新确认状态；本次不更新任何保留实例。

## 验证与停止点

- TDD：四类原反例和材料/运费/多规格等普通文字都可成为待确认建议，但无逐行确认不能填价；明确价格也不绕过确认。未知与 0、错来源与非法数值分别验证。
- UI：未确认仍能采纳有效标题/SKU/规格；只采用勾选行；取消勾选、更新输入、重新生成、原键读回、人工已填单边币种/金额、移除组合与重复点击均有回归。
- 原预算、单次受控派发、同键 GET/重复 confirm 和 UNKNOWN 的现有测试继续通过。只能用受控模型替身；不访问真实模型、35444 浏览器、保留实例或真实账务。
- 一次独立设计检查，最终实现后集中复核实际 diff 和用户路径。准确 HEAD 的必需 CI 与评审点赞后才可按已有授权正常合并；代码评审和 fixture 不等于用户验收或上线。

不做：第二模型互验、通用 NLP/规则框架、持续语义正则枚举、迁移、部署或额外验收平台。
