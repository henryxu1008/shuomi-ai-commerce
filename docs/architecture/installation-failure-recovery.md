## 1. 产品决定与交付边界

用户 2026-11-11 明确要求：先给安装失败处理和安全重试做最小方案并独立评审，说明失败步骤和原因、旧测试记录归档、`shuomi-local` 35 个卷的核对、保留和重试条件；不写生产代码、不删除卷或记录、不重发安装、不改原35444。

用户结果：看懂哪次安装停在哪一步；保留现场，检查原结果；仅当安全条件得到证明时，明确确认后再次尝试。同一操作保留每次尝试的历史，不要求用户删除JSON、猜测网络或换名称绕过阻断。

本设计只修 [安装与模块管理](installation-and-module-management.md) §6 的具体缺口，当前领域 owner、[系统边界](project-boundaries.md) 与 [全新系统基线](../product/greenfield-no-legacy-migration.md) 保持。Figma仅流程参考；界面用“安装记录、安装名称、失败步骤、检查结果、重新尝试”等用户用语，不展示内部状态名。

Must：

- 原操作、目标、安装版本和首次输入可追溯；未知结果不能重发，归档不能伪造成功或放行有冲突的安装。
- 35卷和所有原有数据/身份/凭据/权限保留；无容器、无marker、无报错日志均不能单独证明未初始化或卷为空。
- 正常首次安装继续拒绝已有资源。只有本文件限定的同一原操作、已证明未初始化的空资源重试有额外准入；不扩成保留库初始化、断点续跑或通用重装。
- 所有恢复mutation继续使用本机配对、Origin/CSRF、全局及实例OS锁；普通业务后端、BFF、企业角色不获得Docker或恢复权限。

Out of Scope：自动安装/自动重试、删除/清空卷、备份回灌、修复已初始化的owner、取消运行命令、远程运维、业务/模型/provider调用、原35444更新、账本或原15.445282点预留操作。设计通过不授权实施或真实恢复；未来执行须另有明确窗口。

Threat Model沿原设计：错误实例、并发/重启重放、资源漂移、证据不足、凭据泄露和旧工具覆盖恢复状态。恶意拥有Docker/本机文件写权限的宿主管理员仍非本机工具能隔离的主体；不新增通用IAM或分布式恢复平台。无新增Accepted Risk。

## 4. 步骤、原因和结果如何记录

面向用户阶段为：检查安装条件→准备安装文件→准备安装组件→启动安装服务→检查运行结果→提供登录资料。每个阶段开始前先持久化intent，阶段完成后持久化结果；准备文件与启动服务的界限明确。复用原命令调用，不把Compose服务图重写成自制部署引擎。

每次尝试保存：编号、原操作ID、独立attempt key、候选/输入摘要、原安装release、阶段intent/result时间、受控reason code、命令退出/超时/启动失败类别、是否已进入服务启动、资源观察摘要和最终结果。完整参数、环境、原stderr/stdout和凭据不进公共响应、控制台或诊断文件。

原因来自确定的检查/执行结果：版本文件未就绪、端口占用、目标资源冲突、配置漂移、文件准备失败、组件构建失败、服务启动未完成、健康检查未完成、登录资料未能交接等。使用固定受控说明；可用的非敏感结构化子原因可细分。不能安全确认根因时写“失败原因尚未定位”，保留步骤及退出类别；不通过关键词穷举猜业务事实，也不把可能的网络问题写成确定原因。

结果分开：

| 执行结果 | 含义 | 可以执行什么 |
| --- | --- | --- |
| 待确认 | 仅候选，尚未派发 | 修改设置并重新预览 |
| 执行中 | 已持久化本次intent | 读原记录，不另起尝试 |
| 安装前未完成 | 有明确证据失败发生在启动服务之前；可能已准备镜像 | 先做恢复检查，再明确确认重试；不是自动放行 |
| 结果待核实 | 服务启动已派发、响应丢失、进程重启或历史阶段证据缺失 | 只检查；只有§6证明未初始化时才允许明确新尝试 |
| 已完成 | 原Verify完整成功，含必要服务和交接 | 查看入口，不能再次初始化 |

旧记录没有阶段/原因就展示“当时未记录”；不回填猜测。一次尝试的原结果不因后续成功、归档或重试而改写。

## 5. 私密记录、旧工具及归档

### 5.1 同一操作内的记录演进

使用现有owner的**v2单一可写操作记录**，包含不可变原执行事实、按序尝试、诊断及独立的处理状态。v1当前原记录在首次明确恢复确认时先按原字节保留审计副本及SHA256，确认副本准确后才原子写v2；原操作ID/输入保持，不做全库转换，不恢复旧系统/跨域迁移合同。

审计副本只读且不被当作新的执行事实源；v2是恢复后的唯一可写记录。中途崩溃：写v2前原记录仍有效；副本已存在则须逐字节核对，不覆盖；v2写入后只读取v2，不从副本fallback。损坏或无法证明的记录保持阻断，不能恢复副本后重发。

对于进入v2的实例，`active.json`保留指向原操作的持久guard，不因成功/归档删除；新控制器按记录处理状态判断是否存在冲突。旧工具要求Version=1，因此读v2拒绝；它仍读到非空guard，也不能另建原实例操作。新工具所有后续该实例操作使用v2，明确新安装确认时才在锁内将guard切至新v2记录。关闭旧窗口只是使用说明，不承担安全互斥。

v2原子replace是恢复决定/新尝试的提交点。guard更新只在可证明安全的已结束操作后进行：先落盘新v2意图，再CAS原guard；两文件之间崩溃不能派发。未被guard选中的新意图不可执行，恢复只按原key修复guard投影，不自动发送安装。不得通过删除guard、改目录或换独立operation key绕过原状态。工具降级不能撤销v2已提交的决定，旧版应失败关闭。

### 5.2 归档是处理状态，不是执行成功

卡片显示安装名称/动作、发生时间、最后步骤、可确认原因和下一步；原失败原因缺失明确提示。归档记录仍可从“历史安装记录”查看全部原结果和证据。

本轮只开放**资源已清理且无冲突**的归档：原记录属于新空安装、准确daemon/project/原计划可读取，原计划所指全部专属卷/容器/网络及同project/名称前缀资源均不存在、无其他容器引用；查询失败或疑似外部绑定均拒绝。用户预览“原结果未确认；相关资源已清理；仅结束待处理提醒”，明确确认后写处理状态archived，保留guard与原执行unknown，不产生成功/撤销/账务释放事实。

这覆盖旧测试记录；**不覆盖仍有35卷的shuomi-local**。有资源、仍在执行或无法证明无冲突时，不能用归档清除保护。不得以“归档”为名调用down、rm、prune或清空任何内容。

## 6. shuomi-local 35卷的核对与重试条件

### 6.1 先只读核对，再区分结果

这35卷包括数据库、安装状态、配置/凭据/证书及邮件数据；不能只检查数据库卷或几个marker。沿原封存Compose枚举完整预期集合，逐项核对name、driver、options、准确project/volume标签、CreatedAt及挂载绑定，检查所有运行/停止容器的引用。额外/缺失/重建/改标签/foreign引用都作为漂移，不能凭名称前缀认领。

在后续获准实施/检查时，卷内容检查只能读取：优先复用已有只读资源入口；若用固定、已校验的最小helper，必须无网络、只读root、cap-drop、受限时长/资源，读取Docker inspect返回的准确local卷Mountpoint，使用不自动创建源目录的**只读bind**；禁止用不存在时会自动创建卷的named-volume mount补证。仅接受本地无options卷、可信daemon返回路径；界面不能提交宿主路径。环境不支持安全读取即待人工核对，不能改权限或降级为猜测。

完整枚举卷根目录（含隐藏项、不跟随symlink）；只输出检查成功/空或非空及受控数量摘要，不读取/回显秘密字节或任意文件名。无法读取、超时、特殊文件或未完成枚举均为未知。helper前后再次核对卷元数据与引用，源缺失则拒绝，不创建新卷。**无marker不等于空；任何条目存在都不属于本轮的空卷重试。**

结果：

- 35卷全为空、无容器/网络、无外部引用且完整版本/绑定未漂移：可形成“未初始化、保留空卷再尝试”的候选。
- 任一卷非空：完整保留，交原owner判断；首版不继续初始化、不自动备份/还原/删除，也不放行换名重装。
- 任一项未知或漂移：保留“仍需核对”，不得生成可执行重试候选。

当前仅完成元数据核对，内容状态仍UNKNOWN；本文件不授予任何一卷“空”的结论。

### 6.2 候选、输入和执行

“检查原安装”只产生观察；“准备重新尝试”仍不执行。当前操作guard匹配、没有持锁执行者、原版本与原候选完整性均通过后，才能封存恢复预览：原操作ID/最新revision、各35卷证据摘要、准确daemon/project、source/image身份、预期资源集合、网络/端口、候选digest与有效期。确认时再次完整核对，不能只信旧摘要。

原安装release须由封存Compose的构建目录/镜像绑定与本机准确source receipt交叉核对；不能把显示用“安装版本”文案当执行依据。当前v1缺字段时必须从这些原生证据准确建立绑定，无法建立则阻断；不默默改用新控制器镜像。安装工具版本与被执行安装版本分别记录。

保留同一project、原操作、安装功能、origin/端口、身份和35个卷。不删除/重建卷。仅允许为修复前置而在新预览中修改可选网络地址范围；明确展示差异且检查不重叠。不允许改业务配置、功能组合、安装release或源目标；需要这些改变时停止本恢复路径。

正常新空首次安装的无资源检查不放宽；增加同owner限定的恢复准入，只允许原操作已核对的完整35个空卷存在，其余检查原样执行。封存并核对实际候选后，显式确认才调用相同Compose/bootstrap/原owner顺序；不从中断步骤跳过初始化，不改变原owner合同。任何已初始化或非空状态不能走此分支。

这是**同一操作的新尝试**，不是重发不明原命令：原attempt0结果与原输入冻结；服务端递增attempt ordinal，生成绑定操作ID、preview ID和payload digest的attempt key。相同key不同payload拒绝。网络输入差异只存在新attempt，不改原输入。每次都先写意图，再至多派发一次；不按次数自动重试。

同一预览重复确认返回同一attempt结果；不同预览并发确认用revision CAS仅一个成功。失效预览、源/卷/端口漂移、CSRF/配对失效或已有执行者均拒绝。进程在写intent后、调用前或调用后崩溃都不能据此重新派发；重启进入待核实，只走原检查。全局锁→实例锁顺序与现有实现相同，从审计至派发和最终提交保持排他。

新attempt再次失败时保留35卷及其新状态；一旦出现非空内容或初始化证据，本空卷重试通道关闭。全部原Verify成功后只把操作总体显示为“重新尝试后完成”，原attempt0仍显示原结果，不能把旧失败改写成成功。

## 7. 持久化/故障边界与权限

| 边界 | 失败、重试与重启结果 |
| --- | --- |
| 原记录审计副本→v2原子replace | 副本准确性未证明不提交；提交前无mutation，提交后以v2为准；旧工具拒绝，不能丢恢复字段 |
| 预览→确认 | 重读事实、revision和源指纹；旧预览不再有效；确认响应丢失读同一attempt |
| attempt intent→原命令 | 先私密落盘再派发；不能证明未派发即待核实；不自动回收或重发 |
| 资源核对→启动 | 锁内完整再检查，source/name/CreatedAt/引用漂移拒绝；宿主外部修改不能以原成功观察掩盖 |
| 命令完成→Verify/记录提交 | 未完成最终原Verify不宣称成功；崩溃仍可原key核实，不用再安装证明成功 |
| 结束记录→guard切换 | v2决定是事实，guard保留；更新仅在已证明结束后，CAS失败不派发；保留全部历史 |

恢复/归档确认使用现有同源本机mutation安全，不新增业务权限。只记录本机配对会话非秘密审计标识、操作/attempt、确认时间及观察digest，不伪造企业操作者。网络或读取失败不会触发下载、建卷、启动worker、owner初始化或隐式修复。

## 8. 实施验证与停止点

沿现有测试与一次隔离环境入口，不建设runner或专项平台。实施时TDD及四项实施验证：

1. **诊断与秘密**：准备文件/构建/启动/健康/交接失败、重启失联和旧缺证据分别显示；原始stderr含假密钥/口令时公共响应、私密诊断及日志均无秘密；不捏造原失败原因。
2. **记录/归档/旧工具**：准确保留原字节及结果；已清理测试归档不成功、不删卷/记录；仍有资源或运行者拒绝；故障注入v2提交及guard切换、旧工具读取/写入均失败关闭。
3. **35卷准入与保留**：在隔离合成35卷验证全空才可预览/明确重试；任一隐藏文件、marker、数据库/secret内容、额外/缺失/重建/foreign引用、读取超时/缺源均拒绝；逐卷前后保留证明。当前真实35卷的内容检查/重试另列真实操作窗口，不能用合成结果代替。
4. **同操作幂等与实际接线**：预览→确认→同key重试→刷新，ordinal/key/digest绑定；两个进程竞争只有一次派发；确认丢响应、重启、版本/网络漂移和初始化后再次失败均不重发；绑定原Compose/owner/HTTP/UI的完整调用链。

实际生产代码、实际v2写入/归档、真实35卷内容检查与重试、原35444操作、业务保存及外部调用均NOT_RUN。本轮仅设计和独立评审；实施准入与真实执行授权分别判断。原设计未受影响部分保持冻结；本文件只覆盖实际新增的诊断/归档/受控重试边界，不取消旧失败拒绝或新增迁移承接。
