# 新会话先输入需求

状态：内容型范围 **IMPLEMENTATION_READY**；独立评审未发现架构阻塞，下述恢复和隔离按实施测试收敛。标题型会话当前不支持范围上下文，该模式不开放项目／店铺入口；不假称已绑定。35444 当前为内容型。

## 目标与范围

当前企业用户从 Chat 输入需求，不必手选工作范围；从明确项目或店铺打开时显示经当前授权读取的真实背景。用户明确继续后沿现有 Create 创建会话，将文字带入该会话的可编辑输入框；不自动发消息、调用模型、扣点或创建业务任务。创建结果未知时沿原键核对。用户 2026-11-12 新决定替代 #298 的新建时手动选范围交互，不取消固定范围及当前授权。Figma 仅用于流程参考。

## Owner 与路径

- 会话及固定范围事实 owner 仍为 `aiworkbench`；调用现有 scope-options、conversation-create 和 conversation-detail，不新增 schema 或第二业务事实源。
- 一般入口向 scope-options 获取经授权的唯一 `general` 和确认摘要，自动用于原 Create；标题型沿原无范围合同，项目／店铺入口明确不开放，不假称已绑定。读取失败提示并重试，保留输入；不捏造摘要。
- 项目／店铺详情明确入口只传类型和 ID，Chat 以现有精确 ID 的 scope-options 读取获准对象及摘要，显示项目和绑定店铺或店铺名称。无权、不可用、归档、摘要失效时停止提示，不降级通用或猜测对象。项目绑定变化重新显示并由用户明确继续。商品采集 `operationId` 路径保留。
- Create 使用原 org/actor/member 授权、`scopeSelection`、`scopeConfirmation`、幂等键和回执；已有不可变范围与发送时实时授权不变。

## 输入草稿与恢复

- 文本是当前浏览器标签页的未发送草稿，不是业务事实，按用户、企业、入口上下文隔离，不放入 URL、Create body 或服务端；限制为现有消息的 8192 UTF-8 字节。存储写入失败时阻止创建或跳转并保留当前输入、提示原因，不假装刷新后能恢复。
- 创建前持久化草稿和原 Create key/body 为一条记录；同一用户企业的原 pending-create 仍是唯一未决 owner，其他入口不得覆盖。结果未知只重放原键及载荷，不按新范围重发。只有服务端明确未受理才可释放旧键。原回执返回后先把会话 ID 绑定到同一记录再导航，写入失败保留原键和输入；详情完成同用户企业会话授权、原 pending 状态水合后预填。刷新或丢失响应可恢复；不得覆盖详情已有待恢复发送、草稿或用户输入，重渲染不得覆盖用户编辑。标签页复制时同一未决键只能恢复同一会话。切换身份、企业及上下文不得混用草稿。
- 草稿不触发 message POST、报价、规划、provider、结算或后台发送。原详情页显式发送继续使用原校验、授权、预算与幂等。规划不可用时仍显示保留的草稿及不可发送原因，不伪装可发送。
