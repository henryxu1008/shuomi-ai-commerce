# 硕米 Chat 费用与状态展示

状态：DESIGN_CANDIDATE，待独立评审；不得用于生产实现。

## 用户结果与范围

用户发送商品内容需求前看到本次规划的费用上限；确认内容执行前看到该任务执行上限；调用完成后，在会话和任务中看到对应调用已结算的实际 AI 点数。任务状态按内容/标题正确显示。金额估算与 AI 点是不同口径，不互相换算；状态未知不显示零。无需改变模型、额度、结算或商品审核/应用流程。通用问店铺的路由/概况保留现有行为，不把它伪装成商品内容规划；无模型的请求不显示虚构费用。

## 现有事实与边界

- Chat `PlanningCommand` 是消息/规划命令 owner，绑定会话、用户消息、成员、规划 invocation、输入哈希和原 scope；`BusinessTask` 绑定确切 proposal、执行配置和 Agent 请求。Agent owner 持有原 run 及其模型调用；`aicapability` owner 持有调用与受控报价；商业资源 owner 持有预留和最终结算回执。不得建立第二账本、读取全企业明细后在浏览器猜任务归属，或以估算金额冒充实际扣点。
- 复用既有受控规划 `einoplanner.Prepare`、当前实时 route/价目/汇率和 `QuoteText`；复用任务执行快照 `ExecutionLimits` 和 `OfficialTariff`。复用 `ConfirmModelInvocationSettlement` 对商业 owner 不可变回执的核验，扩展其同 owner 内的受限只读结果以返回已核验实际点数。金额标为参考上限；点数为商业计费口径，格式为 `ai-micropoint-v1` 的十进制字符串，不用浮点数。
- 已有产品授权、聊天读取、任务读取和当前企业/会话/商品授权继续有效。不得因可查看自己会话而赋予商业管理员读取全企业账本的能力；先以当前身份通过原会话/任务 owner 授权、范围与商品来源复核，再由服务端以绑定 ID 调用受限 owner 查询，不能接收任意客户端 invocation ID。历史撤权或切企业时不可返回相关计费、模型、商品或历史内容。

## 操作前与实际结果

1. 规划前的只读预览使用当前输入、选中商品、模板、知识及当前会话 prefix 和当前身份按既有 admission 准备，返回规划金额和 AI 点的保守上限、其所依赖输入和价目标识的有界指纹。没有消息写入、预留、模型或恢复动作。每次输入、选择、身份、上下文、历史、价目或汇率变化，已有预览失效；无权限、不可计算或依赖失败时明确不可用，不展示零或静态配置作精确报价。当前发送逻辑仍在锁内重建准备、复核事实和报价并保持原有 dispatch 门禁；预览不授权发送、不改变预算或幂等。并发有新消息/权限或价格漂移时前端刷新报价；发送时仍以原有服务端门禁的当前报价为准，不承诺先前展示值锁价。
2. 在执行方案上保留现有冻结的任务总金额上限，并基于冻结执行配置和当前可核验价目给出最多模型调用的保守 AI 点上限；显示最多调用次数和计量依据。价目发生变化不能沿用旧值冒充当前执行上限，重新计算或显示不可用；确认路径原本的授权、版本和额度校验不得弱化。规划费和内容执行费分别显示，不能把一次模型的上限与整个任务的上限相混。
3. 查看会话消息的规划扣点必须按 `PlanningCommand` 的 scoped 会话与消息引用定位原 invocation；查看任务扣点从原 `BusinessTask` 定位唯一 Agent run，并从该 run 的原调用记录逐一绑定商业结算回执。仅对已核验的 committed/released 终态呈现已结算实际值；unknown、reconciliation、不可读、调用列表不完整或部分调用未终态时，显示「结算中/暂不可用」，不能把已知部分称为任务总计或显示零。每条 invocation 至多计入一次，不按组织余额差额推算，不混入其他任务或历史预留；失败但有可计量用量也照实显示。商用回执不一致时 fail closed。
4. 任务的 `HUMAN_REVIEW_REQUIRED` / `AGENT_RESULT_NOT_REVIEWABLE` 依已授权任务类型展示内容或标题，不改变状态或审核权限。原历史消息只在能够可靠归属并完成实时授权时展示数据；缺少映射显示不可用，不回填历史事实。

## 合同与接线

报价预览：Chat UI → 同源 BFF → 受 Chat use 权限约束的只读 Chat preview（严格输入、限长、no-store）→ 现有工作范围及商品授权 → 当前路由和 planner 准备/报价 → 最小化上限投影。此端点不得调用模型或创建 command；拒绝任意 client-provided 价格、成员或 invocation。实时结果仅为预览，不提升为发送期保证。

实际扣点：会话/任务投影 → 原 owner 按现有 scope 解析原 command 或 run → 调用事实 → 商业 owner 验证同企业、原调用身份和不可变结算收据 → 返回仅该资源的状态与点数。原收据既是唯一权威，未最终结算时不得根据 token 推导声称已扣。结果不缓存跨用户/企业；无准确绑定就不可用。

执行期所有 gate、额度和幂等沿用原合同；无新持久事实、表、后台扫描、补偿、外部副作用或旧数据迁移。预览不触发 provider、结算或数据写入；正常发送、未知结果处理及明确人工采用保持不变。

## 验证

使用现有受控模型/账本 fixture：内容与标题状态；两个阶段上限的来源、单位与格式；输入/历史/价格变化的预览失效；规划与多次执行调用精确关联、累计且不重复；零/失败/部分和未知结算诚实显示；商品撤权、会话与任务权限、跨企业和跨成员不泄露；并发与原键重试不触发额外调用或更改结算；不可用时保留可用既有任务。必要 UI 测试含键盘、窄屏；不做真实模型调用、不写回商品、不发布、不释放原预留。部署和用户试用另行授权。
