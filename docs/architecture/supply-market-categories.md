# 硕米自营与硕米优选共用商品类目

2026-11-17 · Design Basis `Independent Architecture` · Admission `IMPLEMENTATION_READY` / FROZEN · [执行 Issue #1377](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1377)。用户于 2026-11-17 确认方案。

## 用户结果与适用范围

用户明确要求两个货源渠道共用商品类目。平台管理目录，自营发布前选择，优选审核时确认，卖家在两个市场列表按类目找货。本方案以[供应市场发布合同](domains/supply-market/supply-market.md)、[已有市场筛选](domains/supply-market/supply-market-filters.md)、[精确发布与已加入状态](domains/supply-market/supply-market-card-selection.md)及[当前领域边界](project-boundaries.md)为依据。批准与发布沿用两个独立动作。

首版采用两级目录。一级用于归组，二级用于给商品归类。每次发布只归入一个已启用的二级类目，例如「家居日用 / 收纳用品」。两个渠道使用同一目录与规则，商品仍在各自货源渠道展示。目录初始内容由运营按实际货盘创建。示例名称不作为预置目录。

来源商品类目、各电商平台刊登类目和货盘对接申请中的经营品类各自沿用原用途。首版范围限于市场商品的类目归属和浏览。自动归类、跨平台映射、批量改类、类目合并、移动父级和在架商品直接改类不在本批。

## 用户操作

| 用户 | 入口与步骤 | 完成与反馈 |
| --- | --- | --- |
| 平台专员 | 从现有「供应发布与人工评估」进入「商品类目」。按一级展开二级，支持新增、改名、停用、恢复。短表单复用现有对话框，返回目录原位置。 | 保存后显示实际状态。停用确认先说明对新发布和在架商品的影响。允许停用整个一级，也允许单独停用二级。 |
| 自营专员 | 沿用选择自有商品、填写供货信息、预览发布流程。在「自营商品发布预览」核对商品与供货信息，选择商品类目，再点「确认发布」。 | 类目与商品同次发布。目录未配置、读取失败或选择失效时，在类目控件附近给出可操作的提示。发布失败后保留草稿，重新选择时保留供货资料。 |
| 优选审核专员 | 沿用申请详情与人工审核。在通过审核时选定类目，同时记录原评估说明及线下合作确认。要求补充和未通过仍可直接办理。 | 「审核通过」记录类目，随后可单独发布。类目失效或已有批准记录尚无类目时，由平台人员在原详情重新确认后再发布。类目确认单独留痕，原审核结论和合作确认仍可查阅。 |
| 有权浏览供应市场的卖家 | 在「硕米自营」或「硕米优选」的原筛选栏选择一级或二级，可与关键词、发货地、价格、起订量、供货周期一起使用。 | 选一级时包含其所有匹配二级商品，选二级时精准匹配。应用或清除筛选回到第一页。由列表进入详情再返回时保留该列表的筛选。详情展示完整类目路径。 |

目录页复用现有 Console 页面与列表组件，发布、审核与市场筛选复用各自现有页面。类目控件复用原表单组件，支持键盘、窄屏、字段错误及读取重试。目录尚无可用二级类目时，告知专员先创建或恢复类目。原发布与审核详情继续可读。

## 改名、停用与已上架商品

- 类目 ID 和父级固定。同一父级下名称唯一，一级之间同样唯一。停用类目保留原 ID 和名称位置，可恢复。改名适用于纠正或更新叫法。运营要改变分类含义时新增类目。目录支持停用与恢复，保留已引用的类目。
- 停用一级后，旗下二级全部暂不可用于新审核或新发布。恢复一级后，单独停用的二级仍停用。停用不下架商品。当前渠道还有在架商品的停用类目继续作为该渠道的筛选项，包含所需一级路径。改名后，列表和详情按同一 ID 展示当前名称，历史审批事件保留当时的类目路径。
- 尚未发布的优选记录若需重选，只有平台专员可在已有审核通过、合作已确认且无在架发布时操作。记录原选择、新选择、操作者及时间，保留原审批事件。发布只消费最近一次有效的确认。无在架发布也覆盖撤销后准备再次发布的情形。
- 当前系统已经发布且尚无类目的商品保留在「全部类目」，详情显示「未分类」。从本版本开始的新发布必须有有效类目。现有商品不猜测归类，不做批量补录，不改写已有发布版本或已加入「我的数据」的来源。试用样本已有发布及选入记录，不能通过批量撤销重发来补分类，因为重发会产生新的发布 ID。相关现状有[前一轮试用记录](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1292)。

## 事实归属与调用路径

SupplyMarket 在现有 Product 数据库负责市场类目目录、优选已确认类目和发布所属类目。Catalog 继续负责原商品资料，Listing 与平台规则负责刊登类目。商家私有商品和「我的数据」均不写回市场类目。市场浏览视图以发布所引用的稳定 ID 读取目录名称，目录是当前名称的唯一来源。审批历史中的名称是当时的操作证据。当前市场类目路径只放进市场浏览视图，原选入来源证据和摘要继续使用原发布资料。

`Console → 现有供应市场 BFF / HTTP → SupplyMarket Service → 同库 PostgreSQL Repository`。沿用现有供应市场运行装配。平台端提供目录读取和管理命令，组织端提供按渠道有权浏览的筛选目录及列表查询。浏览目录只返回选择所需的 ID、名称和父级，只包含当前渠道可见的已停用项和可用类目，不返回平台操作人、私有商品、申请、资质、内部组织 ID 或管理字段。

目录用一张关系表保存稳定 ID、父级、名称、启用状态和版本。用父级及去除首尾空白后的名称约束同级唯一，一级作为独立唯一范围。禁止第三层，父级建立后固定，禁止硬删除。子类目指向现有一级，使用既有数据库约束结合事务内领域校验。优选确认与发布各自用可空外键保存原记录和发布上对应的类目决定，空值只表示类目推出前的现有记录或尚未确认的申请。新发布强制有二级 ID。写路径和读路径以此引用为准，不在原商品、发布 JSON 和独立缓存分别维护同一引用。审核事件可留存当时名称供审计。

两渠道的列表加入单个稳定类目 ID 查询。一级展开至直接子级，仍先应用当前渠道与在架条件，再与现有过滤条件组合计算总数和分页。筛选目录按当前渠道给出有效候选，读取结果有界，较长目录按层级分页，不静默截断。已移除的筛选选项给出可理解的提示并允许清除，不将有条件的查询悄悄改成全部商品。没有新的匿名访问入口。

## 权限、持久化与恢复

- 类目管理、优选确认及自营发布走现有 verified global platform 权限与重新授权检查。企业管理员不能写类目。自营发布仍要求原建草稿账号和原商品权限，优选仍核对已批准、合作确认、精确来源及披露权限。市场浏览和目录查询继续使用当前企业的供应市场读取权限和返回前复核。目录读取按用途区分市场筛选项与平台可分配项。
- 审核通过与类目确认、发布与类目引用、目录变更与操作记录各在原 Product 数据库事务内提交。对同一申请或发布，复用原记录锁及版本检查。发布、审核确认和目录操作统一先锁一级再锁二级，需锁业务记录的命令先锁业务记录。原子检查一级和二级的启用状态。选择时返回类目路径版本，确认时校验，捕获同时停用、改名或旧页面误提交。已审核后仅改名时，发布页展示改名后的路径并由专员明确确认发布。发布先提交则后来停用保留该商品，停用先提交则发布失败并提示重选。
- 写入复用 SupplyMarket 命令回执和原恢复入口。类目 ID、版本及明确操作参与请求意图摘要。相同操作者和幂等键、相同意图返回原结果且重新授权，载荷或版本变化视为冲突。结果未知时从原入口查回执或以原键重试。升级前浏览器仍待核实的无类目审批或发布只查原回执，已经停写的旧请求不能重发。按受影响记录保留专员、动作和时间供审计。目录变更摘要复用回执，记录目标类目、操作、版本和前后值，与操作者及时点一起可追溯。优选确认沿用申请事件。目录改名和启停不会生成新发布 ID。卖家选入仍按原发布 ID 和版本处理。
- 前端、BFF 和服务端校验类目名称、ID、版本、层级参数，沿用市场请求超时、列表页大小和响应大小限制。浏览按页读取类目名称，不为每张商品卡发请求。此改动只有本地数据库读写，无模型、刊登、计费或其他外部调用。
- Legacy decision 为 N/A。当前系统正常增加目录和引用。新安装走现有安装及运行校验入口，注册目录表及最小运行权限，运行账号只有所需的读取、插入和更新权限。保留实例若获准更新，由数据库 owner 做经审查的增量结构变更及授权，先停止旧发布写入，再切到执行新类目规则的版本，保留已有业务数据。首次安装命令拒绝非空库，运行启动也不自行改库。现有记录的空类目是真实状态，无旧服务、历史回填或第二事实源。试用交付采用用户授权的试用范围。

## 验收与实施准入

用现有隔离 PostgreSQL、HTTP/BFF 及组件验证覆盖以下路径。

1. 平台专员创建、改名、停用和恢复两级目录。企业管理员调用管理接口被拒绝，重复同级名称可恢复处理。
2. 自营从现有草稿选有效类目发布，缺类目或停用后拒绝发布。优选通过时记录类目，发布前市场不可见。停用旧类目后可在原申请中重新确认，再独立发布。
3. 两渠道分别验证一级、二级、叠加其他条件、准确总数与翻页。停用后在架商品仍能筛出，既有未分类商品仍能在全部类目找到。目录改名与停用不影响原商品的「已加入」状态。
4. 并发停用与发布、旧版本以及同键重放按事务合同处理。已有市场读取、选入及撤权检查按受影响路径验证。用户试用时沿两条真实页面路径分别走到列表筛选与详情返回。

该增量涉及新的持久化事实与审批、发布准入。2026-11-17 已作一轮独立方案检查，未发现 BLOCKER。目录操作回执、原选入摘要和保留实例切换已按检查补充，实际验证归入 IMPLEMENTATION_TEST。用户已确认两级单归属、停用后在架处理和现有商品处理。独立检查结论和冻结设计由执行 Issue #1377 追溯。
