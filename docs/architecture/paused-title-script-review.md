# 暂停新启动后的商品标题脚本人工审核

## 产品决定与范围

2026-11-17 用户要求把暂停新启动与撤销审核授权分开，验证原测试账号仍可在暂停后采用真实 OpenAI 的 v2 回执，并验证撤权拒绝。适用范围为已持久化、校验通过的自有商品标题脚本结果，沿现有人工提交、接受、确认采用流程。适用 [脚本架构](skill-script-sandbox.md) 的标题、技能、模式、预算和隔离边界。本补充仅调整原 §5 将 Agent activation 用于这条人工审核链的规则。

## 权限与调用路径

- 企业内容 Agent 的启停和执行代次继续控制新领取、模型派发、脚本执行及其他既有消费者。暂停可在人工审核期间保持有效。启动方的权限校验和执行 fence 保持原合同。
- 人工审核沿 Product Review → 已完成 Run、配置和模式核验 → 原 Skill use gate → Review/Catalog UoW。仅对绑定自有商品、标题单字段、确切脚本策略的已完成 Run，在人工提交、决定和采用时忽略执行启停及执行代次。既有安全门要先确认同一 Run、请求编号、冻结配置、商品来源和执行结果。自动采用继续使用执行门禁。
- 现有身份/成员、审核者对应写权限、当前模式及修订、技能使用权限、准确版本及脚本 profile/descriptor 校验均保留。撤销成员/审核权限、撤销技能版本或该技能使用权、变更原模式，按现有规则拒绝新审核或采用。运行时仍需要已配置且匹配的脚本描述符，沙箱执行入口可处于关闭状态。
- 配置 owner 复用现有快照与模式核验，提供只供这条已完成结果的人工审核使用的窄读取方法。Product Agent 在既有 Review gate 和人工政策校验两处接入。Skill use 的既有事务也读取 Agent activation。本路径仍锁住同一企业 Agent 行和 Skill 记录以保持与个人准入及版本生命周期写入的顺序，唯一变化是在已建立的人工审核内部入口允许该行处于 DISABLED。技能版本、摘要、状态、组织 use、个人技能准入及锁的持有范围继续沿用当前实现。以 Run/提案实际来源判断资格，请求参数不能声明可跳过启动门禁。
- Review 继续持有提案、审核决定与采用回执。Catalog 继续用商品基线版本、事务与现有预约键校验写入并保存新版本。已提交回执沿原编号读回。并发、响应未知、重试和权限检查的事务边界沿原合约。

## 验收

隔离 PostgreSQL 复用既有 HTTP、Review 和 Catalog 路径。先捕获暂停时原结果提交被拒，再覆盖暂停时提交、接受、采用、商品读回，和撤销技能/当前审核权限后的拒绝。验证新键仍被禁止且模型、沙箱未被调用。真实 v2 验证使用原测试身份和原 run、商品与授权事实的最小隔离副本，运行期使用拒绝任何模型及沙箱执行的测试依赖；真实账号认证如使用既有测试身份夹具，标明其边界。35444、35462 及业务实例的运行版本与数据保留。

Legacy decision：N/A。沿现有 owner，沿原 Run、Review 和 Catalog 记录读取历史数据，无新 schema 或迁移。
