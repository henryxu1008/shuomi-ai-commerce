## State, transaction, recovery, boundaries

Each identity remains original owner. Image run/effect locks serialize the terminal fact and its append-only evidence event; Commercial operation lock serializes reserve/finalize and closes late reserve; immutable receipt drives binding; Storage release repeats idempotently. No cross-DB atomic fiction: durable terminal fact + evidence event -> economic receipt -> fact binding -> capacity close, each resumable with same proof/key and no POST. Historical V3/projection remain fenced, with correction evidence appended rather than rewriting prior history. A crash after a terminal fact is durable can be completed by the current GenerationRecovery because the fact schema and terminal digest are unchanged; its old provider_unknown effect still cannot dispatch.
Unknown without proof stays unknown/reserved. Simultaneous success/proof allows one consistent terminal outcome; never overwrite success to refund. Fact/proof conflict fails closed. Repeated reconcile cannot refund twice, change price/member/month, create calls or consume another reservation. A running original slot blocks manual apply.
Historical four operations retain local before/after backups and exact proof receipts; all other success rows, original data/credentials/config/Skill versions and grants must be unchanged. Accepted requests cannot be inferred rejected from an empty dashboard.
