# 硕米 Chat：按当前权限查询店铺概况

状态：独立架构评审两轮及增量复核通过 / **IMPLEMENTATION_READY**；用户已授权实施及隔离验证，须通过下述并发、故障与权限实施测试。设计基线 main `efc007625d02c03739d93d714bedf4e9a71bc880`；#1259，关联 #298、#1257。未授权真实模型调用、原 35444 操作或释放原预留。

## 产品结果与范围

用户在通用业务会话问“我有几个店铺，分别是哪几种”，发送后得到当前企业、当前成员可查看的店铺数量和按平台分类，指向店铺中心。平台类型来自 Store owner；经营类型只在有明确来源时补充，缺失显示未知。用户明确表示只看启用店铺时才按启用过滤。固定项目/店铺背景不得静默扩大到企业：若问题要求全部店铺，明确提示到通用业务会话查询；无权/不确定时不查询。

默认对齐店铺目录无 status 筛选：未软删除记录，包括 active、disabled、deleting；按状态补充分项或提示删除中，避免误解为全在经营。店铺中心当前平台是 SHEIN、TEMU、TikTok Shop、Walmart，分类以 owner 返回为准；上轮示例 Amazon 不代表当前 Store owner 已支持 Amazon。零是成功完整读取到的零；超时/错误/权限拒绝不可解释成零或“企业没有”。不新增店铺编辑、外部平台查询、其他业务问答或让模型直接访问工具。

## 现有事实与缺口

- `internal/storecenter/catalog.go` / `member_access.go`：有效企业和成员授权过滤；管理员可见企业数据，普通成员按 active 店铺 grant 过滤，读取后复核权限和可见集合。`httpapi/module.go` 店铺目录要求 `workbench.store.read`。这两个校验都必须用于新入口，不能以 Chat 权限替代店铺权限。
- 目录 `Total` 是可见过滤结果总数，`Items` 每页最多 100；`facets.ApplicationTypes` 是存在的类型集合而不是按类型统计；`metrics.complete` 是 attention/sync 覆盖，不是经营类型完整。目录信号读取失败或可见项超过 500 时类型可能未知。不能累加多次不一致页面冒充同一快照的总数。
- `internal/integration/aiworkbench/einoplanner/planner.go` 的内容规划器只接收选定商品、禁止工具和决定身份；`aiworkbench.MessageInput` 及 UI 消息发送要求商品选择。会话 `Message.Content` 是普通持久化文本，不能把可撤权店铺统计直接存成永久可见普通回复。现有能力不能直接回答此问题。

## 路由、调用与无模型路径

- 只有用户明确发送才启动。通用会话先按现有 AI 治理、授权、报价、额度、幂等和最终发送门禁调用一个**受管的意图识别调用**；输入只含用户当次问题及明确允许的最少上下文，不含系统查询到的店铺事实或旧的店铺结果。结果严格校验为枚举 `STORE_OVERVIEW` / `PRODUCT_TASK` / `CLARIFY`，只允许 `ALL_NON_DELETED` / `ACTIVE` 受限口径；不从模型接收企业 ID、成员 ID、店铺 ID、SQL、URL 或可执行工具参数。不能用语义正则穷举或第二个模型互验替代判断；不确定必须澄清，不调用 Store。
- `STORE_OVERVIEW` 触发一次服务端受控只读 Store owner 查询，程序渲染确定性结果，不作第二次模型改写或把店铺事实交给模型；`PRODUCT_TASK` 保持商品选择/原规划合同，需用户补充商品后沿原路径执行，不自动创建商品任务。若模型不可用、额度不足或路由结果无效，说明无法识别并提供显式“查看店铺概况”操作；该操作是用户主动选择的确定性查询，不走模型，不以关键词猜测。
- 现有商品规划器和新分类能力不能共用有不同合同的冻结 profile/输入哈希：新增版本化、明确用途的结构化路由 profile，通过现有 `aicapability.GovernedText`、企业已获准凭据/价目/额度和账本 owner 注入；保持现有商品调用不被无关自动重试。当前 35444 不意味着该用途已准入，配置、价格、额度和真实调用需另行核对及授权。

## 店铺 owner 的汇总合同

Store Center 提供窄只读 `VisibleStoreOverview` 应用端口：输入为服务端鉴权的 org、actor、member 与受限状态选项；调用者不得传任意身份或覆盖 grant。实施在 Store owner，复用 member authorizer 和有效 grant，数据库只读一致性快照中对可见、未删除记录统计总数、按平台与状态分项；返回前必须重新验证 org/成员角色和该次可见集合，与现有 Catalog 同一安全约束，不符则整体失败。平台数量之和必须等于总数；不依据单页或异步多页拼出完整统计，不向 Chat 返回 store token、external ID 或完整记录。

经营类型若能复用现有 CatalogSignals 的权威来源，作为带 independent availability/unknown count 的附加投影，不让其失败影响平台总数；不得把 `metrics.complete` 当作类型完整性。若无法证明当前可见集合与类型结果对应或超过现有信号边界，标识类型未确认，不猜。只在用户问题需要、并由服务端授权时读取，不读取订单、库存、授权 token 或跨店资料。失败直接返回明确不可用，不把部分聚合标成完整。

## 会话历史、权限与状态边界

- 由现有 aiworkbench owner 保存用户提问、请求键、限定的查询类型和一条不含店铺事实的结果引用/占位（当前普通 message schema 需要扩展，具体 schema/安装与已有保留库兼容须独立实施方案，不能宣称已支持）；店铺事实 owner 仍是 Store Center。不得将姓名、店铺名、平台计数、供应商原始响应或包含它们的自然语言正文持久化成普通 assistant 消息、模型历史或可脱离权限重放的缓存。
- 首次展示、刷新、读取会话历史、分页、重新打开及同键恢复时，先验证会话当前 actor/org、Chat 访问及 live 店铺权限；通过 Store owner 重新计算**当前**可见结果，界面标明“当前数据”，不能冒充历史当时快照。权限已撤销或成员/企业已变化，清除当前展示，仅显示“当前无权查看/请重新登录”，不显示旧总数、类型、列表或从缓存回显；无店铺读取权不是 0。后续模型上下文也不得包含此前的结果文本。账号切换需隔离页面状态和客户端缓存。
- 回执/幂等身份绑定用户、企业、会话、请求 key、原问题和明确查询类型；相同 key 不同载荷拒绝。模型预留/已发送未知状态沿现有 AI invocation owner 原键恢复，不新建第二次调用；Store 查询为只读，可按当前权限重新计算，重试不创建店铺或业务任务。只读结果可能因授权/数据变化而不同，不能将重算伪称原时点的结果。
- Store 只读失败不把空结果写为成功。任何后续执行沿现有用户确认机制；本功能无平台发布、数据库业务写入、外部店铺变更或预留释放。现有会话保存用户提问及查询引用属于新的可追溯持久化语义，不能未经评审拼入现有 planner 状态。

### 路由命令的最小事务与恢复合同

- 增加 Chat owner 的明确命令类型 `chat_intent_route` 和有类型的 assistant 消息 `STORE_OVERVIEW_REF`；不是把当前必须选商品的 `chat_message_plan` 伪装成该类型。请求由服务端绑定有效 actor/org/member、会话、唯一 key 和原问题；请求指纹只含原问题及用户明确选择的上下文和原始参数，**不含分类结果**。相同 key 相同载荷查原收据；同 key 不同载荷冲突。每个命令固定一个 invocation ID，记录用途、结构化路由 profile 版本、模型输入哈希、预算和截止时间，不能由客户端/模型选择。已有明确商品任务入口继续原路径，不预先触发分类器。
- T0 在 Chat owner 的会话锁及本库事务内原子写用户消息与路由命令（初始待调度）并分配单一 invocation ID；已有成员授权和全局消息限制继续执行。外部 AI 账本/网络调用不得放在此事务内。T0 前的校验失败无命令和用户消息，响应丢失按同 key 查询。
- 调度时，使用固定 invocation ID 和精确输入调用既有受管 AI owner 的报价、预算预留、发送前复核及结算；重试只查询/复用该 owner 原调用收据和账本事实。尚未发送且 owner 明确允许原键继续时可继续；已发送且结果 UNKNOWN 保留原键并展示待核对，不创建新 invocation、不二次预留、不自行判未计费或释放。路由结果只有格式合法、内容属于枚举且 owner 返回完成收据才进入 T1；失败或不确定分别呈现失败/待核对，不查询 Store。显式店铺概况快捷入口不调用 AI，其独立 key 命令可以直接进入本库 T1，零模型调用与零 AI 点。
- T1 Chat owner 在同一会话事务以相同命令 key 原子提交分类终态和一个安全的 assistant 结果引用：`STORE_OVERVIEW_REF` 仅保存受限状态口径、来源 user message ID、序号和无店铺事实的标记；成功不持久化总数或类型。并发/重复 T1 查原完成回执且不再追加消息。`CLARIFY` 只能追加固定安全澄清，`PRODUCT_TASK` 只提示用户选商品并继续现有有商品的规划路径；不把店铺查询结果作为后者输入。不同命令的序号沿现有 Chat 会话事务分配。生成真实商品方案仍需该用户下一步显式操作并按原模型准入执行。
- T0 后崩溃/重启、T1 前丢响应、并发重试、T1 后丢响应，均以原命令和 AI owner 原收据恢复，不新造 invocation。Store 只在投影/重读时实时只读查询，失败产生可重试的展示状态而不是把结果或错误冻结为永久事实。任何原 AI invocation 的失败/UNKNOWN 处理和点数预留仍由现有账本 owner 负责；本方案不新增释放接口。
- 特别处理“AI 已成功结算、Chat 尚未提交 T1 后进程丢失”窗口：现有 AI invocation 只持久化输出摘要和用量，不保存分类文本；因此原收据不能还原分类枚举。恢复时检查原 AI owner 的终态与 Chat 命令：若已结算但分类尚未持久化且进程内结果已丢失，Chat 原命令以 `ROUTING_RESULT_LOST` 原子终结，显示“识别结果未能保存”，保留原账本结算，不重复识别、不再次预留/扣点，也不推断分类或自动查询 Store。用户可明确点击独立 key 的“查看店铺概况”走零模型查询；若需再次自然语言识别须由用户明确发起新请求并重新报价。原收据 UNKNOWN 时维持 UNKNOWN，不误判为结果已丢失或释放预留。只有 T1 已提交分类结果时，同键恢复才回放原类型化引用。不得假设 AI owner 能重放输出内容；若未来要求自动找回完整分类结果，须另行设计持久化和评审。
- 并发同键重试不得仅凭“AI 已结算且 T1 未提交”判定结果丢失。实施核查确认当前 `CompletePlan` 的 `WithoutCancel` 写入不校验截止时间，因此现有调用超时不能证明原处理者失去提交资格；必须给**新路由命令**增加明确的数据库终态提交栅栏，而不是复用现有 context 截止作为证明。T0 在数据库时钟下固定模型调用截止 `model_deadline` 及 `commit_deadline = model_deadline + 30s`（与当前规划恢复宽限一致），均随命令持久化、同键不可延长；模型已结算但 commit_deadline 尚未过时保持处理中。T1 和 `ROUTING_RESULT_LOST` 均锁同一命令行，在锁持有时用数据库实时钟判断：T1 仅可在 `now <= commit_deadline` 且非终态时提交；LOST 仅在 `now > commit_deadline`、原 AI owner 明确成功结算且命令尚未终结时提交。二者互斥且最多一个终态，迟到 T1 不得覆盖 LOST 或再追加。此栅栏证明的是旧处理者不再能提交，而不是进程已经死亡；用户提示应为“识别结果未在期限内保存”。UNKNOWN 不可判 LOST。隔离测试须覆盖锁等待跨过截止、数据库时钟边界、原处理者暂停后恢复和 T1/LOST 并发，不能以客户端超时作为证明。

### 查询引用的输出合同

- aiworkbench `Message` 增加受约束类型字段（普通文本或 `STORE_OVERVIEW_REF`）及仅包含口径的受限引用，引用仅由服务端创建，不信任用户提交的标记；Store owner 不拥有或复制 Chat 消息。所有会话读取入口和分页调用同一投影器：在检验会话 owner 与当前身份后识别该类型，单独调用服务端 store overview 端口；成功才返回独立的临时结构化 `currentStoreOverview`，并带数据时间与当前口径。普通 `Content` 对此消息只含固定中性标签，前端不从普通文本中解析店铺事实。读取权限拒绝/数据不可用只返回明确状态，不返回历史数值；不得因单条查询失败掩盖其他普通消息。
- `HistoryForCommand` 及任何模型 history / 导出 / 搜索只能看到中性引用或在本轮显式排除引用，绝不能回填临时投影的店铺事实为 assistant 内容；用户自己输入的文字不作虚假清洗承诺。接口响应 `no-store`；客户端缓存按 actor/org/会话键隔离，切换身份或收到权限失败时立即丢弃旧投影和旧请求响应，刷新、重新进入或页面重新获得焦点先隐藏并重新授权读取。未有撤权推送时，页面停留期间无法承诺瞬时撤权，展示结果标注读取时点；任何重新读取都不得显示旧结果充当当前值。
- schema 为当前 Chat owner 的正式类型化合同：字段约束保证引用与普通文本互斥、禁止把数值编码到中性标记，安装和权限入口由原 Chat owner 管理；原有已保存普通会话必须保持可读。现有保留库如何启用新结构须另行明确用户授权及单独验证；本设计不授权迁移、修改原库或改变既有角色权限。
