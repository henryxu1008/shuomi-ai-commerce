# 硕米「模型与服务」设计

2026-11-17 · 用户已认可首版范围，独立评审及修订复核已完成。首版采用 `Reuse Existing Architecture`，执行见 [#1397](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1397)。未来新增调用、持久化事实或跨系统边界的切片各自完成 `Independent Architecture` 准入。

企业管理员从「我的账户 → 企业空间 → 模型与服务」进入，查看 Chat 规划的企业侧状态，以及图片分析和生成各自的模型配置。页面按当前权限指向处理入口，提交后重新读取状态。业务成员在原工作页查看与当前操作相关的条件。首版交付这条配置路径，嵌入、搜索和后台任务模型随各自首个真实业务场景接入。

DeepTutor 的「提供方 → 模型 → 用途 → 运行状态」值得借鉴。它把嵌入单列给知识库，将图片与视频生成分开，在搜索设置中区分找网页和读网页，并允许后台任务继承默认模型。硕米采用同样的分工，由企业统一维护模型和已登记渠道，由业务页决定能使用哪些来源、何时运行及如何确认。依据为 2026-11-17 用户要求先设计，以及当前账户导航、企业统一模型、共享渠道和模型准入决定。[账户导航](../../../product/final-ui-ia-authority.md) · [企业模型](../../enterprise-shared-model-configuration.md) · [渠道 Key](../../channel-credentials-ui.md) · [模型准入](../../eino-model-admission.md)

## 页面与操作

当前「模型与费率」卡片在企业空间内更名为「模型与服务」，复用现有 `/workbench/account/organization/model-route-pricing`。面包屑返回企业空间，侧栏仍选中企业空间。当前企业和用户身份确认后，具备任一项现有相关权限即显示卡片。进入后，按权限独立加载对应区域。某一区域的服务未启用、列表为空、当前只读或读取失败时，在该区域说明原因和下一步，其他有权区域仍可进入。平台价目区明确标为平台共用，只有平台权限的账号直接进入该区域。[账户导航决定](../../../product/final-ui-ia-authority.md) · [当前页面与路由](../../../../web/listingkit-ui/src/components/workbench/account/model-route-pricing.tsx)

```text
我的账户 / 企业空间 / 模型与服务
当前企业  某企业

使用概览                       示例状态                   示例操作
硕米 Chat · 规划业务任务       尚未发布企业文本模型       去选模型
图片分析模型                   模型配置符合条件           查看模型
图片生成模型                   缺少适用参考价             查看原因

按权限可进入                   企业模型 | 提供方与 Key | 参考价格与汇率
```

每行展示用途、已发布的模型和提供方、当前状态、简明原因及一个主要操作。实际需要人工处理的行排前。首次配置时在当前卡片说明「选定使用的渠道和模型 → 补齐缺项 → 确认发布」，管理员也可以从提供方直接开始。尚未提交的选择只出现在当前编辑会话，首页读取已发布版本。窄屏改为纵向排列，状态有文字，按钮和链接可用键盘到达。回到概览时焦点回到原用途或其状态标题。

1. **从概览定位缺项。** `/enterprise` 明确显示尚未发布时，可进入企业模型区域并定位文本模型。用途的现有资格数据指向凭据问题时，按权限引导查看渠道配置。业务页使用固定用途和原业务页面标识打开同一设置区域，有设置权限时才给跳转入口。回到原业务页面后按原权限读取当前对象。
2. **处理提供方。** 选已有连接，首次录入填写账号备注和 Key，核对受影响的可见模型，保存后显示「Key 已保存」及回执。成功读取当前企业的获权连接列表后，只有按**模型类别、引用 ID 和版本**在已登记连接中得到唯一匹配，才定位该连接，并由用户打开编辑。其余情况打开列表。列表为空显示「当前企业暂无已登记渠道，请联系系统维护人员」。`canManage=false` 时可看去密状态，解释此环境暂不能保存。短暂读取失败提供重读入口。Key 不通过跨页状态转交。[当前模型与连接响应](../../../../web/listingkit-ui/src/lib/contracts/model-route-pricing.ts) · [连接列表合同](../../../../web/listingkit-ui/src/lib/contracts/channel-credentials.ts) · [凭据管理接口](../../../../internal/app/httpapi/channel_credentials_module.go)
3. **选择模型并检查。** 复用现有企业共用模型表单和候选，确认的是三类具体选择。区分「已有可选型号，但未达到执行条件」与「这类没有当前可发布的候选」。三类引用都必须在现有候选内，原版本失效要先重新选择，正式发布仍由当前接口复查。图片候选尚未具备运行条件可按原规则保存，实际执行独立判断。改变选择、保存 Key、刷新发现配置版本变化或离开后再回到编辑区，均需要重新检查当前选择。企业当前配置和候选是编辑所需数据，历史读取失败只影响历史区。[企业配置合同](../../enterprise-shared-model-configuration.md) · [当前发布条件](../../../../internal/aicapability/routeconfig/shared.go)
4. **确认结果并返回。** 模型发布、Key 变更、参考价发布或核实这些变更的成功回执后，立即在原身份和企业下重新读取受影响且有权限的区域。模型配置读取 `/enterprise`，编辑时更新候选。持有相应权限时重新读取受影响的连接或价目。Chat 状态主动刷新原工作台上下文，回到业务页时重新读取对应业务状态。重新读取期间使用「正在检查」，失败时保留保存回执并显示「本次已保存，当前状态暂时无法确认」。并发冲突时提示重新读取并检查，中断时按原请求编号核实。同一个设置页在区域切换时保留未提交的模型选项和原编辑版本，切企业、退出或权限变化时清除。离开 Key 表单即清空 Key 输入。已提交而待核实的请求按原隔离规则保留，回到原企业且仍有权限时才展示查询入口。[现有工作台上下文](../../../../web/listingkit-ui/src/components/providers/workbench-context-provider.tsx)

| 页面状态 | 判定与下一步 |
| --- | --- |
| 尚未发布 | `/enterprise` 成功返回 `UNCONFIGURED`。已获企业模型配置权限者「去选模型」。 |
| 已配置，待处理 | 现有资格数据返回明确阻碍时显示该原因，例如「缺少适用参考价」。只有获权的准确连接明确缺 Key 时，才显示「渠道 Key 尚未保存」。凭据资格错误也可能是停用、版本或连接条件不符，原因不明确时显示「渠道暂不可用，请核对渠道配置」。 |
| 企业已具备 Chat 规划条件 | 当前企业已开放 Chat，且原工作台状态为 `AVAILABLE`。实际任务仍在业务入口核对个人权限、资料和预算。 |
| 模型配置符合条件 | 仅用于两个图片模型行。当前已发布版本的该类别资格为 `ready=true`。商品页分别检查素材、模板和实际使用资格。 |
| 当前未开放或暂不可用 | 明确知道当前企业未开放 Chat 时显示未开放。原状态只表示不可用时显示「Chat 规划暂不可用」，没有可归因的缺项时提供重读或联系维护。读取失败显示「暂时无法确认」。 |
| 正在读取或结果待核实 | 读取中暂停基于旧状态的操作。已提交命令按原回执核实，保留当前企业及请求编号。 |

**Chat** 使用同一次成功读取得到的 `aiWorkbenchAvailable` 和 `aiWorkbenchPlanningReadiness`。前者确认当前企业是否开放，后者结合规划和对应执行路径。`NEEDS_CONFIGURATION` 只说明需要检查配置，配置事实能够确认缺项时才补充原因。`UNAVAILABLE` 还可能来自依赖或未装配，单独这一值不足以判断企业关闭了 Chat。实际使用 `workbench.chat.use` 等权限由业务入口核对。模型行展示的是已发布企业文本选择，不能用模型候选资格覆盖 Chat 的真实状态，也不从 Chat 的汇总值推导精确 Key 或参考价缺项。[工作台上下文返回](../../../../internal/workbenchcontext/httpapi/handler.go) · [Chat 规划状态](../../../../internal/app/httpapi/ai_workbench_routes.go) · [Chat 页面权限](../../../../web/listingkit-ui/src/components/workbench/ai-workbench/chat-page.tsx)

**图片** 在设置页固定采用配置层口径。两个类别分别读取已发布 `/enterprise.preview.models` 中的 `multimodal` 和 `image-generation`。逐类资格来自同一次成功读取，聚合状态 `NEEDS_CONFIGURATION` 不覆盖某个已合格的类别。已发布默认渠道失去资格，或资格依赖发生错误时，整个 `/enterprise` 可能读取失败。此时图片行显示暂时无法确认，无法正常重读时引导联系维护人员。候选默认值和历史版本只用于编辑，不能补作当前状态。独立的工作台上下文仍可显示可确认的 Chat 状态。图片分析和生成的业务接口需要实际商品、来源和业务授权，设置页只读取企业模型接口。每个类别展示当前已知原因，解决后重读才能确认是否还有其他缺项。[当前配置与三类资格读回](../../../../internal/aicapability/routeconfig/shared.go) · [模型资格字段](../../../../web/listingkit-ui/src/lib/contracts/model-route-pricing.ts) · [图片分析业务入口](../../../../internal/app/httpapi/image_analysis_routes.go) · [图片生成业务入口](../../../../internal/app/httpapi/image_set_module.go)

## 后续接入设计

每个后续切片从一个能验收的业务用途开始。业务 owner 先给出用途、资料范围、现有权限和可复用依赖，再由对应的服务 owner 提供准确的可用状态与配置入口。新增外部调用、费用、使用授权或持久化状态时，按该切片完成独立设计和评审。接入顺序以实际业务阻碍为准。

### 知识库嵌入与检索

第一个场景建议为「从当前企业指定知识库找到相关商品规则段落并查看出处」。从知识库进入「配置检索」，在已准入的渠道与嵌入模型中选择。系统从可信模型元数据取得维度，配置时说明会发送的资料及预计索引范围。首次跑通文档选定、建立索引、检索、返回引文四步；页面分别显示配置状态和资料可检索状态。研究阶段先比较现有关键词、结构化检索对这批文档的效果，确认语义召回确有价值后再选成熟向量检索组件。

知识库 owner 管理文档版本、索引世代和可查询范围，AI owner 管理嵌入模型与调用。查询与文档向量使用同一已启用版本，切换型号或维度须显式重建并在完成后切换，失败时保留仍获准的可用索引并说明进度。新版本准备不能延长旧资料授权。索引任务以企业、知识库、原文版本和索引世代绑定，限制文档批次、输入量和费用；撤权和删除在提供给用户或模型前再查。外部发送、费用、失败补做和删除传播在该切片落到现有 owner 与可验证的协议。[知识上下文与后续检索](../../agent-knowledge-context.md)

### 图片生成、图片分析与后续视频

「分析商品图片」消费有权读取的原图，结果沿原分析与审核；「生成商品图片」沿现有模板、素材、费用确认和产物保存。两个入口分别定位自己的模型。若日后确有「用已批准商品素材生成一段短视频」需求，先限定一种生成方式和一个已准入模型，确认原素材可发送范围、时长、异步费用与结果领取，再决定增加「生成商品视频」行。供应商已接受但结果中断时用原意图查询，重复提交、外部存储、下载与失败费用按该业务另立合同。[商品图片分析](../../product-image-visual-analysis.md) · [图片生成与恢复](../../image-agent-workflow.md)

### 搜索与网页读取

建议从已明确的 SHEIN 美国市场研究方向选定第一个可合规获取的来源。区分「按条件发现商品」和「读取选中商品详情」，可以由同一服务承担，但分别记录可用性、受限范围和失败原因。研究人员从原调研流程看到来源、地区、费用和资料用途，确认后取数，原证据保留页面、时间、取得方式和缺项，研究结果引用该证据。已有 ZenRows 仅是有界试用路径，正式接入依赖具体供应商的覆盖、许可、费用和失败处理。适用时优先复用 Data Services 和现有采集/查原请求能力，在发出付费请求前绑定来源范围与预算；结果未知按原操作核对。Chat 是否能通用联网属于新的业务场景，需另外定义可发送输入和可读取来源。[多来源市场调研](../../../product/market-research-multi-source-plan.md) · [来源服务生命周期](../../data-services-execution-lifecycle.md)

### 后台任务模型

建议先评估「自动为 Chat 会话命名」。若交付此用途，现有手动改名优先，后台任务只写仍符合原前置条件的标题，模型不可用时保留用户继续使用会话的路径。业务 owner 决定触发第一次命名的时点、输入范围、明确的运行身份和次数，通过原 AI 准入与账本调用。用会话与触发版本约束重复执行，并校验会话仍属于原范围、标题未被手工改过。输入或授权变化需要重新核对。费用应归到明确的企业及消费用途，结果不明走原调用核实。

有独立调配需求后，模型选择顺序建议为「任务单独指定 → 企业后台默认 → 企业文本默认」。这条规则只解析未设置的选择。明确指定的模型当前不可用时应如实显示原因，当前任务按其自身失败处理。管理页显示实际继承来源、模型以及影响的任务。店铺经营日报由已保存数据生成，继续在定时任务流程判断权限和数据覆盖。商品标题优化或其他用户确认的工作按原用途管理预算和模型。[会话现有操作](../../../../web/listingkit-ui/src/components/workbench/ai-workbench/chat-page.tsx) · [店铺日报](../../scheduled-store-daily-report.md)
