# 企业自有 GRSai 渠道生成单张商品主图

状态：`IMPLEMENTATION_READY`，2026-11-24 已完成两轮独立架构复核，最终无阻塞项。执行 Issue [#1628](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1628)。基线 `bd4483af950c062c4aea10626e723002cce1655b`。

## 用户结果与范围

2026-11-24 用户确认使用企业自己的 GRSai 账户，生成一张商品主图。企业直接向 GRSai 付费，硕米只记录能核实的用量。企业渠道管理人从现有「模型与服务」登记专用渠道。商品编辑者在已选真实原图的商品图片流程中选择该渠道，确认一次生成，检查候选并人工保存正式素材。

首版仅允许一件自有商品、一张参考图、一次生成请求和一张 `product_identity` 主图。固定采用 GRSai 全球节点的 GPT Image 统一接口，型号 `gpt-image-2.6`，`1024x1024` 和 `auto`。该准确型号和参数来自新版官方接口示例。旧 GRSAI VIP 路由和平台生图收费路径独立沿原合同运行。场景图、详情图、多图、POD 图案、通用代理、自动换渠道、商品上传、正式试用和真实付费验证不在本批。复用现有渠道管理与商品图片界面，沿 [UI 交付权威](../../../product/final-ui-ia-authority.md) 保留原导航、素材预览及审核入口。

## 供应商证据

- [GRSai GPT Image 统一接口](https://qmy27nhsd9.apifox.cn/452409160e0) 的请求定义支持 base64 参考图、`gpt-image-2.6` 的 `1024x1024`、PNG 及 `replyType: async`；异步受理返回任务 ID 和状态。使用异步模式，以便先保存原任务号再读取结果。同步成功示例有 `usage.credits`，不借该示例推定异步查询返回相同字段。
- [GRSai 原任务查询](https://qmy27nhsd9.apifox.cn/452409577e0) 定义按供应商任务 ID 查询、终态、结果列表和约两小时的终态查询窗口，响应没有供应商积分字段。工作台记录成功终态中可核实的实际出图数，供应商扣款及积分不作推算。文档没有调用方幂等键，也没有按内部操作号查询的合同。查询不到不能证明未生成。
- 现有 `internal/integration/grsai` 的旧接法仅有历史适配证据。用经过原来源检查的 JPEG/PNG 字节构造 base64 参考图。真实参考图、受理、结果以及失效行为按另行授权验证，不临时公开本机原图。隔离替身以新版接口结构验证。

## 授权、计量与持久化

服务器从现有登录上下文和登记读回企业归属。使用原 `app/listing` 图片来源 reader 已读取的权威 `source.Source.Kind`，仅允许 `own` 和 `Target.Platform=product`。将该来源种类作为可选的服务端绑定值冻结。准备、确认、最终派发和发出核实查询前均重新读取实际来源，验证种类、版本、企业、成员、原图哈希和准确凭据。`ContextKind=supply` 或浏览器参数不证明来源是自有商品。凭据关闭、轮换或版本变化使尚未派发的计划失效，已经记录的原结果仍按原事实读取。传输不允许任意 endpoint、浏览器密钥、平台凭据回退或借当前默认替换已冻结渠道。仅发送生成所需的单张原图与原商品任务提示，保留原图片源内容的输入边界。

在原计划、准入快照和 effect 的可向后解码 JSON 中显式标记 `usage_only`，仅允许上述确定用途、供应商、模型和协议。保留一张图、一次模型调用和原来源／字节／时限约束。原点数路径继续要求正额度和价目。这个特例的点数为零，完全跳过 `orgresource` 的点数预留、扣减和结算，存储容量仍按原合同计量。原已付费/已结算状态保持真实。禁止以零价目或伪造收据通过平台账本。ImageAgent 原 effect 作唯一调用事实并绑定原结果，原图片任务详情显示核实的用量。

已有 effect 行、锁及唯一身份沿用。仅可增加该模式需要的可省略事实字段或兼容版本，旧事实序列化／指纹／回执不得被重新计算。新登记模板使用原 Run DB owner 显式安装入口扩充现有模板 CHECK，验证既有两种模板并保留已有登记、读写角色及事务。启动只验证，默认关闭此能力，API 与 worker 同版本装配就绪后才允许使用。不得新增第二套记录、出站 worker 或计费表。

该模式的技术成功由原 GenerationFact 持有的原任务 ID、明确成功状态、一张输出和结果摘要证明。从 fact 到 slot closure、候选投影和 Asset owner verifier 传递明确的 `provider_usage` 证明分支。审核保存必须重新读取同一企业、来源、slot 和 attempt 的有效 terminal digest，确认物化资产哈希与原候选一致。该分支独立于 `ai-micropoint-v1` 结算证明，并为成功输出、无效输出和确定无生成分别收束原存储预留。沿原已付费结果的 closure、资产证明、结算字段和摘要算法保留旧路径。不得借一个伪造的已结算回执晋升素材，也不得把旧结算证明用于此分支。

## 派发、核实与用户反馈

1. 准备冻结单张主图计划并预览原图，明确会将参考图发往所选 GRSai 企业渠道、将使用供应商额度。确认复用原动作键；双击、并发和重启通过原 slot 事实持久 claim，至多一个 POST。
2. POST 受理返回有界供应商 ID 后，在脱离外部请求取消且有明确短时限的上下文中，加锁持久化原已 claim 的 effect 行，固定原任务号、已冻结的渠道 ID／凭据版本和受理时间。此写入成功前不得 GET 或出具终态。重复相同受理证明幂等，其他任务号冲突。正常 worker 可在原计划期限内查询同一 ID，单次 GET 最长 5 秒、间隔至少 5 秒、最多 12 次。成功回执要求 ID 精确匹配、明确成功、恰好一张图片及可校验结果定位。记录实际确认的图片数量，候选仍须通过原媒体验证。若供应商确认了结果但输出不可用，保留确认的图片数量和原始结果证据。迟到的进行中结果不能覆盖已证明终态。
3. 出站前确定失败按原无发送状态记录。出站后超时、响应丢失、格式不符或本地提交回执丢失，按原操作核实，不能再次发 POST。已持久化任务 ID 时，现有 ImageAgent `RecoverEffectV3` 在恢复身份且通过当前企业、成员、来源、slot 和原效果校验后，使用同一冻结且仍有效的凭据版本为本次显式核实发一次最长 5 秒的 `GET`。原身份恢复前的本地 reconciler 保持无供应商网络访问。恢复操作不延长生成授权，只读取供应商。`failed` 或 `violation` 须来自合格的同号明确终态，显示生成失败并关闭无输出状态，不推断扣款。自受理起最多两小时内核实，以供应商实际可查询性为准。凭据撤销、401、404、无 ID 或证据互相矛盾均保留待核实。已确认终态的取图恢复使用既有定位，和继续派发隔离。
4. 人工「采用并保存」沿原候选摘要、选择回执和企业权限。工作台的耗用单位写为「GRSai 用量」，确认无硕米点数。原点数界面和跨企业不可见性保持。

## 校验与真实开放

- TDD 覆盖租户和权限、固定 endpoint／型号、单参考图／单主图限制、报价不发请求、授权和凭据失效、重复确认／恢复至多一次 POST、单张成功和供应商用量持久化、缺用量、非法响应、无任务号或原任务查询失效、物化失败与重读。
- 凭据登记和计划准备不依赖平台点数余额或已发布默认模型。对供应商明确失败的原任务保留受理和终态证据，与发出前无效果区分。原已付费路径的摘要和 JSON 字节仍按现有规则验证。
- 隔离 PostgreSQL 和模拟 HTTPS 供应商核对「登记 → 选用 → 确认 → 出图 → 人工批准」以及无硕米点数预留/扣减。复用现有 image worker、source guard、artifact 和配置权限测试。测试资料不取用户真实图片。实际原图发送、付款主体、预算和真实 endpoint 结果由用户另行授权。此切片不改变开发店商品或生产试用实例。
