# 企业自助添加渠道与模型绑定

2026-11-18 · Design Basis **Independent Architecture**。状态 **IMPLEMENTATION_READY**，已完成两轮独立评审，设计基线冻结。用户已授权 [#1426](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1426) 实施、隔离验证及提交 PR。调查基线为主分支 `e53866390eb9c9d1e3cd05c3999d0eb663ae718b`。真实配置、Key、调用和试用实例操作各有独立阶段授权。

## 用户结果与本轮范围

企业配置人员从「我的账户 → 企业空间 → 模型与服务 → 提供方与 Key」添加自己的渠道，安全保存一份 Key，关联支持的模型，在「企业模型」选择并发布后供已有业务使用。同一提供方支持多个账号或地址，模型选择明确到具体渠道。交付的一条核心路径为「新增渠道和 Key → 关联文本模型 → 发布企业文本选择 → 硕米 Chat 按原权限和预算使用该选择」。

2026-11-18 用户指出 DeepTutor 能添加新渠道，并同意按本切片做独立设计及评审。这个新决定扩展先前“仅管理服务器已登记连接”的阶段范围。[首版设计](model-and-services.md) · [原渠道界面合同](../../channel-credentials-ui.md) · [共享凭据合同](../../shared-channel-credentials.md) · [企业模型合同](../../enterprise-shared-model-configuration.md)

本机 DeepTutor Web v1.7.3 的只读查看已确认，提供方列表有「添加提供方」，可选内置服务或「自定义」，自定义先填名称与地址，再填写凭据并选择接口协议；具体模型在各类模型页面管理。硕米借鉴提供方和模型分开的关系，以及空列表可直接开始配置的流程。此次未保存或测试 DeepTutor 配置。[本机参考入口](http://localhost:3782/settings/connections)

首轮新建绑定只开放文本，准确型号首个采用当前的 `gpt-5.4-mini-2026-03-17`。后续型号须有平台受控模板、已实现用量映射及对应用途，才进入可添加目录。用户可选支持的模型，未列型号显示“此型号暂未支持”。原已有图片/多模态配置仍由各自当前定义消费。

## 当前代码与需要解决的架构问题

| `Catalog.definitions` 是进程内映射，消费者模板还来自已部署的 operation anchors。 | 在同一 `routeconfig` owner 增加登记绑定读取，配置与正常调用消费同一个有版本目录；业务用途和资源上限仍由原已装配消费者决定。 |

现有目录由服务器提供连接、数据库保存凭据，两者通过精确匹配工作。自助登记需要把新连接的登记事实接入同一权威目录。只放开网页 Base URL 或仅增加按钮，会导致“页面保存成功，但运行目录找不到连接”的断链。[连接列表装配](../../../../internal/app/runtime/currentapplication/channel_management.go) · [Key 命令](../../../../internal/aicapability/channelcredential/management.go) · [模型目录](../../../../internal/integration/aicapability/routeconfig/catalog.go) · [实际策略读取](../../../../internal/integration/aicapability/routeconfig/shared_catalog.go)

## 页面流程与用户用语

沿现有设置页、配置区域切换、AccountDialog、同源 BFF 和发布回执流程。渠道列表承担选择与状态查看，创建使用有明确返回位置的表单。接口依赖形成两个操作阶段，第一阶段只需保存渠道与 Key；成功后再关联模型。用户可以在第一阶段完成后退出，列表显示“已保存，尚未关联模型”。

1. **添加渠道。** 空列表和现有列表均有「添加渠道」。填写渠道名称，选择「OpenAI 官方」或「OpenAI-compatible」。官方地址固定展示；兼容渠道由用户填写 HTTPS 服务基础地址。提供方、协议、接口路径及认证方式由模板决定。输入 API Key，页面告知将来业务使用时会发到哪个域名。保存前无厂商请求。
2. **保存结果。** 成功返回同一渠道详情，显示“Key 已保存”和“尚未检查”。账号备注仅是标签。保存失败显示可修正原因；只要请求已发出，Key 输入清空。回复丢失时用原操作编号核实结果，查不到回执仍显示待核实。取消返回原列表和焦点，未发送的 Key 清空。
3. **关联模型。** 在渠道详情选择支持的文本型号，显示准确型号、用途范围、协议适配情况与参考价缺项。名称是用户识别标签；准确型号和受控模板由支持目录选择。保存为当前企业的独立模型引用，在不同渠道的同型号不会合并。
4. **选用并发布。** 「去选用模型」带当前企业和准确引用回到现有企业模型表单，定位文本字段。页面显示“渠道名称 · 型号”。原三类选择的完整快照与检查/发布继续使用当前接口。已有图片和多模态选择保留；首次配置时未开放的类别沿原明确未就绪候选处理。不得要求先配置无关生图服务才能发布有效文本选择。
5. **返回。** 发布并回读后可返回使用概览或原业务页；详情「返回渠道列表」恢复选中项，模型字段返回详情可查看同一连接。切企业、退出或授权变化清空未提交编辑和临时检查，已发请求只保留去密核实引用。
6. **运行条件。** 显示“Key 已保存”“尚未关联模型”“缺少适用参考价”“已停用”等可证实状态。查询结果单列并注明时间，成功仍写“模型调用权限未验证”。本轮 OpenAI-compatible 显示“此渠道暂不支持资料查询”，没有以生成请求代做免费查询的入口。

Key 写入服务和登记服务缺失时，列表能显示当前状态，新增/保存处明确写“当前环境暂不能保存渠道，请联系维护人员”。上线到试用实例前须配置实际受限 writer 和保护材料；有权限但写入装配不可用不能作为此切片的成功验收。

## 模板、地址与型号边界

| 模板 | 提供方和地址 | 首轮可关联模型 | 查询与正常消费 |
| --- | --- | --- | --- |
| OpenAI 官方 | `openai`、`openai-direct`，固定 `https://api.openai.com/v1`。用户只填名称与 Key。 | 准确 Mini 文本型号，当前已开放的 Chat 规划及内容用途。 | 复用 #1423 官方固定单型号只读查询；正常调用沿原 Mini 文本策略。 |
| OpenAI-compatible | 明确显示为兼容服务，服务基础地址由用户填公网 HTTPS；独立渠道类型 `openai-compatible`。 | 同一准确 Mini 型号，受控兼容文本模板固定 Chat Completions、结构输出及用量映射。 | 沿 Eino/OpenAI SDK 与受控单次传输；无免费兼容探测。参考估算须适配这个模板和渠道类型。 |

企业输入不能指定厂商认证请求头、项目号、价格、usage mapper、operation、预算、日志开关或 adapter policy。平台支持目录是代码发布的模板，不在本切片建设模板编辑后台。模板组合清楚记录 `id/version`、协议、准确 wire model、制造商参考型号、可用 operation、输入输出上限、deadline、响应模型校验及用量映射。两种受控渠道均可先保存 Key。关联和发布按当前企业已开启的文本用途判断，保留受授权计划约束的原官方标题试点策略。兼容渠道无法覆盖已开启的用途时，详情说明暂不能关联，保留已保存的渠道。

兼容服务按其选定模板核对响应型号和用量；不通过去除型号前缀、猜测别名或自动降级接受不同模型。参考价格仍由原平台 owner 维护，匹配当前兼容渠道类型、准确参考型号及计量策略；缺价或 FX 时可保存登记、无法执行并显示缺项。已有官方价不能仅因同型号就自动套用到任意渠道。本轮不改变点数比例、舍入、预留或结算规则。

## 权限与外部发送

| 操作 | 需要的现有或新增权限 |
| --- | --- |
| 查看或管理新增渠道的名称、登记与停用状态 | 新增「管理模型渠道」`workbench.ai.channels.manage`，经现有企业角色模块显式授予。 |
| 创建并保存 Key、轮换或停用含 Key 的连接 | 「管理模型渠道」与原「渠道凭据管理」；首次创建两项同时检查。 |
| 关联/取消关联文本模型 | 「管理模型渠道」与原 `workbench.agent.configure`；企业发布继续核原模型配置权。 |
| 官方模型资料查询 | 原「渠道凭据管理」与「测试渠道模型」；目标来自准确可信绑定。 |
| 普通业务使用 | 原业务权限、企业选择、准入、资料和费用预算逐次核对。 |

新管理模块不自动授予管理员或平台维护者。只增加渠道管理权不获得 Key 写入、平台定价或业务执行。Key 权限者仍按原合同查看已有连接与模型的去密信息。本切片不会把资料查询成功写成可执行。

浏览器经同源显式命令提交，expected 用户/企业/成员仅用于检测上下文漂移。后端从 live 身份和企业授权推导真实 scope，记录 actor。提交、Key 解析、实际网络交接和返回查询结果分别沿现有门禁核对。暂停企业、成员撤权、角色模块撤回或依赖读取不确定时拒绝新操作。企业 A 的模板授权、连接、绑定及回执无法从企业 B 访问。

## 唯一事实所有权和数据库边界

| 事实 | 唯一 owner 和存储 |
| --- | --- |
| 连接身份、基础地址、厂商、地区、启用状态、Key 与 credential revision/reference | 原 `channelcredential` / Run DB `ai_channel_connections`，继续使用原加密和去密视图。 |
| 企业登记标签、模板引用、登记版本 | 同一 `channelcredential` owner 的最小登记表 `ai_channel_registrations`；以企业+connection ID 外键指向原连接，不另存 endpoint、Key 或调用状态。 |
| 渠道内的准确型号与用途引用、绑定版本和停用 | 原 `routeconfig` owner 的 `ai_enterprise_model_bindings` 及原版本化命令回执模式；同一个 Run DB。 |
| 企业发布选择、参考价与 FX | 原共享模型与平台价格 owner。 |
| 调用、预算、UNKNOWN 和历史恢复 | 原 Invocation、orgresource 及业务运行 owner。 |

连接保存必须在一个原数据库事务中同时写原连接、登记元数据和去密回执。复用原 Store 的锁、CAS、HMAC、AES-GCM 与事务逻辑，提取事务内写入能力供同一事务调用；不能先调用已自行 Commit 的 Publish 再写登记表。命令回执仍落原 `ai_channel_connection_receipts`，按命令类型区分严谨结果 DTO，不另建待确认平台。

模型绑定不含秘密，关联时在同库事务里锁准确定义与连接、核对当前启用状态、模板版本及 credential revision 后创建不可变引用和回执。绑定保存不发布企业选择。停止关联通过原 owner 标记其停止接受新选择与执行，历史引用保留。

登记表只保存登记元数据。将其列出来后从原 metadata view 批量取去密连接状态，并由绑定 owner 提供“使用此渠道的模型”投影。禁止通过 `SecretReader` 列表或向 BFF 注入它。普通 reader、登记 writer、Key writer 和调用 secret-reader 沿原分池和最小 DB 权限验证装配；新表只赋需要的列/操作，runtime 不获 schema 初始化或所有权。

## 当前部署定义与新登记定义

当前可信部署定义继续拥有原来的引用；自助登记创建新的连接与引用。两者共属当前 routeconfig 目录，通过明确命名空间查询，任何一个引用只由一个来源负责。

- 新连接 ID 由服务端从固定命名空间、命令种类、live 企业、actor 与原 requestKey 稳定派生为 `uc-` UUID；同一创建请求重放不会生成另一个 ID，客户端不能指定或冒用部署引用。新模型引用使用 `um-` UUID，创建同样绑定原命令身份，版本为绑定的不可变版本。装配时拒绝部署定义占用这两个命名空间。
- 当前部署引用按其准确 ID/version 解析；`um-` 引用只从企业绑定库读取。已停用的准确绑定保留不可变身份和去密定义，以 `Ready=false` 和具体停用原因返回资格；真正不存在、跨企业或数据库读取失败仍返回对应拒绝/读取错误。目录不以一个来源的失败去寻找另一个来源。
- `routeconfig` 的窄 `DefinitionReader` 为列表、资格、发布和正常调用提供统一的准确定义。登记定义由版本化模板+绑定+原连接事实构造，限制在原业务 anchor 内。消费者不保留另一个动态 current 缓存。
- 既有部署渠道在界面标识“由维护人员管理”，新登记渠道标识为可自行维护。同一个现有连接不能再创建自助登记副本；不同连接保存相同厂商/域名/型号是正常的独立账号配置。
- 此切片不导入或搬移现有 Key，不改写已有部署引用，不引入旧系统适配、双写或历史迁移。新表只接纳新登记事实。[全新系统基线](../../../product/greenfield-no-legacy-migration.md)

## 合同到消费者的接线

`提供方与 Key → 现有同源 BFF → 当前模型配置模块的渠道命令 → channelcredential 登记/Key 服务 → 同库事务`。

`关联型号 → routeconfig 绑定命令 → 模板与当前企业业务 anchor → 新准确模型引用`。

`企业模型表单 → 原检查/发布/current → SharedCatalog/DefinitionReader → SharedTextReader → 原治理执行与 SecretReader → 受限公网传输 → 原计量和账本`。

`当前 runtime` 向 HTTP 层注入窄登记、绑定和查询服务；受限存储和模板只由后端装配。`SharedCatalog` 原来直接查进程 map 的位置改消费同一 DefinitionReader，价格与凭据资格照旧。正常 Chat、内容工具及恢复读取中的引用消费者一并核对，不能只让页面看到新模型。独立图片 worker 继续消费其现有类别，新文本绑定不会进入图片/看图执行。

共享配置的三类选择仍采用原快照。准确模型引用标识连接，默认渠道字段仍表示渠道类型；同一个类型下的两个账号在选项中显示不同名称和地址域名，选择冻结到准确引用，不能在运行时按类型寻找“第一个可用连接”。

`ValidateDefaultChannel`、Options、Current、Preview 与资格读取都消费同一目录，识别登记的 `openai-compatible` 类型；连接停用不会令当前快照的渠道类型凭空消失。当前已选的停用引用作为“当前已选，已停用，请更换”返回，禁止把它作为其他字段的新选择，但允许查看、替换，以及在修改其他类别时保留原字段的准确停用引用。保留只保存状态，不恢复其执行资格。实现须区分保留原字段与新增选择，不能用前端过滤代替后端检查。

一个已知引用停用属于可展示的未就绪状态，不得使整组三类 Current/Preview 返回读取失败而关闭编辑。普通业务继续通过 `ReadCategory` 只检查所用类别，已具资格的文本不会因其他类别停用而被阻断。真正未知引用或目录读取失败仍明确报错；不能用未就绪占位掩盖这些错误。

## 修改、停用与进行中的操作

| 用户操作 | 保存及对后续操作的影响 |
| --- | --- |
| 修改显示名称 | 只提升登记元数据版本，Key revision 和已发布的模型引用不变；名称可重复，详情展示域名及账号备注辅助区分。 |
| 轮换 Key | 原 revision/reference 递增，绑定继续指向同一连接；后续报价与最后发送门禁读取新版本。旧检查结果失效。 |
| 修改服务地址或从兼容切到官方 | 使用「更换服务地址」创建一个新的连接，要求重新输入 Key；关联支持型号后，由用户检查并发布新选择。原连接保持可见直至用户明确停用。 |
| 停用渠道 | 使用原 CAS 和 credential 停用命令，登记身份保留。默认发布选择若指向它显示“所选渠道已停用”，使用该选择的新请求拒绝，其他未依赖的类别继续按各自资格。 |
| 停用某个模型绑定 | 只停止这个引用的新选用及准入，同渠道其他型号继续按其当前条件使用。 |
| 重新启用渠道 | 明确重新输入 Key，沿原新版本保存；重新检查当前型号、权限和参考价。 |

服务地址和提供方是凭据授权目标的一部分。不能对原 connection ID 原地换地址并带着保存的 Key 去新域名。详情展示受影响模型和发布用途；停用时用户确认影响。原已发送调用可能返回，已冻结的 Invocation 和账务结果归原连接/版本，UNKNOWN、预留和恢复只查原 owner；不换 Key 重发，不自动选择替代连接。展示名称改变不修改历史账务事实。

新绑定的 `refVersion` 是不可变定义，Key revision 是独立变化的秘密版本。运行准入以当前定义、当前凭据和已发布选择冻结一次调用，网络交接前再比较；并发轮换、停用或解绑先完成时，旧准备不能发送。已经交接的调用由原 owner 收尾。

## 命令、幂等与不确定结果

新增渠道命令使用原企业/actor/requestKey 幂等身份。输入为模板引用、名称、兼容地址、账号备注、API Key。服务端先核定身份、规范化并校验输入，再按前述稳定规则派生 connection ID；事务内加密保存、写登记和回执，回复中只含 ID、去密配置与保存结果。

创建命令沿原受保护 HMAC 机制使用有版本的完整命令指纹，覆盖命令种类、服务端核定身份和派生 ID、模板 ID/version、规范化地址、名称、账号备注、所有其他实际保存字段及 Key；Key 只进入受保护 HMAC，不另存明文或可离线猜测的普通摘要。不能直接复用只覆盖旧 Key 命令字段的 fingerprint。原 Key 命令保持原合同，创建、改名、绑定及 Key 命令以明确类型区分，不能误认彼此回执。同一键改变任一保存字段均冲突；不同 actor/企业的同 requestKey 相互隔离。

客户端在发请求前只记录用户/企业/成员、requestKey、操作类型和预期版本，禁止持久化 Key、完整请求正文或秘密指纹。新建 ID 未收到时，通过“原企业+发起者+requestKey”的窄回执入口查回，不要求重新输入 Key 来判断是否创建过。服务端在事务内先核原回执及完整指纹，再决定是否创建；相同命令返回原 ID 和原回执，即使连接后来已轮换或停用也不重新创建。同名异键是两条独立连接。

| 失败边界 | 结果与下一步 |
| --- | --- |
| 校验/权限失败，事务未提交 | 明确拒绝；无连接、登记或凭据副本。前端可修正非秘密字段，再明确输入 Key。 |
| 事务内部分语句失败 | 共享事务全部回滚；不留下能被调用的半个渠道。 |
| COMMIT 回复丢失或浏览器关闭 | 显示“保存结果待核实”，查原回执；不以列表存在、404 或超时推断成功/失败，不换键自动重发。 |
| 渠道已保存，模型关联失败 | 列表如实显示已保存和尚未关联，可单独重做关联；首次 Key 保存不回滚或再次发送。 |
| 模型关联成功，企业发布失败/冲突 | 原发布回执和 expectedRevision 流程核对；已关联模型可保留，业务继续按真正的 current。 |
| 服务重启 | 登记/模型绑定从同一 Run DB 重新读取，原命令回执仍可查询。请求时的临时资料查询结果不恢复成已验证。 |

请求正文沿原 16 KiB 上限，Key 仍为 4096 字节上限，短标签和 ID 沿现有有界合同。企业渠道登记和模型绑定各按现有目录的 128 条上限读取。创建在事务内检查上限，已保存内容和原回执总能继续读取。事务、锁与 HTTP timeout 复用当前 5 秒锁等待、25 秒语句和 30 秒命令边界；没有网络请求持有数据库锁。

## 自助地址的实际出站保护

保存只验证地址结构与用户明确的目标，不发送 Key、拉取模型或试调用。公开自助地址只接受 HTTPS 主机、受模板允许的端口与规范基础路径，拒绝 userinfo、query、fragment、反斜杠、编码路径穿越和模板以外的接口路径；官方模板只接受固定 origin/path。接口路径由 SDK/模板附加，不能在服务地址里夹带生成或管理端点。

所有新增连接消费者在每次实际拨号时校验该主机解析出的 A/AAAA，并直接连接经核对的 IP，TLS 仍按原域名验证；公网之外的地址、混合公网/私网结果、IPv4-mapped IPv6、loopback、link-local、保留地址和云元数据目标均拒绝。自动重定向、环境代理和 SDK 自动重发均关闭，连接重用遵循原单次传输约束。不能仅在保存时 DNS 校验，再让 SDK 自己解析并发送。

复用仓库 `httpimage` 的公网 IP 分类/直接拨号办法和 `einomodel.NewSingleSendHTTPTransport` 的单次配置，在 AI 传输内做窄适配。必要的安全边界不能仅凭 `net.IP.IsPrivate`；原 `httpimage.IsPrivateIP` 与商品发现客户端已有保留网段用例须核对。厂商 SDK、HTTP、TTL 缓存使用现有 Go 标准库和 Eino/OpenAI 组件；不引入第二网关、通用代理平台或自写 AI 协议。

资料只读查询继续使用 #1423 的 5 秒 deadline、16 KiB 响应和固定官方 URL。查询器必须验证“官方模板+官方地址+准确绑定”，不能因为用户把渠道名称填写成 OpenAI 就把兼容渠道 Key 发往官方。

| A1 | 空列表新增官方连接 | 保存后原列表出现新连接、准确名称与“Key 已保存”；取消不留行；保存无厂商请求，Key 不出现在日志、页面、缓存和回执。 |

| A4 | 现有三类快照 | 首次文本配置不会被未开放图片候选挡住；原文本/看图/生图选择的保存与读取行为保留，模型选项显示具体渠道。当前停用引用可展示和替换，修改其他类别时可保留该字段但不能新增选用；其不可用不阻断已具资格类别的调用。真正目录错误不伪装成停用。 |

| A6 | 事务和幂等 | 并发同键、回复丢失后重放均返回原 ID/回执；名称、模板、地址或备注等任一保存字段变动均报同键冲突，跨命令类型不误认，跨 actor/企业同键隔离；登记/原凭据/回执任一步失败无半成品，404 不触发重建。 |
| A7 | 持久读取和装配 | 服务重启后新渠道和绑定可用，API 与正常消费者都用 DefinitionReader；缺 writer/保护材料/reader 显示正确原因，新功能不使原只读设置无法打开。 |
| A8 | 改名、轮换、地址更换和停用 | 改名不重用 Key 版本；地址更换必须重新输入 Key 并显式发布；从“发布兼容文本 → 停用绑定/渠道 → 返回企业模型 → 更换并发布”走通，停用原因可见，未依赖类别仍可用；并发停用/轮换阻止未发送的旧准备，已发送与 UNKNOWN 继续原恢复。 |
| A9 | 实际传输 | 用受控 DNS/TLS 记录目标与次数；公网/私网混合解析、DNS 变化、重定向、代理、特殊 IPv6 和 SDK retry 均不会把 Key/业务输入发往未许可目标，不自动多发。 |
| A10 | 检查状态 | 官方新连接的只读查询匹配准确 ID，注明调用权限未验证；兼容渠道没有伪装成免费测试的生成请求。切企业/换 Key/改引用后清除旧检查。 |
| A11 | 返回和窄屏 | 完整新增、取消、待核实、保存成功、关联、发布及返回路径键盘可达；窄屏主操作可见，错误文字指出能做的下一步。 |

开发使用已有单元、HTTP/BFF、PostgreSQL 与受控 TLS/DNS 测试入口，先复现目标缺陷再实现。阶段候选运行适用 CI，做高风险边界及最终用户路径独立检查。实际试用需记录准确构建版本、装配、操作账号与型号；受控测试、CI、独立 AI 评审和用户验收分别记录。

新表初始化由现有 `product-agent-runtime-prepare --target managed-model-channels` 接入专用 Run DB owner 流程，使用私密 `PRODUCT_AGENT_SCHEMA_DSN`。它要求目标库已有原连接、去密投影和模型选择结构，创建渠道登记、文本绑定及其回执三张表，设置对应读写角色。启动时检查当前结构和授权。试用时先核对目标 Run DB 和现有数据，按影响范围保全数据和权限。付费诊断继续搁置。
