## 当前方案：OpenAI 模型资料查询

### 能验证到哪一步

OpenAI 的 `GET /v1/models/{model}` 读取单个模型的资料，包括 `id`、`object`、`owned_by` 等。成功响应且 `object=model`、返回 ID 与准确型号完全一致，可确认 **OpenAI 接受了该 Key 在此连接上下文中的模型资料读取请求，且返回了指定型号**。官方把 Models Read 和 Model Capabilities Request 列为独立能力。只读 Key 可以读资料的事实无法证明它能发 Chat Completions 或 Responses 请求，也无法证明项目的推理许可、余额、限额或当前生成用途已就绪。项目另有模型允许/拒绝清单管理接口，官方使用组织级 Admin Key。本方案只使用企业已保存的项目 Key。[读取模型](https://developers.openai.com/api/reference/resources/models/methods/retrieve) · [OpenAI 角色与权限](https://developers.openai.com/api/docs/guides/rbac#permissions) · [项目模型权限接口](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/projects/subresources/model_permissions/methods/retrieve)

**费用依据。** 这是读取目录资料的 GET，没有提示词、推理或模型 token 消耗。查阅 OpenAI 公开价目未发现对该模型查询单列收费，按公开合同可作为无推理费用的检查；此次未使用真实 Key 核对账户账单。硕米此检查不预留、不扣 AI 点数、不创建模型调用结算记录。界面写「本次仅查询模型资料，不消耗硕米 AI 点数」。若将来厂商为查询引入独立收费，停止该查询入口，付费测试仍按搁置状态处理。[OpenAI API 价目](https://developers.openai.com/api/docs/pricing)

### 查询与结果显示

1. **浏览器触发。** 在「提供方与 Key」的当前连接显示「检查模型查询权限」。用户点击后发起一条同源 POST，按钮在本次查询未结束时禁用。浏览器到 BFF 复用原可信同源写入检查、会话与预期用户/企业一致性校验。GET、HEAD、预取和跨站提交均不能触发外发。连接 ID 和预期版本是浏览器可传的目标参数，未知字段拒绝，真实企业/成员只从当前会话和后端授权解析。浏览器结果及中转都禁用缓存。[现有同源 BFF](../../../../web/listingkit-ui/src/lib/server/model-route-pricing-proxy.ts)
2. **锁定目标和凭据。** 在 AI 现有可信目录内按当前企业确认准确的模型引用与版本，匹配可信定义下的 `openai-direct`、OpenAI 提供方和原连接 ID。读取原连接去密元数据核对官方基础地址 `https://api.openai.com/v1` 和目录绑定的端点摘要、启用状态、预期 revision 与凭据 reference，再由受限 SecretReader 按 `(企业, 连接, reference)` 解析。解析结果的版本和连接身份必须与前述匹配。SecretReader 自身不证明厂商身份或端点归属，OpenAI-compatible、自报 OpenAI 的连接、非官方端点以及未匹配的企业模型引用均拒绝。相同厂商名称的代理 Key 不能进入官方查询器。仅沿用已由原装配验证且与该 Key 对应的项目上下文。无可信项目字段时使用 Key 自身项目作用域，账号备注、浏览器项目号和传入请求头不用于构造厂商头。[凭据合同](../../../../internal/aicapability/channelcredential/credential.go) · [原受限解析](../../../../internal/integration/persistence/channelcredential/store.go)
3. **服务端外发。** BFF 后的 HTTP handler 在现有 live 企业/成员门禁上逐项查双权限。仅注入窄用途的服务端查询能力，不向 BFF 或通用客户端注入原始 Key。网络交接前重新核对 live 授权和原连接/目标/凭据版本，变化或读取不确定直接拒绝。每次操作仅允许一次 TLS GET 到 `https://api.openai.com/v1/models/gpt-5.4-mini-2026-03-17`。上游 deadline 5 秒，响应最多 16 KiB。请求无正文。沿现有单次传输的防重发配置禁重定向、连接复用和可能透明重发的协议路径，关闭 SDK 自动重试。无模型列表、管理接口或推理回退。只从可验证的 HTTP 状态和受限结果映射去密原因。[原单次受控传输](../../../../internal/integration/aicapability/einomodel/component.go)
4. **展示范围。** 返回去密结果前重新确认当前权限及原企业、成员、连接等上下文，页面同时用原发起范围及最新连接版本舍弃旧回复。撤权或轮换在最后网络交接前生效时拦截外发。已通过门禁并交接的请求可能返回，此时禁止把结果投影到撤权或新版本之后的页面。刷新、打开设置及保存 Key 不主动查询。超时或厂商暂不可用后由用户手动发起新查询，限流时遵守厂商给出的等待时间。

| 收到的证据 | 页面显示 |
| --- | --- |
| HTTP 200、有效模型对象且 ID 精确匹配 | **「Key 通过查询验证 · 已查到指定模型」**。下一行显示「模型调用权限未验证」，并注明具体型号及检查时间。 |
| OpenAI 明确报告 Key 无效 | 「OpenAI 拒绝了该 Key，请核对或更新后重试」。其余无法归因的认证拒绝使用「OpenAI 未接受本次查询，请核对 Key 和项目设置」。单凭 401 不断言 Key 过期或已撤销。 |
| 厂商明确拒绝读取权限 | 「无权查询模型资料，请核对 OpenAI 项目和 Key 的读取权限」。其他 403（如明确地区原因）按可验证原因显示，证据不足用「OpenAI 拒绝查询」。 |
| 受信的 OpenAI 响应返回 404 | 「未查到指定模型，请核对型号和项目权限」。不从这次查不到推断全球型号不存在或当前 Key 无生成权限。 |
| 429、超时、断网、5xx、无效 JSON、返回 ID 不符 | 按能确定的原因显示「查询暂不可用」或「本次查询无法确认」。收到明确厂商限流时显示「请求过多，请稍后重试」。 |
| 检查后连接、Key、厂商项目或型号有变化 | 「配置已变更，请重新检查」。旧响应不得更新新版本，切企业或退出清除当前结果。 |

只在当前设置会话展示去密结果和检查时间，匹配当前企业、发起账号/成员、连接和 Key 版本、项目与准确型号。刷新可回到「未检查」，不自动补发。该结果不写回企业模型的业务就绪状态或已发布配置。原始响应、厂商错误正文和密钥不进入界面或持久记录。状态映射采用受信的 HTTP 状态和明确的厂商错误标识，模糊原因不作推断。[官方错误说明](https://developers.openai.com/api/docs/guides/error-codes)

### 归属、接线与开工基线

调用顺序为「模型与服务 → 同源 BFF → 现有配置模块内独立查询操作 → AI 目录绑定与渠道凭据原受限 reader → OpenAI 单模型适配器」。AI 目录持有型号与厂商连接定义，channelcredential 持有 Key、企业归属和版本。去密结果只在本次设置会话存在。沿用现有凭据加密、授权与版本协议，范围内无需新增持久化事实、调用账本、恢复协议或迁移。Legacy N/A。

现有 openChannelCredentials 由 Product Agent 或 Image Agent 执行装配驱动。只读路径启用时，定向向诊断服务注入经相同权限验证的窄 SecretReader。连接缺失、配置无法验证或诊断装配关闭时拒绝发送并显示「当前无法检查」。配置 handler 与 BFF 只获去密查询服务。诊断开关不启用生成，普通数据库账号和凭据管理 writer 的权限保持原范围。用户已批准从包含 [#1405 首版](https://github.com/henryxu1008/shuomi-ai-commerce/pull/1405) 合并提交 `baf5ebeab49a8f5992f82fcc8e07496ab30161a4` 的主分支开始执行 #1420。[现有渠道装配](../../../../internal/app/runtime/currentapplication/channel_credentials.go) · [#1405 最终候选 CI](https://github.com/henryxu1008/shuomi-ai-commerce/actions/runs/44105030701)

### 当前验收条件

| 场景 | 通过条件 |
| --- | --- |
| 正常查询与权限边界 | 受控传输中，仅一个 GET 发到固定官方地址和准确型号。200 且 ID 匹配显示已查到，同屏仍显示模型调用权限未验证。只有 Models Read 的 Key 对应成功查询场景，验收无需发推理请求。 |
| 主动发起 | 同源显式 POST 才能进入查询。GET、HEAD、预取、跨源 POST 或浏览器假冒企业/账号均零外发。以模拟厂商服务器的实际接收次数验证连续点击、传输异常和超时无隐式第二次发送。 |
| 授权与 Key 安全 | 只有任一项权限、撤权、跨企业、未登记/停用连接及换 Key 后的旧准备均不能外发。型号、连接 ID、reference、provider/channel 或已绑定端点不一致均拒绝。伪装成官方连接的代理 Key、浏览器提供的项目头与重定向均无法带出 Key。 |
| 错误与过期 | 受控覆盖无效 Key、权限拒绝、404、限流、超时和错误模型响应。页面正确显示原因或无法确认，版本变化提示重新检查，迟到结果不会覆盖新页面状态。 |
| 费用与副作用 | 所有查询分支都无推理、无 AI 点数预留、无扣点、无厂商管理写入。余额为零或成员未配置 AI 点数限额，不会阻止有权的模型资料查询。没有失败后自动续发。 |
| 接线隔离 | 只读服务可定向装配，付费诊断保持关闭。缺 reader 或关闭诊断时操作提示不可查且零外发，既有 Key 管理功能仍遵循原路径。 |
| 现场验收口径 | 先用受控响应验证。后续另行明确指定试用 Key 与授权时才用真实 GET 核对模型可见性，逐项记录观察到的证据。该验收不使用付费推理，当前未执行。 |

## 已搁置方案：付费模型响应测试

原方案适用于未来明确重新批准的一个文本模型。使用固定短文本、一次非流式调用。威胁范围与处置包括企业点数越权、重复支付、超时误释放以及原请求恢复。下列内容保存已确认的规则和此前的独立评审结果。当前只读路径不开放付费测试入口，也不消费其报价、预留和 UNKNOWN 处理。

### 操作与费用确认

1. 选择连接并点「测试模型」。先做本地检查，展示缺 Key、连接已停用、型号不支持本次测试、费用暂不可估算、成员限额未配置或余额不足、权限不足。打开区块、读取状态、保存 Key 和检查草稿均无外发。
2. 本地检查通过后展示当前企业、提供方、准确型号、仅发送固定测试文本、最多一次、预计最多预留的 AI 点数、由当前企业承担，以及超时可能继续保留点数待核实。用户明确选择「确认并测试」。取消或关闭未提交确认无预留、无外发。
3. 服务端签发有时限的报价和确认标识，**同一份确认在签发时绑定唯一服务端原请求键及 InvocationID**。确认内容冻结真实企业/账号/成员、连接和 Key 版本、模型及协议版本、用途、固定文本版本、输入和输出限制、适用参考价与汇率、预留点数 R。确认标识使用服务端完整性校验，浏览器回送原标识和原键，服务器只使用该标识已经绑定的调用编号，拒绝替代键或其他载荷。服务端复算，版本、资格、权限、计价期限或点数上限变化先停下，提示重新检查并确认。余额及成员限制以提交时的原账本门禁为准。
4. 页面分别展示测试结果和费用状态。已知且可结算时显示实际扣除及释放的点数。费用待核实时显示仍在保留的点数和「查看本次测试」。已知未发送时显示未产生本次费用。只收到本地检查通过、网页 HTTP 200 或渠道认证成功的证据，不显示「指定模型已响应」。

R 沿现有参考价和 FX 整数估算，使用固定输入和受控输出请求限制，并受用途封顶值和原账本限制。R 是硕米的确认与预留范围，厂商持 Key 账户可能单独计费，页面明确区分厂商账单与硕米扣点。可信用量按冻结价目结算 A，原账本释放 R−A。缺基础用量、矛盾或超 R 走现有 UNKNOWN/异常处理，避免把 SDK 默认零当成零费证据或直接扣尽预留。按同一报价去重，原账本是唯一点数事实来源。[现行参考价与账本](../../enterprise-shared-model-configuration.md) · [Eino 准入、基础用量与恢复](../../eino-model-admission.md)

**已确认的单次点数上限。** 每次最多 1 个请求，按 **0.30 AI 点（300,000 微点，¥0.003）** 封顶。首个绑定按标准文本价、无工具、`reasoning_effort=none`、固定短文本、输入上界 256 token（含消息封装及估算余量）、`max_completion_tokens=32`、`n=1` 作候选。启用前须用实际受控请求证明上述上下界可执行，使用平台发布且适用的价目、计量和冻结汇率；预留采用原 `ReserveTextMicropoints` 向上取整到微点。官方标准价每百万输入 $0.75、输出 $4.50，举例以 7 CNY/USD、不用缓存折扣计，`(256×0.75+32×4.50)/1,000,000×7÷0.01` 得 0.2352 AI 点（¥0.002352）。示例汇率只用于解释上限，结算仍按原合同。确认页显示实际复算的 R。报价超过 0.30 点、企业余额或成员月限不够、价目不适用或输入/输出限制未证实时拒绝发起，禁止截低 R 后继续发送。该数值是硕米单次预留及授权上限，厂商账单按其适用计费协议。[OpenAI GPT-5.4 mini 标准价](https://developers.openai.com/api/docs/models/gpt-5.4-mini) · [原点数估算函数](../../../../internal/aicapability/official_model_pricing.go)

### 超时、回执和结果未知

首个组合建议上游期限最多 **10 秒**，本地终态写入复用现有执行器独立于断开连接的 **2 秒**收尾时间。端到端服务期限须覆盖验证、预留、发送与收尾。前端达到界面等待期限即转回执查询。确认有效期建议 **2 分钟**，从服务器生成报价起算，已开始的原记录不因报价过期失去查询能力。上游和报价数值在明确所选厂商及现有端到端期限后确认。超时约束本地等待，厂商是否执行按原证据判断。受信传输守卫只允许一次发送并限制响应范围。

诊断结果和费用状态分别取可信事实。现有执行器缺可信用量时可能直接返回 `ErrOutcomeUnknown`，常规终态并未写入已观察到的诊断，本测试不能借即时响应或错误字符串重建历史。仅在原 Invocation owner 已持久化与原次调用绑定的去密诊断证据时，回执才可显示相应的已知结果；费用可同时待核实。复用现有可承载的事实类型，遇到无法持久化该诊断的路径时，回执明确显示「结果待核实」。若所选组合的常见失败不能持续提供可信的用户诊断，须补齐有界证据合同并完成适用复核，或保持该组合未开放。

| 事实 | 页面和后续 |
| --- | --- |
| 固定文本请求获指定模型有效响应，所需可信用量齐全，原终态及结算可查 | 「指定模型已响应」。显示本次完成/费用。业务能力仍按原运行检查判断，测试事实只属于冻结的连接、Key 和模型版本。 |
| 本地无发送证明，或厂商拒绝且证据满足现有原 owner 验证 | 显示确定原因。只有原账本可核实未发送、明确零用量或等价现行许可的证明，才显示未产生本次费用并释放原预留。明确的认证失败、模型访问、限流等仅在该 adapter 能可靠区分时具体展示。 |
| 已越过网络交接后超时、连接中断、无可信用量、claim/终态回复丢失、原费用尚未写回 | 测试结论未知时显示「本次结果待核实」。模型响应已有可靠记录但原费用尚未完成时单列「费用待核实」。保留原标识及原账本已记入的预留，只读查询原回执。断网、浏览器关闭、claim 已写入但发送事实不明或 404 尚未读到均不足以判定未发送。 |
| 页面期间换企业、Key 或模型 | 原回执维持其自己的归属与费用。新企业无法读旧回执。已授权查看历史时将旧结果显示为「配置已变更，请重新测试」。已通过最后外发门禁的在途请求归原记录，轮换与退出不触发重发或结算。 |

回执查询只读去密事实，浏览器无厂商证据写入或预留释放权限。原 owner 的处理分为三种：

1. **本地已有可信终态。** 原点数 owner 的 `RecoverDue` 重读原调用事实，凭原资源记录幂等续结或释放。结算已提交但回复丢失时直接读取已记入的终态。此路径不去厂商查账或再发模型请求。
2. **本地缺终态，有可核对的外部证据。** 现有 `modelinvocationrecovery` 和零费拒绝证明只支持 OpenAI 指定型号的自有商品资料用途。它们不能直接处理本测试。精确测试用途须经同一 owner 新增窄准入，允许有权恢复人员凭与原厂商请求、调用和原预留均可关联的可信证据提交确认。试用前要验证完全丢响应、没有厂商回传请求号的情况下，仍能用准入并经实际验证的请求关联方式取得证明。恢复人员沿原批准和校验规则处理，无通用 HTTP 状态码零费映射。确认发生用量须有原请求的实际用量，确认未收费须有原合同接受的证据。
3. **没有合格证据。** 持续显示「待核实」及原问题编号，保留已存在的预留。没有自动重发、按时间释放或按预留额强扣。浏览器显示仍待核实，维护人员按原流程补证。

首个组合若没有可验证的丢回复关联证据或新用途无法接入原核实/续结，则付费测试保持关闭。可先保留本地配置检查，其页面状态仍是「配置检查」，不展示模型已响应。[原续结入口](../../../../internal/integration/orgresource/model_invocation_repository.go) · [现有受控恢复命令](../../../../internal/app/modelinvocationrecovery/command.go) · [零费拒绝证明范围](../../../../internal/aicapability/provider_rejection.go) · [关闭执行时的历史核实](ai-disabled-application-lifecycle.md)

### 付费调用丢失回复的 OpenAI 查证结论

本轮仅核对 OpenAI 官方公开文档和硕米源码。硕米现有 Mini 直连复用 Chat Completions，发送 `n=1`、`store=false`、`service_tier=default`，使用受控的 completion 上限。现行代码从收到的响应读取诊断用 `x-request-id` 和用量。此次场景假定响应头与响应体同时完全丢失，连服务端请求号也拿不到。[直连组件和响应诊断](../../../../internal/integration/aicapability/einomodel/component.go) · [Mini 请求合同测试](../../../../internal/integration/aicapability/einomodel/mini_text_test.go)

| 方法 | 查证结果与能证明的范围 |
| --- | --- |
| 请求预先带 `X-Client-Request-Id` | 官方明确支持。由应用在发送前生成唯一的不透明 ASCII 编号，并和已冻结的调用身份关联。完全丢回复时可以由相应 OpenAI 账户的有权维护人员用该编号请支持团队查是否收到、何时收到。官方没有把它定义为自助检索接口、费用幂等键，也没有承诺凭这个编号提供实际用量或零费证明。仅确认收到不作为执行成功、费用或释放预留的证据。[OpenAI 请求排查](https://developers.openai.com/api/reference/overview#debugging-requests) |
| 按 ID 查 Chat Completion，或按 metadata 查询已存补全 | 公开接口只返回 `store=true` 的补全，详情读取需要服务器生成的 completion ID。列表按预先写入的 metadata 能找到已存成功响应并读其用量，是不同的数据留存设计。现有 `store=false` 路径无法使用。Zero Data Retention 下 `store=true` 亦会被当作 false。即使另行批准存储，查不到记录仍不足以证明未接收或收费为零。[已存补全列表](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/list) · [数据留存](https://developers.openai.com/api/docs/guides/your-data#zero-data-retention) |
| 用量、费用 API 或 Usage 面板 | 用量按时间桶、项目、Key、模型等维度汇总。费用按日和项目、Key 或账单项目等汇总。公开查询未提供按该客户端请求号、服务端请求号或 completion ID 查单次费用的接口。官方帮助把单次用量指向 API 响应。汇总增量、空桶和统计延迟不能用来判定单次费用、零收费或未发送。[用量 API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/completions) · [费用 API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs) · [单次用量说明](https://help.openai.com/en/articles/10478918-reviewing-api-usage-and-costs) |

**准入结论。** 按当前 `store=false` 接法，OpenAI 有人工收件追查途径，但公开证据不足以用完全丢失的回复恢复原次可信用量或零费结果。付费测试保持 `NOT_IMPLEMENTATION_READY`。如果后续有明确依据，原 owner 只在证据同时匹配原请求、目标模型、原预留和受权的用量/零费处理规则时续结。在此之前，客户端编号仅供排查，维持原配置检查，保留未知结果与原预留规则。当前建议不改变厂商数据留存或为此引入组织级 Admin Key。真实账单、支持工单证据和断网现场测试均未执行。
