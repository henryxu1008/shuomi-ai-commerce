**用户结果。** 有权成员从当前 Chat 显式选择「查公开资料」，提交一个自己确认的搜索词，得到 0–5 条带原网页链接的结果。具备配置权的企业人员可以从原 Chat 进入「模型与服务 → 搜索服务」处理缺项，保存后返回同一会话。支持平台开放的服务与本企业自有服务。

首版只做网页搜索和来源列表。网页正文抓取、自动联网、模型改写搜索词或综合回答、图片搜索、私有知识检索、站点商品采集、自定义服务地址和自动切换厂商均在后续范围。现有 Chat 普通发送继续走原路径。

## 首个提供方

选 **Brave Web Search API**。一个请求可以返回标题、原链接和摘要，能构成有出处的列表。DeepTutor 也用同一 Web Search 接口，可参考其提供方登记与选用交互。首版选公开网页搜索接口，区域和语言由受控配置给出，最多请求 5 条、仅第一页。供应商接口参数和地址由后端模板固定。新增供应商时按实际用途扩充模板。

Brave 定价页将 Search 按请求计量，独立于 Answers 模型套餐。公开价格只作选型依据。投产以实际适用套餐、按请求计价上界和许可为准。通用条款对持久保存搜索结果有限制，产品展示和留存边界见后文。

## Chat 流程、数据边界与责任

1. 成员在通用 Chat 选「查公开资料」，看到当前服务、费用归属和「搜索词将发送给提供方」说明。使用单独输入框，允许修改后再发送。返回设置后回到原会话并重读当前服务，旧确认失效。
2. 同源提交只携带业务明确输入的搜索词和本次请求编号、预览的配置版本。服务端从会话和身份取得企业及成员，重新核授权，读取可信企业选择。只向 Brave 发送本次确认的搜索词和固定参数，Key 仅经 `X-Subscription-Token` 请求头送至固定主机。企业资料、商品、附件、对话历史和用户标识不会随请求发送。输入上限建议为 200 字符、30 个空格分隔词，并遵守供应商更严格的边界。空输入和控制字符按格式拒绝，业务敏感性由明确的输入范围和用户确认控制。
3. 结果卡仅显示纯文本标题、摘要、合法公开 HTTP(S) 原链接、提供方与取得时间。以查询返回时点标注「搜索结果」，不从摘要推断规则现行有效。链接由用户点击打开，服务端不访问结果 URL。摘要当作不可信文本，转义后展示，禁止脚本和原始 HTML。限 5 条、单条标题 200 字符、摘要 500 字符、链接 2 KiB，响应体上限 256 KiB。固定 `GET https://api.search.brave.com/res/v1/web/search`，按白名单发送 `q`、`country`、`search_lang` 和固定页数与条数。使用原有单次发送传输约束，验证证书和目标，禁止连接复用导致的透明重试、重定向及自动代理。Key 和查询 URL 均按敏感信息处理，日志与链路追踪不得记录请求头或完整 URL。同步总时限建议 10 秒。
4. 结果只有在搜索 owner 确认原状态已保存后才可交付，只在当次 Chat 页面内存中短时展示，建议最多 10 分钟。刷新、离页、切换企业、退出立即清掉。结果响应使用 `Cache-Control: no-store`。搜索响应、标题、摘要、结果 URL 不进入持久消息、浏览器缓存/持久化、代理缓存、日志、监控、分析、导出或模型上下文。原会话历史只留成员主动提交的搜索词与原请求引用，另从搜索 owner 读回状态。刷新后可看到「这次搜索已完成，网页结果已过期」，不会自动重搜。若将来要在历史中长期保留出处，需另核具有明确留存权的套餐和实际产品范围。
5. 设置页只显示「已保存 Key」「已选用」「已停用」「配置待核对」等有事实的状态。打开、保存或轮换均不隐式外发测试请求，未实际查询时不显示认证成功。出现限制或服务故障时能回到原 Chat 并继续普通对话。

| 事实所有者 | 窄职责和调用路径 |
| --- | --- |
| `channelcredential` | 复用存储、加密、停用和 Key 版本。增加 Brave 受控用途边界，运行时只允许搜索调用取固定连接及版本的 Key。原 OpenAI 文本模型模板不承担搜索协议。 |
| `routeconfig` | 复用平台开放、发布和企业原版本确认的模式。搜索用途有独立选择及发布记录，消费者从服务端获得可信企业、范围、版本、权限与额度。价格上界和上限随发布冻结。公司 Key 与平台 Key 的 owner 从记录派生。 |
| `aicapability` | 以一个窄搜索操作记录作为原调用、用量状态和预算占用的唯一事实。实施前确认可复用的原调用记录原子语义。不适用的模型 Token 或资费字段不能被填假值来套用。仅补搜索需要的事实与约束，既有模型、平台 AI 点数和商品数据额度保持原合同。 |
| `aiworkbench` | 沿 Chat 身份、会话、原请求读取和同源 BFF 接入一个显式操作。只能使用去密结果和状态，由应用装配注入受控搜索端口。普通会话消息不会自动触发搜索。 |

调用链 `Chat → 实时身份/会话 → 搜索选择及开放资格 → 原请求占用与预算 → 最后发送门禁 → Brave 适配 → 原状态与当前页面结果`。Legacy 按 EXTRACT 复用现有 owner 和适用组件。现有 Chat、模型、数据服务均没有需要退休或迁移的搜索记录。

## 费用、并发与恢复

**2026-11-19 用户确认的首版费用方式。** 平台通道由平台承担 Brave 费用，用实际套餐确认的每次成本上界和请求额度控风险。首版不向租户扣搜索 AI 点数。自有 Key 由企业直接承担厂商账单，硕米只记可确认的搜索用量。每个独立操作记录 0、1 或「待核实」，AI 点数和商品数据条账本均无预留或扣减。平台搜索次数预算与厂商实际金额分开显示。全程不触发文本推理，因此本操作也没有文本模型费用。商业收费若需上线，应另确认业务口径及对应结算设计。

- 请求按企业、成员、会话、操作和原请求号约束唯一性。对确认的搜索词计算带密钥的指纹，冻结服务选择、平台开放、Key 版本、成本版本、额度时段。并发重复返回同一记录。同键更改搜索词或原身份范围时拒绝。历史查询沿原授权和原事实，当前切换不会更改历史。
- 同一 PostgreSQL owner 在一个事务中依固定顺序锁定当期平台连接总量和消费企业额度，登记唯一原请求并占用一个名额，状态为 `HELD`。额度占用归稳定的计费账户与消费企业，跨配置版本、额度变更和 Key 轮换保留当期累计量。平台首版使用一条连接和专用计费账户，开通前核实账号级硬上限及预算能隔离其他用量。企业自有使用本企稳定的请求限制，轮换、停用或改名不能重置。额度耗尽拒绝新请求。平台和企业均使用已冻结的 UTC 日窗，同时受供应商计费周期的账号级上限约束。
- 最后门禁重读当前身份、企业、会话、选择、开放、连接启停及 Key 版本。占用的名额只允许在原预算日窗及原时限内交接，时限取请求 deadline 与原日窗结束的较早者。门禁拒绝，或仍为 `HELD` 且已超时，由同一 owner 对原状态做原子迁移为 `NOT_SENT` 并归还旧窗占用。通过门禁后，在同一数据库以当前 UTC 时钟检查窗口和期限，再以条件更新持久化唯一的 `DISPATCH_CLAIMED`。发送权只归这次成功更新的执行者。实际交接前再查 deadline 和日窗，并将截止时间带入传输。在原日窗外禁发。数据库锁不跨外部请求。已交接按原日窗和原版本核实，重启、回读和重试均不得恢复该发送权。若领取后未能证实是否交接，即使进程可能在建连前退出，也保留未知及原额度。
- 可信成功响应作为一笔搜索用量，空结果也是一次成功查询。响应能确认成功但内容无法显示时仍记已发生用量。可确定未交接时记录零。Brave 公开文档说明失败请求不计额度，真实套餐须核实哪些明确响应可当作未计费证据。连接中断、收到不可信响应或无法确认计费时保持「结果待核实」，继续占当期预算。只读原回执按原身份恢复。没有可查逐笔证据时保持未知，按当期最坏成本计入额度；窗口换日不会把历史改成零。本地日窗限制硕米交接次数，厂商接收或计量时刻可能跨日。真实账单硬上限须由已确认的适用套餐或账号级控制提供。
- 决定是否返回结果前再次查会话与成员权限。企业切换、撤权或其他失效使响应内容不再交付，已发生的内部用量保留在原企业。崩溃或响应丢失后的恢复只读取原状态。发送资格已被占用但缺终态时保持未知。只有可信原请求证据才能修正状态，聚合余额与耗时不作单笔凭证。

## 阶段和开放条件

## 运行接线

运行字段为 `aiWorkbench.publicWebSearch`，缺省关闭。获准开放时复用当前企业允许名单、可信平台维护机构、路由配置 writer 和渠道凭据读写角色。由已有 Product Agent 数据库 owner 在同一事务显式安装[搜索表](../../../../internal/integration/persistence/websearch/schema.sql)并[授予窄权限](../../../../internal/integration/persistence/websearch/grant.sql)，运行进程启动时只校验，配置写账号不可修改原配置回执或删除搜索记录。渠道凭据 owner 在保存、轮换或停用 Brave Key 的同一事务记录该版本的数据库时间，原回执按原版本读取该时间。渠道凭据 writer 只可读该时间并添加版本，不能改写时间。隔离测试在任务自有数据库执行同样的准备，Brave 客户端注入本地传输替身。实际厂商许可、应用条款、账户硬上限及真实验收仍使用前文的启用条件。
