# 模型渠道的平台配置与租户选用

状态：独立架构设计已修订并完成复核。当前交付为设计和评审，后续执行经单独开工准入。源码基线为主分支 `365d68e41`，[#1428](https://github.com/henryxu1008/shuomi-ai-commerce/pull/1428) 是复用来源。与上一版的关系见[模型与服务总设计](model-and-services.md)。2026-11-18 用户修改计费规则，企业自有渠道只记录用量，平台渠道照常扣点。当前计费及新增验收以[企业自有渠道只记录用量](enterprise-owned-model-usage.md)为准。

## 产品结果与首版

用户确认平台统一配置、租户按用途切换、自有渠道作为高级权限。借鉴 DeepTutor 将提供方、所供模型与使用位置串起来的方式。硕米的企业页面首先解决“现在用什么、可以换成什么”。

| 开放顺序 | 用户操作与可见结果 |
| --- | --- |
| 首版先交付主流程 | 平台配置并发布至少两条可用于企业文本用途的渠道，设置开放企业和适用参考价。获权租户成员在「企业空间 → 模型与服务」切换一次即可保存，刷新后看到当前渠道。以硕米 Chat 规划和当前已开放文本消费者验证。 |
| 首版接入高级入口 | 明确授予「管理自有渠道」的租户成员能添加 OpenAI 官方或已受控的 OpenAI-compatible 渠道、保存或轮换 Key、关联受支持型号、查看结果和停用。达到同一用途准入条件后，自有渠道进入本企业的切换列表。新增仅交付已支持的文本模板，同一渠道可分别停用渠道或其模型关联。 |
| 后续按业务接入 | 图片生成、图片分析沿现有条件运行，之后再各自接入新切换操作。嵌入、搜索、后台任务随[对应业务切片](model-and-services.md#后续接入设计)设计。任意协议、自动发现、自动换渠道、平台批量开放和付费诊断延后。原[官方模型资料查询](model-connectivity-test.md)按既有范围继续。 |

当前 `SharedTextReader` 将 Chat 与其他接线的普通文本用途读到同一份企业文本选择。首版的可编辑行称「企业文本模型」，标明「用于硕米 Chat 及以下当前已启用的文本用途」，由服务端按当前挂接的消费者列出准确范围。该行的候选必须满足全部受影响的用途，已接入的官方限定策略继续检查。业务独立选 Chat 是后续明确产品需求时的单独切片。首版验收可以用两条独立官方渠道和同一受准入的 Mini 型号验证平台主路径，兼容模板单独用受控业务替身覆盖适用和不适用企业。[现有分类 reader](../../../../internal/integration/aicapability/routeconfig/shared_catalog.go)

## 页面与操作

**平台管理员**从复用的仅平台维护者可见入口进入「模型渠道」，沿已有账号维护区的信息架构。列表显示渠道名、支持用途、准备状态、向多少企业开放。一个渠道详情依次处理 Key、受支持型号、适用参考价和开放企业。保存渠道后可以继续补其他条件。完成条件后，主操作「发布给所选企业」，回到详情确认生效。停用前提示当前受影响企业数量和用途，仍由目标企业管理员决定替换。

**租户配置人员**从现有「模型与服务」进入。每行先显示用途、当前渠道、准确型号、配置状态，一个主按钮「切换」。选择界面展示名称、来源「平台提供／企业自有」、准确型号。平台选项显示适用参考点数，自有选项标明「企业自有 · 不消耗硕米 AI 点数」。同名型号保留独立项。确认框再次列出本次影响的用途。确认时核对预览中的渠道与用途资格。平台选项同时核对开放版本、参考价与汇率，报价基础变化时由用户重新确认。成功后回到原行并读取最新选择，业务页入口带回原页。平台选项显示当前参考价，实际业务请求按届时生效价冻结。普通成员的业务页显示当前选择及阻碍，带有相应权限时才提供配置跳转。

**自有渠道管理人**在同页看到次级入口「管理自有渠道」。在列表添加，保存后在原详情显示「Key 已保存」「尚未关联模型」，关联且通过全部适用用途和用量解析资格后，已有模型配置权的人可点「去选用」，跳回用途行确认。只负责管理自有渠道的人看到「已加入企业可选渠道，请联系企业配置人员选用」。已关联但资格不足时显示「型号已关联，暂不可选用」和具体原因，暂时隐藏「去选用」。返回列表保留位置。发布或绑定缺条件时保留已保存渠道，并显示下一步。Key 输入不进浏览器持久化或 URL。请求发出后或离开表单时清空 Key。结果待核实期间只保留原操作编号。

| 场景 | 对用户的结果 |
| --- | --- |
| 还没选或可选列表为空 | 分别显示「尚未选择」和「暂无可选渠道，请联系平台管理员」。存取故障显示「暂时无法读取」，提供重新读取。 |
| 当前渠道已停用或企业访问已收回 | 保留本企业的已选型号和渠道标签，分别提示「当前渠道已停用，请切换」或「此渠道已停止向本企业开放，请切换」。原项不可新选，仍可打开其他可选项。 |
| 变更或回读失败 | 已获原回执但重读失败，显示「本次已保存，当前选择暂时无法确认」。响应丢失时按原操作编号核实；版本冲突提示重读后重新确认。 |

状态以已发布选择和实际配置资格为依据。「可选用」「Key 已保存」均为配置事实。适用 #1423 时，官方资料查询成功仍显示「模型调用权限未验证」。

## 权限与威胁边界

| 操作 | 授权 |
| --- | --- |
| 配置平台渠道、Key、型号、参考价和开放范围 | 平台维护读和写沿现有平台定价的身份门禁，写入同时要求 `listingkit.platform_admin` 和 `listingkit.admin.write`。平台维护请求须处于受信配置的平台维护组织。服务端核对 live 有效组织、项目、原生维护授权与有效成员，拒绝租户代管或企业自定义角色作为平台授权来源。 |
| 租户切换企业用途 | 现有企业模型配置权和 live 企业、成员访问资格。只写当前企业选择；对平台渠道仅消费平台明确开放给该企业且适用于此用途的引用。 |
| 租户管理自有渠道 | 复用 #1428 显式企业角色模块，界面名称为「管理自有渠道」。现有企业角色管理者在「成员与权限」创建含「管理自有渠道」和「渠道凭据管理」两个模块的自定义角色，再用正常角色分配入口授予指定成员。保存、轮换和停用沿原双权限门禁。关联或取消关联核对「管理自有渠道」、当前企业登记归属和受控模板，只写自有绑定，不改企业选择。实际切换继续单独要求原 `workbench.agent.configure`。企业管理员、普通成员和仅有模型配置权的成员默认没有自有渠道管理权。 |
| 模型调用和资料查询 | 正常业务保留业务、资料权限和非点数的请求限制。平台调用同时检查原点数预算，自有调用只记录用量。#1423 已有租户官方直连资料查询继续用原双权限与准确范围。平台 Key 和兼容地址的诊断入口在后续切片。 |

平台渠道默认只向明确选中的企业发布。发布目标从后端可核对的当前企业目录选择，停用企业即使仍在名单也拒绝访问。平台开放授权仅适用于该渠道的已发布型号和准入用途。企业选用页只读取面向自己的去密投影。选用版本冻结最少的渠道显示名、渠道来源和准确型号供同企业回读。撤回授权后仅回读原版本的标签及停止开放状态，已选项无法查询平台最新名称、价目或渠道详情。平台密钥、租户私有 Key、其他企业的选择与请求回执均在原持有范围内。查原回执仍核对当前授权和原操作主体。平台和租户维护凭据沿原保护及审计要求，变更访问与凭据必须走实际权限检查。

现有自定义角色模块不能授予 `workbench.agent.configure`，常规成员修改使用单角色替换。首版须用常规授权路径验收，禁止依赖叠加系统管理员和自定义角色。#1428 的关联 handler 额外要求企业模型配置权，须在本轮改为上表中只写自有绑定的授权。在 API 和界面分别判定关联与选用；管理者不能借关联、取消关联或直接发送切换命令改企业当前选择。[现有角色模块](../../../../internal/authz/module_catalog.go) · [原角色分配](../../../../internal/integration/zitadel/membership/writer.go)

威胁范围包括跨企业选用或调用、伪造所有权、权限撤回后的滞后提交、Key 或业务内容外发给错误地址、重复扣点。兼容渠道经营方可能收到正常业务请求与 Key，沿 #1428 的明确地址和告知合同。Key 记录成功和只读模型查询无法证明执行质量或厂商账单。

## 所有权与接线

| 事实 | 唯一 owner 与接线 |
| --- | --- |
| 渠道身份、地址、启停、Key 版本和加密凭据 | 现有 `channelcredential` owner，连接身份为「受信所有者命名空间 + 连接 ID」。企业自有使用现有 live 企业作用域。平台使用受信装配核定、与 IdP 企业 ID 不相交的保留 owner 命名空间。它独立于平台维护身份的有效企业和平台价目目录 scope。HTTP 客户端无法指定 owner，Key 解析仅在后端窄执行端口。 |
| 已准入型号、平台发布状态和开放企业 | 原 `routeconfig` owner 管理准确绑定、用途和平台开放集合。单一带版本的发布事实记录开放企业集和准确绑定，授权判定由目录及执行共用；同一连接的凭据启停仍读原 owner。两个 owner 的运行事实在 Run DB，采用原有分离写入身份和限定投影。 |
| 租户当前用什么 | 原 `routeconfig` 企业当前选择和原版本记录。租户命令只传用途、稳定的绑定 ID/version、预期版本及请求号。服务端从企业自己的当前快照构造下一版，按原仓储 CAS 更新该用途并记录回执。 |
| 参考价、汇率、点数和调用 | 复用平台价目与汇率 owner。平台渠道按准确型号、价目、地区、用量策略和生效版本匹配原参考价，消费企业承担点数预留和结算。Invocation 负责两种渠道的执行快照和实际用量，企业自有调用只经该 owner 记录。 |

平台和自有绑定在同一受控目录按明确的命名空间路由。引用带准确 ID/version，所有者由后端从受信范围解析。平台方案需要两个不同的组织概念。凭据 owner 决定 Key 从哪里解析，消费企业决定谁能使用、读哪些资料、账本归谁。两者都进调用准入及原 Invocation 的可追溯引用。平台渠道的厂商账单归平台的厂商账号，自有渠道的厂商账单归该企业的厂商账号。平台使用原参考价、换算和点数账本；自有渠道靠获准模板读取并记录用量，独立于参考价和汇率。

`平台维护页 → 同源 BFF → 平台身份与写权限 → 凭据登记服务 / 路由发布服务 / 原价目维护`。先保存，可回读已完成项目。发布服务在其版本事务内校验型号、开放企业和所需条件，结果回执随发布提交。缺价过期、Key 停用等动态资格始终通过原 owner 实时判断。

`租户用途行 → 同源 BFF → 企业模型配置授权 → 候选与切换命令 → 原企业选择 owner`。发布时只校验本用途的新候选，保持其他类别引用以及既有共享字段（包括 `defaultChannel`）原值。当前 `CategoryDigest` 包含 `defaultChannel`，从所选模型反写全局字段会影响图片资格或在途校验，首版应禁止这种联动。快照版本和初始化合同见下方。[当前选择与发布接口](../../../../internal/aicapability/routeconfig/shared.go)

**快照版本与首次选用。** 沿用同一 `ai.models.enterprise` scope、current 指针、版本历史和 CAS 仓储。没有当前版本时使用原哨兵 `NONE` 发起切换。存在版本但所读用途为空时，返回可确定的「尚未选择」，该用途不进入运行。新版沿同一仓储信封，允许快照内 `SharedModelSelection` v2 明确省略未设置的引用和无配置的全局字段。初次选文本写入这一条，图片和多模态仍为空。读与历史投影对现存完整 v1 和局部 v2 使用同一类别读取器。基于 v1 改一个用途时，保留原字段及其他类别的运行摘要算法；摘要只受该类别有效字段影响。创建 v2 不批量改写存量，也不猜测任何初始渠道。现有聚合页面的兼容写入口和历史恢复都必须走同一服务的授权、版本及逐类别资格判断，未改字段原样继承。若无法遵守该规则，在对应租户启用新流程前停止旧入口写入，仅保留获权查询与原回执读取。

`现有文本消费者 → 统一资格 reader → 当前选择、计费方式、授权范围和受信凭据解析 → 原业务调用保护 → Invocation；仅平台调用接原点数账本`。候选、保存、运行都用模板允许的 operation 与消费企业已接线且启用的用途 anchor 的交集；首版全企业文本选择须覆盖当前同一行全部已启用的消费者，沿各自原有协议策略、权限和调用上限。平台开放不激活缺少受准入 anchor 或关闭的用途。涉及价格时，用绑定内显式指定的 `PriceID`、准确报价型号、渠道类型及适用范围/版本走原价目 owner。两个相同协议、相同型号的独立渠道可指向不同价目 ID；同一价目仅在平台明确核定同时适用时共享，运行时禁止用名称、协议或型号猜价。

**跨作用域的调用合同。** 后端通过受信目录生成冻结组合：消费企业与业务 operation、企业用途选择摘要和准确绑定 ID/version、平台发布与该企业开放授权版本（如适用）、凭据 owner、连接 ID、Key 版本、目标地址摘要、计费方式及用量解析策略。平台调用另外冻结适用价目及汇率版本。资格 reader、窄 Key 解析和最后发送门禁都使用同一组合。Key 解析必须按受信 owner 和连接/版本查询，再核对返回 owner、启用状态与目标；公共配置与 HTTP DTO 不接受凭据 owner 或版本作为授权输入。调用记录、资料访问和平台点数账务始终以消费企业与当前业务身份为准，原 Invocation 复用含 owner、连接和 revision 的去密凭据引用，并将配置版本记录绑定到原选用、发布和价目事实。历史收尾按冻结引用查原调用，禁止从今天的授权推导旧 owner 或重取 Key 重发。最后门禁重读同一组合，拒绝权限变化、版本不一致与依赖读取失败。企业成员权限和平台开放授权分别核验。

## 停用、并发和结果不明

- **保存与启用。** 渠道草稿允许先有 Key 后补模型、价格或开放范围。启用后，平台开放授权、准确版本、当前 Key、适用价目及业务用途任何一项不满足就不可新选和新调用。统一目录与业务运行使用同一资格规则。
- **切换与停用并发。** 切换按原版本 CAS 重新校验选择和关联的当前发布、访问条件。若停用或撤回先于切换准入被观察，返回已失效并提示重选；若切换先提交，随后停用保留已选并标为待切换。跨 owner 事实以运行时最后门禁为准。门禁拒绝时，已有平台点数预留沿原规则释放。自有调用留原记录，没有预留。无资格自动换渠道的行为延后。
- **发送门禁。** 使用原单次受控传输的最后检查点判断新请求是否可交接。撤回先于最终检查生效时阻止发送；已经通过最后检查进入交接的请求按原在途处理，不改目标、不重发。后续设计与实现验证停用、撤回、切换、轮换的具体时序及单次发送。数据库写锁不跨外部请求。
- **保存 Key 与版本。** 用 #1428 同库事务保存登记、加密 Key 及回执，轮换产生新秘密版本。更换地址使用新连接并重新输入 Key。原业务选择仅在获权用户确认后产生新版本。
- **失败与恢复。** 新建、关联、发布和切换沿原主体、scope、操作类型和请求号的幂等回执；同键换内容拒绝，超时或断线查原回执，未查明不自动重发。已到厂商但结果不明，由原 Invocation 核实，平台请求按原冻结价目与账本恢复，自有请求只核实原用量。停用、授权撤回及后续切换不影响历史审计或使旧费用重新归属。

与 #1421 迁移的 Eino 合同存在两个需明确限缩的旧约束。第 5 节的三类完整选择要求，对本设计覆盖的按用途首次选用以本文同 owner 的版本化局部快照合同为准。第 9 节的同企业凭据限制继续适用于企业自有渠道。平台自持凭据仅能经本文的明确开放授权与双作用域门禁由受控业务执行消费。该例外不允许查其他企业凭据，也不扩大 #1421 的迁移范围。后续执行批次同步这两处适用范围引用，保留其余协议准入、计量、单次发送和原账本合同。

## 可验收条件

| 验收 | 预期证据 |
| --- | --- |
| 平台管理闭环 | 平台管理者创建两条同型号的渠道、分别核对适用价、设置开放企业并发布。刷新后读回。只有读权限或租户代管身份无法修改。缺 Key、型号、价格或开放范围的草稿不能成为可选项。 |
| 两企业和三类权限 | 企业 A 可以选择公开给 A 的选项、B 无法通过界面或直接请求使用同一引用；企业自有渠道从另一个企业不可读写。通过正常角色页面为人员分别授予模型配置或两个自有管理模块。高级人员能添加并关联、无权切换，配置人员能切换、无权代管 Key。普通成员无法写。核对双权限缺一、直接 API 越权以及撤权实时生效。 |
| 按用途切换和返回 | 两个同型号选项可辨识。切换仅保存该行，初次配置可保存文本用途且其他类别真实未选。已有图片及多模态选择、资格摘要不因文本切换漂移。从 Chat 进入后返回原业务，读取服务端已保存选择。窄屏与键盘能完成操作。 |
| 停用、撤回和并发 | 原选择可读有具体提示，新请求和新选择拒绝已不可用项；能换回其他可用渠道。确认后掉线按原请求核实；发布、切换、撤回或轮换交错时不覆盖他人版本、不泄露凭据、不重复发送。 |
| 正常业务接线与计费 | 在受控传输替身分别核对平台和自有渠道的准确用途、型号、凭据 owner 及消费企业。平台同型号不同价目和报价变更沿原验收；自有渠道的无点数执行、用量核实、恢复以及账本零副作用按[计费专项验收](enterprise-owned-model-usage.md#验收条件)。 |
| 复用及协调 | 分别验证与 #1421 迁移后的文档链接、分支有效复用代码和组合差异。旧 #1428 成功证据仅覆盖原企业自建路径；平台开放和跨 owner 使用要有各自的新证据。 |

## 独立评审与修订

| 评审发现 | 分类与影响 | 本轮处置 |
