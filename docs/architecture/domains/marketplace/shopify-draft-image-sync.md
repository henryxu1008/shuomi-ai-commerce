# 工作台同步图片到已有 Shopify 草稿

执行 [#1639](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1639)。Independent Architecture。用户于 2026-11-25 同意继续完成已有草稿图片同步。沿用 [店铺授权与创建草稿](shopify-product-draft.md)、[已采用图片上传](shopify-draft-approved-image-transfer.md) 和 [按颜色生成图组](shopify-color-image-sets.md) 的现行边界。此前的创建合同没有授予更新能力。

## 用户结果

商品运营在同一件自有商品的 Shopify 刊登编辑入口选择「同步图片到已有草稿」。工作台显示当前已连接开发店，让用户明确输入该店的 Shopify 商品编号或后台链接。核实已有草稿后，同屏显示商品、图库、已采用素材和各变体拟替换的主图，按「已在图库」「待新增」「需要核实」反映读到的证据。已有图与关联一致时显示「图片已同步」。有变化时明确确认后继续同步。完成时仍可打开原草稿。

首轮仅限已验证的 Shopify 开发店、单个 DRAFT、当前自有商品版本、现有已采用图及完整唯一的 SKU 匹配。真实试用使用同一原草稿 `10419372589218` 和已采用的 12 张图；它们已在该稿图库中，效果验收应证明查回与防重复。实际新增图片和变体写入使用隔离测试数据与官方合同验证，并单列真实与合成证据。无创建／删除商品、删除或重排旧图库、价格／库存／标题／状态更改、商品发布、订单、其他平台、额外生图、生产部署或合并。

## 事实与预览

| 事实 | 现行拥有方 |
| --- | --- |
| 当前企业、成员、来源商品及固定版本 | Identity、Listing Preparation、Product/Catalog；沿现有工作台的商品与店铺选择及权限 |
| 选用图片、采用版本、图片内容、颜色图位 | Product Asset 与 Image Agent；读取同一企业、同一 ProductKey 和版本的现有正式素材，复用生成工件 reader 与摘要核验 |
| 稳定 Shopify 店铺、安装、授权代次、访问范围 | Store Center；同一个已验证开发店和现有商品权限，使用实时检查后的应用令牌 |
| 远端草稿、图库状态、变体标识和配图 | Shopify 的官方 Admin API；Marketplace adapter 只负责传输、读回与校验，Listing 负责同步计划和执行证据 |

预览从现有同源工作台入口进入 Listing。来源商品及采用素材须通过 `SourceImageReader` 当前 Supply Manage 授权，店铺另由 Store Center 按当前成员的商品状态读取权限独立核实。链接只用来解析固定格式的商品编号，程序不会按输入域名发出请求。经 Store owner 对当前操作员、同一稳定 Shop GID、安装、当前代次及开发店资格复核后，以固定 Admin GraphQL 端点查询明确的 Product GID，返回前再次核实当前店铺绑定。要求完整、有界的图库和变体页，在匹配当前来源的所有 SKU 及实际结构化规格前不展示图组对照。拒绝重复 SKU、空 SKU、对不上组合、分页不全、非 Draft 与跨店结果；草稿标题用于给用户核对。工作台曾创建的草稿可从合法回执带出 ID；此前后台手工建成的草稿需运营自己选中并核对，不生成历史创建回执。

预览读取当下的 Store 绑定、应用和代次、Product GID、来源版本和采用头、远端变体 GID/SKU/规格、原配图及图库快照、每个选中资产及拟用图。只读交付返回对照所需的显示状态，无创建意图、计划或回执的能力。颜色与尺码按现有结构化值匹配，由运营确认图片选择，未能唯一选定主图的颜色要求运营明确选图。回读结果只使用该草稿图库中的 Shopify MediaImage GID。允许使用官方 Admin API 返回的 `MediaImage.originalSource`，由服务端对固定 `https://shopify-shop-assets.storage.googleapis.com` 的短期地址进行直接公开网络 GET，验证主机、公开 IP 和 HTTPS，不重定向，不附应用凭据，设置单文件 3 MiB、整体超时与并发限额。签名地址只在调用内存中使用。比对原始字节 SHA-256，需要唯一对应的 READY 媒体。遇到无法读取的可能候选或多张相同媒体，保留需要核实。只有候选全可核实且该摘要不存在时才能显示待新增。文件名、处理过的缩略图 URL、相似外观和不完整列表都不作为自动去重证据。展现用缩略图只走现有公开图片入口，不把签名原图 URL 或令牌交给浏览器。

## 写入与恢复合同

- 复用 Listing 的封存意图、原操作回执、ExecutionKernel、一次性发送许可和 Store Center 的实时授权。此动作拥有自己的稳定目标 `企业 + 稳定 ShopKey + Product GID + 草稿媒体同步`，与源商品的一次性创建目标区分。禁止拿创建回执当作更新许可。新意图只能在同一稳定目标的上一轮已确定关闭后进入；现有平台重复动作的精确前序尝试检查适用于这里。关联回执仅用于读取原 Shopify 草稿，不改写创建事实。
- 已经符合的图片和配图返回已同步，既不申请暂存也不发变更。需新增时，先按现有隔离工件交接读已批准字节，通过 Shopify 原 staging 路径发到固定暂存端点。只使用 Shopify 对现有商品的 `productUpdate` 增量 media，输入仅有准确的产品 ID 和新图片。暂存仍有界、可到期回收，保留既有体积和时间限制；若超过一次有据可用的暂存数量，确认前让操作员调整，不能隐式分批重发。
- 若需要变更变体主图，只对已经属于同一产品、READY 且可唯一核实的 MediaImage 执行 `productVariantsBulkUpdate`，对每个变体仅提交准确的 `id` 和 `mediaId`，显式 `allowPartialUpdates=false`。读回变体实际 media 关系，证明预览中的每项关系已落地。不得用 `productSet` 重写商品或其文件和变体集合。
- 追加媒体与配图可能分两步。实现以原 Listing 效果 owner 为唯一责任方，保留一份已确认意图和逐步外部执行证据。每步先在原发送许可下持久化，这一步是否已经发送、观察到的准确远端身份与状态随后记录。附图仍在处理时保留步骤，用户核实只读；必要的后续关联继续使用该计划，在重新核实权限、来源及变体关系后才可取得前序明确完成的下一步许可。禁止在结果不确定时重复发同一步或者用新计划跳开。远端非本程序的并发改动应在发送前以当前快照复核，并在发送后读回实际结果；Shopify 更新接口未承诺服务端按 DRAFT 或远端版本比较并交换。本轮只在专用开发店使用。
- 在成功或可信确定未发送证据后才能关闭相应步骤。Go 网络超时、响应丢失、局部错误、Shopify 空读或缺少可证实原图只留「同步结果待核实」。只读证据能解锁后续一步或记录已同步；不能证明没有副作用时不补传。访问撤销、安装代次变化、已采用库存头变化、用户更换来源或 Shopify 商品状态改变时停止后续写入。已追加图片不自动删除，展示已观察到的部分事实。
- 所有写入步骤必须加入现行 Shopify 隔离护栏，使用原有店铺 freeze 与 dispatch/drain 所有者，不能成为隐私排空后仍在途但未被归集的第二条写入链。正式写入准入需要把两个步骤的事务、释放、重启、未知回收以及同店重连／冻结映射到该护栏的现有可验证事实。当前只读预览无此副作用，它仍须遵从当前 Store 可见性。

## 开工门槛与验证

只读预览与写入是同一交付批次的递进。先在真实开发店证实 API 返回同一草稿的完整媒体与六 SKU 关系，并检查远端原始字节是否确实能与已采用的旧图对照。在合成验证覆盖 Shopify 拒绝、丢响应、部分之后回查、操作员双击和重启、越权及过期版本。写入实现前，明确上节每个步骤的可重放证据与护栏归集，并完成独立评审。不得复用创建路径规避这个门槛。

2026-11-25 的只读隔离查询已通过同一开发店和当前安装，Shopify Admin API 返回 HTTP 200、API 版本 2026-10、Draft、27 个图库媒体和 6 个变体。对 Shopify 专用存储主机返回的 12 个原图执行受限直连读取，12/12 与已采用资产的原始文件 SHA-256 一致，6/6 变体的媒体 GID 对应已核实的同色主图。未发 Shopify 商品更新请求。文件名仅用来在这次试验证据中挑选已知样本，正式预览按图库成员及内容摘要进行匹配。

只读预览与合成写入 `IMPLEMENTATION_READY`，现用试用库与真实 Shopify 写入 `BLOCKED`。合成写入只使用现有 Testcontainers、预装护栏的空白 Product 数据库和模拟 Shopify。既有 Shopify 成功创建目标不复用于更新，合成执行使用独立步骤身份并复用 Product 的原执行与排空记录。状态读回不能替代原请求已退出排空范围的证据。

### 只读试用中的分色核对

按当前正式采用结果的颜色与轮播位使用第一张，校验图片绑定的原图属于来源商品同一规格维度。要求该维度唯一且各颜色均有主图证据。规格有多张远端媒体时保留「需要核实」。有正规草稿回执时在商品行的独立预览入口带出商品编号，没有回执时可输入自己核对的现有草稿。入口同样适用于「已上传」列表。

### 写入的独立评审候选

Listing 的官方执行 owner 在同一产品数据库内保存一次明确确认的同步意图。用现有事务范围建立按企业、稳定 ShopKey、Product GID 唯一的活动同步；意图包含来源版本、采用头、已核实的既有图库与规格关联、所选图摘要、唯一用户确认及单调递增的同步修订。相同确认键与相同输入返回原计划，冲突载荷拒绝。仅当旧同步各步骤均被持久化关闭且无未观察的发送，才允许下一次确认。Stable ShopKey 的活动占用跨重装保留，上传许可仍绑定于确认时的授权代次。只读核实继续沿当前 Store 授权。

每个网络操作拥有独立的一次性执行尝试身份。子意图键由父确认键、操作、暂存轮次和冻结素材顺位确定，图库追加与配图各自只占一个步骤身份。按是否必需执行并持久化 Shopify 暂存参数请求、按工件编号发送暂存文件、原草稿追加图库、原规格关联。签名表单字段和暂存地址限于本次进程内存，持久事实仅包括摘要、关联及原响应退场证明。每次发送与既有 `shopifyguard.AdmitDispatch` 在同一事务下提交，校验父意图、generation、锁、有效执行声明和前一步证据。所有已发请求由既有排空表按当前代次汇总。仅当同一父意图的原暂存轮次都已证实退场，且追加步骤从未获发送许可，才允许在期限内换下一轮重新暂存。缺失证据的阶段保留待核实。

每步结果记录业务结果与传输退场两个独立事实。退场只由该次持证发送者对已读到的完整原响应记录，在 Shopify 已接受的异步媒体处理期间继续保留待处理业务状态。冻结后只允许窄范围补记已返回原响应的退场，停止获得任何进一步发送许可。确认前和发送前均校验仍是同一 DRAFT、店铺、当前采用头、已核实的原规格和配图。任意一步未获确实原响应时保留未排空；确认窗口过期、进程重启、HTTP 超时和平台空读无权解除。恢复只读可记图库或配图的实见状态，不改写原 response-observed。 Shopify 永久停留在不确定又无官方退场证据时不重发，不跳过到下一步。

在持有原响应的追加阶段保存该响应已经纳入同一产品的候选 GID 以及发送前的原图库快照，待处理完成时从同一产品只读查询准确 GID，按文件 SHA-256 唯一识别新增且 READY 的成员。若覆盖范围完整且能唯一证实，可以进入变体关联。追加响应丢失时，即使查回看到相同图，也只展示目标状态和原发送仍待核实。配图步骤只写精确预览中的变体和已证明的 MediaImage；按同一规格的唯一媒体关系回读。完成后由同一确认收据记录追加项和配图项，不改原商品创建回执。

新写入在应用接线和每次许可交易中均须确认原护栏可用，沿用原执行 owner 并按动作、父意图、授权代次和原 claim 原子检查退场。既有草稿创建仍按当前合同执行。2026-11-25 现用隔离工作台的产品数据库已有七次 Shopify 执行尝试且没有排空表；当前仅供一次性合成测试的初始化入口要求没有既有尝试。完整写入的最小合成试验需要已有护栏的空白试验数据，现用开发店工作台的写入开通还需要可验证的增量接线。此候选尚未批准写入。

合成实现复用一份执行尝试与一份 Shopify 排空证据。当前合成端口用完整的图片图库、原图摘要与规格关系核对结果。图库缺页、图片处理未完成、追加请求候选与确认计划不一致，或外部已经修改拟配图规格时均保留待核实。暂存只有在旧阶段完整退场、图库追加未获发送许可的条件下才可再进行，当前同一确认最多提供三轮暂存。现有工作台与真实 Shopify 写入入口未接入这条合成路径。

官方依据：[追加商品媒体](https://shopify.dev/docs/api/admin-graphql/2026-10/mutations/productUpdate)、[变体媒体关联](https://shopify.dev/docs/api/admin-graphql/2026-10/mutations/productVariantsBulkUpdate)、[媒体管理顺序](https://shopify.dev/docs/apps/build/product-merchandising/products-and-collections/manage-media)、[productSet 集合语义](https://shopify.dev/docs/api/admin-graphql/2026-10/mutations/productSet)。
