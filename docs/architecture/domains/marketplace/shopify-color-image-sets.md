# 工作台按颜色生成商品图组

执行 [#1637](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1637)。Independent Architecture。用户于 2026-11-25 指定复用通用 Skill v4、使用黑灰白外套原图在隔离环境各生成主图、轮播和详情，并核对现有 Shopify 开发店外套草稿的六个变体。沿用 [企业商品图片](../ai/enterprise-grsai-product-image.md) 与 [Shopify 草稿已采用图片](shopify-draft-approved-image-transfer.md) 合同。

## 用户流程和责任

- Shopify 隔离工作台的同一商品图片智能体提供「按颜色生成图组」。用户明确选择商品已有的销售规格列及每个值的一张原图。Listing 从当前固定原商品的结构化变体属性和变体图片推导可选值及原图 ID。S、M 共享该颜色的图片图组。通用图片、空绝对图和其他颜色图不能冒充原图。共同挂在多个颜色下的同一 URL 对这些冲突颜色无资格。任何颜色无已归属原图时不准备任务。程序不从 SKU、照片名称、自由文本或模型推断颜色。
- Image Agent 复用现有执行模式、Skill、可选企业渠道和共用原图三图模板。一次计划将精确模板版本的两张主图/轮播及一张详情扩为按颜色的槽位。首次需选择共用原图的模板、通用商品目标、企业用量渠道、明确不加文字，2 至 3 个实际值，9 张以内。为每个槽位只读取一次所属颜色的原图，保持原有引用数量、累积文件大小和单图规格限制。计划在现有控制下冻结分组规格、每色图源、稳定槽位 ID、每图事实、渠道和报价。旧计划无新增字段，摘要及旧行为保持原样。现有数据库记录和工作流协议扩展可选字段，无新表、新队列、资金语义或持久化责任。
- 一次明确确认展示每色图数和总调用次数。使用 Image Agent 既有请求键、每槽位外部调用栅栏、用量计量、重试和不确定结果恢复。固定颜色存在于槽位配方及正式素材图位；同一颜色各槽位引用同一张原图。生成或采用时重新核对同一企业、同一商品版本与原图资格。对分组任务逐图保留人工采用。已有 Asset 头版本、选择摘要、素材工件及用量来源仍由原 owner 校验。图片的颜色标签以槽位为准；借用其他商品、颜色或历史任务的候选不能附加到本图组。图片模板依旧可用于其他商品。
- Shopify 运行路径沿 #1634。试用只触及已存在、可读回的开发店 DRAFT `10419372589218`，先核对标题、DRAFT、变体原 ID 和六个 SKU。使用 Shopify 既有后台媒体及配图能力补入本轮选用的图，每色 S、M 关联同一张主图。原有图库可保留。无创建请求、无商品标题/价格/库存/可售状态更改。现有工作台销售平台的创建幂等规则不变，不建立正式的 Shopify 既有商品更新服务。店铺主题和前台按颜色切换图库不在范围内。提交结果不明时只刷新查回现有商品。

### 分色不变量

- 每个分色槽位的提示词以冻结的颜色值为唯一销售规格与颜色依据。分色场景不注入原商品汇总颜色或规格，保留描述材质等同款共用且当前合同允许的事实。构造与校验使用同一个提示词函数，旧计划保持原提示词字节。颜色不作为图中文字。
- 初版一次确认覆盖全部实际颜色，各色三张，总共 6 或 9 个槽位。只核实、恢复同一任务的原调用。分色计划不能进入普通重新生成入口，普通计划也不能通过重新生成换成分色计划。整套通过逐图审核后提交。失败或仍待核实时，保留原任务和槽位，不能冒充完整图组。
- 采用要求本计划全部槽位及准确图位一致。图片的组别、顺序和颜色从已通过的槽位配方核实。后续保留已批准图片时，已存颜色及图位不能被选择请求抹除或覆盖。通用候选、原图和手工材料不能通过自行填写颜色取得分色生成的证明。

## 验证

本地定向回归验证多色结构、错误/重复来源、规格变化、单色原有合同、预算及报价摘要、图片不得换色和资产分组。隔离验证复用已保留服务，先用真实外套三个颜色的现有图片走正常 Workbench，保存成组图片，核对指定 Shopify 草稿的三个颜色每色两 SKU 配图及图库。检查已有和新图片、草稿状态及渠道状态。全程保留工作台和 Shopify 后台的实际证据。
