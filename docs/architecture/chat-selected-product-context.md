# Chat 规划读取已选商品资料

状态：`IMPLEMENTATION_READY`。独立架构复核确认权限和历史关联方案可实施；实施与最终验证仍需完成。

## 用户结果与范围

用户选择已保存商品并要求整理内容后，Chat 规划应使用该商品已有资料，不再因规划输入缺失而要求重复提供已有内容；资料确实缺失时可如实追问。本次覆盖内容会话的自有商品和采集商品，先用原有黑白 T 恤测试商品验证。只生成规划与回复，不确认执行、不改商品、不发布；原预留保持不动。用户仍需确认执行及采用建议。

## 已有事实与根因

现有 `workbenchSelectionBinding` 已按当前身份向原商品 owner 读取并核验所选版本和授权，但 `einoplanner.Prepare` 仅序列化选择标识、任务参数、工作范围和历史消息，没有商品资料。内容 Agent 的后续执行才读取已保存商品；规划模型无法据此辨别哪些资料已经存在。

## Owner、合同与调用路径

- 沿用 Collection/Acquisition 的成员授权和 Catalog 当前有效、不可变的发布版本；不建立第二商品事实源、表或迁移。先按原身份读取并确认选择的商品版本，投影必要的标题、纯文本描述及卖点；不读取图片二进制、凭据、成本、库存或无关字段。对商品资料设置确定的长度边界，明确截断/缺失，作为不可信业务数据而非指令。
- Planning 的准备和执行都通过相同授权 owner 读取所选的不可变版本，验证商品身份、版本、publication 及选择匹配；版本、授权或事实不一致即在发送前停止，不能退回其他版本或其他商品。针对当前任务支持所选自有和采集商品的已有 owner，不自行新增权限。
- 商品事实进入模型后，回复和后续对话历史都可能包含商品内容。每次读取模型回复、原命令回执、历史消息或将历史送入新的规划前，按该消息关联的原命令及其冻结商品选择使用现有 owner 重新检查当前成员权限；撤权或无法可靠关联时对相关内容拒绝或遮蔽，不能仅检查会话范围或依赖旧缓存。发送前同时复核商品与工作范围权限；不新建通用权限系统。
- 一条回复可能复述本会话更早商品的内容，因此只检查该条直接选择不够。逐条按回复所属命令的历史前缀检查相关商品授权；后续商品的撤权不能遮住更早、不依赖它的回复。任一必要授权失效、命令关联缺失/重复或解析失败时，对受影响的回复和回执 fail-closed，并阻止将其送入下一轮规划。普通会话和用户自己的无关内容仍可读；历史版本按原 owner 授权读取，不因商品正常更新自动失权。命令关联限定同企业、用户、会话、操作及回复 ID，不假定数据库存在唯一约束。
- 由回复派生的目标摘要可能进入任务、定时计划、通知或项目引用；这些读取路径沿同一原命令前缀核验。普通和定时内容执行在原有最终发送门禁重查依赖；后台复用原成员的定时执行身份，直接手填且没有 Chat 来源的定时计划仍按原有权限处理。
- 模型规划的精确输入、上下文、报价和输入哈希共用同一投影；准备和发送重建同一版本并校对现有 InputHash，重试沿用原命令键和原收据，不另发未确认的调用。权限和工作范围在原有发送门禁重新验证。新增上下文不得绕开最大输入、字节、报价、点数或额度上限；超界明确停止或使用确定的有界投影。
- 按现有提示版本合同明确新版本；更新精确用途配置时沿用同一企业模型、价目和费用上限，不改变其他功能。历史会话、旧命令和 UNKNOWN 继续使用其原有协议，不重复提交或伪造结果。

## 验证

TDD 验证授权商品事实进入规划输入、缺失与超长资料处理、跨企业及撤权拒绝（包括历史、回执和送入新规划的上下文）、版本变化不能串用、同键重试及输入哈希不漂移；自有商品和采集商品各覆盖原 owner 路径。复用现有测试与当前环境；原试用实例运行一次受预算约束的规划请求后刷新查看同一回复，不确认或执行商品任务。真实模型输出具有不确定性，单次试用结果和自动化结构测试分别报告。

## 实施约束

- 商品读取和授权在会话锁外完成；PlanPreparer 在锁内保持纯计算，发送前重新核验冻结历史和商品授权。
- 新旧提示协议分开处理；已有 v3 输入逐字重建。旧 READY 命令在路由变更时可按既有合同安全失败，UNKNOWN 不自动重发。
- 新版写入商品相关回复后，不能直接回退到不执行历史商品权限检查的旧进程；回退需保留读取门禁或阻止回退。
