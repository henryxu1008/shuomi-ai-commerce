# 商品采集交接在扩展后台重建后恢复（#1161）

状态：设计候选，待独立复核。依据 [持久草稿与可靠交接 §7](plugin-capture-durable-drafts.md#7-交接刷新与跨重启恢复) 和 #1161 用户决定。

## 用户结果和边界

同一 Edge 配置、浏览器会话及原接收文档内，扩展后台在预览后终止并重建，用户仍可手动确认原草稿。五分钟按首次签发计算。真正到期、浏览器进程重启、扩展更新或会话数据缺失时，用户通过既有「本机保全资料 → 恢复原操作」签发新交接，保留原 key/body/scope。无真实插件更新、部署、原草稿提交或历史会话迁移。

## Owner、绑定和恢复

- Handoff 是短期凭证 owner。Controller 在打开接收页前生成随机 nonce 和绝对到期时间。沿用 ReturnSession 的受信任 storage.session（TRUSTED_CONTEXTS），在既有接收标签记录标记本次签发的 nonce。首个通过现有精确来源、路径、顶层 frame、tabId、documentId、nonce/key 和草稿 scope 校验的 capture.meta，原子保存完整绑定（草稿 ID、key、nonce、到期时间、原 documentId，复用记录的 tabId），成功持久化后才应答。待绑定或写失败的凭证无法恢复，页面保留既有明确恢复入口。存储不含正文、身份凭据或重试许可。
- Background 等待会话和 DraftStore 准备。Controller 按会话凭证的精确草稿 ID 加载，经 key、配置的接收路径、草稿来源与原到期时间一致性验证后重建 Handoff。每次消息仍校验原 nonce、key、发送标签和文档及现有 scope。恢复只采用已完成文档绑定的凭证；最新草稿只能作为现有本机恢复入口的数据，不能授予接收页权限。原文档若被替换，新的 documentId 不继承授权。
- 接收页消息处理与 ReturnSession 会话更新共享一个串行边界。该边界覆盖消息校验、首次文档绑定、读取/草稿事务与应答；在重置/显式恢复中已开始切换时阻止新消息进入。显式恢复或新操作使用既有 ReturnSession 清理/替换路径撤销旧绑定，持久化只可更新仍匹配本次 nonce 和 tabId 的记录。清理先完成时旧消息不得读取或取得发送许可；先被接受的发送可能已发出，保留原编号核对，清理不等同取消。过期凭证不续期、不持有额外正文副本，不记录到日志。读取、解析或写入错误停止凭证恢复/交接，保留 IndexedDB 草稿。Legacy N/A，无迁移或兼容路径。

## 发送和核对

DraftStore 继续持有原 key、冻结的 body、scope 和事务化发送阶段。Handoff 重建时不发业务请求，不恢复内存中的一次性重试许可。已标记发送或重试途中的草稿保持现有启动时 UNKNOWN 收敛，按原编号核对；只有用户经现有 Amazon 核对和明确重试流程才可继续。接收页仍在当前可信应用上下文和用户确认后先 bind、再 beginSend、最后发 POST。后端权限、原键幂等和已保存事实 owner 保持原样。

## 验证

先用现有插件测试重现后台重建后原文档的消息失败。回归覆盖精确草稿、文档/标签/账号/企业/成员不匹配、首次签发五分钟到期、显式替换与并发旧消息的先后边界及已开始发送的 UNKNOWN。复用隔离 Edge browser-smoke、临时配置、回环接收器及本地 Amazon 夹具，停止实际扩展后台，手动触发同页确认，断言原 key 和原 body 且一次发送。发送后再重建，禁止未经核对的重复发送。共享交接的 1688 路径一并回归。合成验证与真实环境验收分别记录。
