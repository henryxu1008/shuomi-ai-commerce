# SHEIN 美国站一页试取 · 单次发送离线接线

## 交付范围与准入

用户在 #1074 原会话授权先独立设计评审，再离线实现同一批准单的单次请求、25 credits 上限、并发及重启去重和超时原单核账。适用 [#1074 当前准入材料](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1074)、[商品卡片首试](research-commercial-assessment-v1.md#53-shein-美国站商品卡片首试实施方案)及其 Must、Out of Scope 和 Accepted Risks。来源实现基线 `f1287f1750540f7ba6f88977d924e910bb2346b9`，#1075 消费基线 `f50d7d35e61927f848f44536e3f0cd85cba35c9e`。本轮无用户入口、路由、Figma 修改或 UI 范围。

独立架构准入覆盖离线接线。使用测试批准单、现有空 Product PostgreSQL 测试安装和本地函数替身执行完整发送控制及核账路径。固定 SHEIN US 连衣裙类目 `1727` 首个列表，ZenRows Fetch + Extract 参数 `mode=auto`、`extract=auto`、`proxy_country=us`。批准单授权的是一次客户端提交、并发一、最多 25 credits 和新增现金 0 美元。服务商自动模式内部换策略属于来源许可范围。商品投影与 [shein_us_data@v1](research-commercial-assessment-v1.md#52-shein-来源侧最小交接合同) 原版发布仍由原 Product owner 负责。商品解析、准备、真实账号结算与上线装配不在本轮发送控制范围。万邦按既有独立证据推进。

## Owner、装配和事实

- Domain 逻辑在 `internal/product/dataacquisition`。同一 owner 的 Product 持久化使用窄的 SHEIN 页级试取表，每个全局唯一批准 ID 只有一行。批准 ID 同时是本轮原单关联 ID。发送口无客户端自选任务 ID、URL、上限、翻页或重试参数。
- `internal/app/dataservices` 提供内部离线装配，连接该 Domain 服务、Product 持久化及注入的批准权威、发送端和原单用量查证端。三者缺一关闭。离线装配无真实 HTTP、SDK、ZenRows key、开关、worker 或路由注册。空库试取 DDL 显式安装在同一个 Product 库，独立于现有 Amazon 安装及运行权限。无历史迁移、跨 DB 双写或新任务平台。
- 可信权威从现有授权主体、私有项目和批准单派生固定绑定。绑定批准 ID、企业、操作者、成员、私有项目、账号/专用 key 的非秘密引用、有效期和请求版本。提交时必须复查当前项目权限、来源许可、账户专用 key 独占且无在途、本次最高计费已证实在 25 内、包内可用至少 25、无自动充值或超额现金。调用方只传 principal 与批准 ID。存储核对绑定，改作用域/批准内容不能复用。授权读原记录须通过当前访问权；查证由权威显式授权的同企业核账角色完成，可在发送批准过期或原成员撤权后处置原账。只返回最小账务状态。
- 25 credits 是账号包内页费的本地预留意图。独占及真实可用余额由账户 owner 保障。持久化行没有终态用量时即保留 25。无真实钱包、人民币 fen 兑换或单独 Resource 扣减。与每张商品的内部发布预留分开，页级原账只确认一次。将来需要账户与现有 Resource 的真实计价或发布准备绑定时，按各自 owner 单独准入。
- Amazon 当前的重试型租约适用于原 Amazon 路径。SHEIN 的试取行不走该 worker、租约、ASIN 或按商品计价。保留既有 P1/P2 原版读取、展示及付费对比门禁。

## 发送与恢复合同

| 状态 | 事实与动作 |
| --- | --- |
| 无页级试取行 | 验证批准和账户。库内以批准 ID 原子插入并提交，核对不可变绑定及 DB 时间早于有效期。额度证据缺失、过期、关闭或权限失效时发送 0 次。 |
| 已占用，结果 UNKNOWN | 插入即消费唯一发送机会并持久化 25 预留，只有明确收到插入事务成功的调用可以发送一次。唯一约束拒绝并发第二次获得发送资格。若提交结果不明则停止，重启只能观察已提交状态。发送前再核准当前授权、时限及账户条件。使用带硬超时的上下文。任何发送错误、取消、失权、崩溃或费用不明时保持 UNKNOWN。提交已写但发送前崩溃也作相同处理，无自动补发。 |
| 已核账 | 以同一批准 ID、原请求绑定及可信原单用量确认写回 request ID 和 credits。重复同回执幂等，不同回执拒绝。确认超过 25 时保留实际数字，标为超限，不改写为 25。未确认用量时不得按零记账。 |

查证接口只读账务证据，不能提交 Fetch。输入是原批准绑定、固定请求和唯一发送机会的时间窗，由可信查证端按原请求 ID 或专用 key、固定 URL 和时间窗的唯一原单出具关联后的回执。无原单、仍在途、匹配不唯一、账务不完整或关联不符时继续 UNKNOWN。一次查证返回 0 credits 也须附原单和明确最终用量。回执同时绑定批准 ID，原请求 ID 唯一约束防同一原账确认到多个批准单。写回失败或重启后重查同一原账。接收正常响应也走同一回执写入口。并发查证不能夺走发送资格或覆盖已确认事实。

只复用原始固定请求，不自动跟随重定向、重试、换 key、重新发任务或降级来源。离线发送端只有单个调用口。将来的实际 transport、代理层重试关闭和账户 Activity Log 可核对性需要按最终候选专门验证。外部凭据、Cookie、HTML、原始 URL 查询密钥不得进入试取表或错误输出。本轮真实许可、账号余额、外部计量及执行批准均保留原准入状态。
