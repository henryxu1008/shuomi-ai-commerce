## 新版写入后的恢复方案与隔离证据

- 原则：新版曾写入新消息、类型化引用或命令后，旧快照不能覆盖当前库，也不能直接假定旧镜像识别新版结构。若新版本异常，停止新增写入，保留当前数据库和原始回执；涉及跨库引用或 UNKNOWN 的操作保持原键及原状态，不发起模型调用、不释放预留。
- 无损优先方案：在明确停写且数据库和外部事实的一致性边界可核验后，对当前新版数据及必要的项目、商品和权限 owner 做一致性备份；先在独立环境恢复，并使用**支持该结构的新版**验证数据、权限及连接。仅在目标身份、备份完整性、跨库引用和当前状态均明确时，另行评估将服务恢复到新版。无法证明一致性或存在 UNKNOWN 时保持停写并人工核对；不依据旧快照强行回退。
- 确需旧版时，可在与用户业务隔离的只读副本上使用旧快照进行诊断；它缺少快照后的数据，不能代替现有库。对新类型数据做降级转换或合并属于新的持久化/恢复合同，未在本方案内实现，必须另行设计和评审；不允许把数据隐藏或删除当作回退成功。
- 隔离验证：在 `network=none` 的保留库副本的另一个克隆中，通过当前 Chat owner 创建一条明确标记的合成会话及 `STORE_OVERVIEW_REF`；原键重放未多建。对新版状态制作备份并恢复到另一独立库，十张工作台表行及表/列 ACL 一致，新会话、命令和引用均保留。旧快照不含新会话，直接覆盖会丢数据；旧版 787207b03 的 runtime schema 校验对新版写入库拒绝。新版后端在恢复库上以禁模型 `conversationOnly` 合成配置启动并返回未认证 401。
- 独立只读复核确认新版源库与恢复库的十表数据、ACL、备份哈希及旧快照缺失新会话；结论仅限工作台 owner，不覆盖全部业务库、外部资产、一致性冻结、完整应用或自动化无损回退。此为恢复方案及隔离证据，不授权变更原 35444。
