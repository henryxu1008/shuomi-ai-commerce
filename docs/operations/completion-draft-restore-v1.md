# 待补全草稿恢复历史内容

Refs #708；合同见[历史内容恢复](../architecture/completion-draft-restore-v1.md)。

## 使用入口

1. 自有商品详情 → 已有待补全草稿 → 继续编辑 → 保存历史 → 查看旧版。
2. 有供应链管理权限时，点击“将此版内容恢复为新版本”，进入独立页面；仅查看用户仍可查看旧版。
3. 核对固定来源 Vn、当前已保存 Rm 和旧版 Rn 的标题/描述差异，点击“恢复为新版本”。页面不自动保存。
4. 成功后显示实际保存的 Rk，可查看准确新版本，或返回最新草稿、保存历史、原商品和原转入批次。旧记录保持不变。

也可从原供应链待补全列表进入。独立路由为 `/workbench/supply/mine/missing/:sourceId/history/:revision/restore`；仅允许原 `preparation` / `item` UUID 导航上下文，并与实际来源核对。选中当前版本、内容完全相同、读取失败或归属不符时不保存。

若其他窗口已保存新版本，页面提示当前版本变化。点击“重新读取当前版本”、重新核对差异，再次明确确认；不会自动覆盖。操作结果待核实时，保留原键，使用“核实原操作”；只有原请求尚未读到时才按原键、原载荷重试。返回或刷新仍沿既有浏览器待核实操作，不另建恢复命令。

## 运行与边界

复用原 `ProductCollections` / `SupplyCompletionDrafts` 能力及已安装的 CompletionDraft API、权限、表和命令回执，无新增后台 API、schema、grants 或配置。正常后台启动继续沿既有私有配置：`go run ./cmd/current-application -config <private-config.json>`；前端在 `web/listingkit-ui`、沿既有私有环境运行 `pnpm build` / `pnpm start`。

本轮只增加前端消费者，可与提供 #705 合同的后台配套使用。实际实例切换须单独授权，保留原配置、数据、图片、镜像、卷及正常启动流程；不能用无配置页面或 CI 当作实例试用。本轮未部署、未写保留实例业务数据，用户/生产验收为 NOT_RUN。

只恢复标题/描述；当前候选属性、SKU价格/库存保留当前预览版本的值，来源SKU/图片/属性、固定来源版本及平台资料仍保持原owner。结构化候选编辑及历史比较见[操作说明](completion-draft-structured-v1.md)。恢复保存的是普通新候选版本，不代表已绑定店铺、平台校验、批准或上传，也不新增服务端“恢复来源”审计事实。
