# 定时内容任务 V1

跟踪 [#1244](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1244) / [PR #1245](https://github.com/henryxu1008/shuomi-ai-commerce/pull/1245)，设计依据为[已批准架构](../architecture/ai-workbench-scheduled-tasks.md)的 §3.2。源码交付、隔离验证与具体实例开放分别记录；本说明不授权部署、真实模型调用或数据操作。

## 用户操作

1. 登录当前企业，进入 **AI 工作台 → 任务中心 → 定时任务**。入口只在后端已配置定时能力时出现；调度服务未就绪时仍可查看和暂停已有计划。
2. 创建计划时从“我的数据”选择已保存的自有商品或源商品，选择目标语言、文本字段并填写任务目标。也可从 Chat 的内容执行方案点“设为定时任务”，沿用其商品、模板与已冻结的项目／店铺范围。
3. 选择一次预约、每天或每周；周期规则使用明确的 IANA 时区。一次日期和可选截止日期使用输入框标注的本机时区，再在确认区展示计划时区的具体下一次时间。
4. 点“核对时间与预算”，核对对象、下一次时间、最大次数、单次及整个计划的 AI 积分上限，再确认保存。预算核对本身不调用模型。积分单位为 `ai-micropoint-v1`，1 AI 积分 = 1,000,000 微积分；来自原模型费率的最坏预留乘以已批准调用次数，不是模型参考币种报价，也不新增余额账本。
5. 保存成功仅表示计划事实已落库。只有准确 Temporal 规则读回匹配后才显示“已启用”；登记结果待核实时不重复创建。HTTP 503、超时或响应丢失后保留浏览器会话存储中的原命令，使用“核实原操作”沿同一键恢复。
6. 关闭浏览器后由后台执行。计划详情显示每个预定时刻的跳过、执行前阻断、结果未知和原任务已核实记录；“查看原任务与人工审核”进入原任务详情和原 Review 路径。生成建议不等于采用、保存回商品或对外发布。
7. 暂停、恢复、修改时间、结束仅影响未来执行。结束不能恢复；已经创建的原任务及其未知占用继续保留。修改时间沿服务端修订号比较，冲突后重新读取并核对，不自动覆盖另一次更新。

同一计划有未决原任务时，后续触发记录为跳过，不积压付费执行。默认补触发窗口为 15 分钟；过窗及遗漏的历史时刻保留为跳过记录。暂停期间收到的旧回调恢复后仍是同一跳过记录。DST 缺失本地时刻跳过，重复本地时刻最多执行一次。

## 配置与启动

沿用 [Chat / 内容任务运行说明](ai-workbench-chat-trial.md) 的正常登录、企业 allowlist、当前 IAM 服务授权、内容 Agent、Collection/Source、Review、模型准入及原积分服务。定时任务不保存浏览器 JWT，不制造 HTTP 身份，逐次按冻结的企业、操作者、成员向原 IAM 和业务 owner 复核。

在**获准的新安装**的私有 current-application manifest 中，已有的 `aiWorkbench` 配置另外加入：

```json
{
  "enabled": true,
  "contentTasks": true,
  "conversationOnly": false,
  "schedules": {
    "temporalAddress": "127.0.0.1:7233",
    "temporalNamespace": "<当前已创建的 namespace>"
  }
}
```

该片段不能替代原数据库、企业、模型、积分与 IAM 配置。Temporal 地址必须为显式 literal loopback 地址；复用现有 Temporal SDK 和客户端拨号，不另外运行一个进程内计时器。正常启动命令：

```powershell
go run ./cmd/current-application -config C:\private\current-application.json
```

新安装由现有 Workbench schema installer 与 runtime grant 安装当前 schema。运行构造只验证 schema 和最小权限，缺失定时表／字段时拒绝启动，不自动迁移、双写或覆盖旧表。历史精确空库补列工具不构成本次旧实例升级路径；保留实例升级与数据库操作需要另外确定范围。worker 启动失败使启动失败；退出时先停原 worker，再由原应用 owner 关闭 Temporal client。既有有界后台恢复循环按游标扫描登记与原回执，未决计划不会饿死后面的待登记计划。

## 已验证与限制

代码级和隔离运行证据包含：DST/漏槽/长中断；真实 PostgreSQL 原子 occurrence+BusinessTask、来源互斥 FK、幂等与修订冲突；暂停后旧回调；20 个未决计划之后的登记扫描；真实 Temporal dev server 的登记、暂停、恢复、旧修订拒绝和准确 nominal slot；真实 PostgreSQL + 合成模型 transport 的无浏览器执行、default/read_only、拒绝自动模式、组织停用、权限撤销、项目范围与原来源、用量未知保留占用；HTTP 提交后最终读回 503 的同键恢复。

前端单元回归覆盖请求结果未知的原命令保留、重载恢复和输入保留；浏览器 UI fixture 只验证界面交互与视口，不作为真实 provider 或部署验收。

本期只开放原商品内容任务，生成待人工审核建议；支持默认与只读模式，拒绝自动批准／完全访问。含知识库的 Chat 提案暂不提供定时入口，服务端也明确拒绝；不自动换成无知识库执行。来源版本或配置变化后阻断原计划，需要用户重新确认当前方案。没有新增平台发布、批量旧任务补跑、金额阈值调度、任意 Agent 调用或新的账务 owner。

真实模型、真实业务数据、保留实例部署和用户产品验收仍为 **NOT_RUN**。具体准确 HEAD、CI、独立复核及浏览器执行结果记录在 PR。
