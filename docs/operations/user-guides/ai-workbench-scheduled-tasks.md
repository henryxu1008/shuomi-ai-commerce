# 定时任务与已有商品内容计划

跟踪 [#1244](https://github.com/henryxu1008/shuomi-ai-commerce/issues/1244) / [PR #1245](https://github.com/henryxu1008/shuomi-ai-commerce/pull/1245)，设计依据为[已批准架构](../../architecture/ai-workbench-scheduled-tasks.md)的 §3.2。源码交付、隔离验证与具体实例开放分别记录；本说明不授权部署、真实模型调用或数据操作。

## 用户操作

1. 登录当前企业，进入 **AI 工作台 → 任务中心 → 定时任务**。入口只在后端已配置定时能力时出现；调度服务未就绪时仍可查看和暂停已有计划。
2. 按2026-11-15最新产品决定，新建计划只开放店铺经营日报：选择店铺并安排时间，不再显示商品内容或任务类型选择。Chat不再提供“设为定时任务”；原`schedule_proposal`链接显示停止新建提示，可返回定时列表，不自动核对或保存。已有商品内容计划仍可查看和管理，原执行状态、任务及历史不变。
3. 店铺经营日报选择一次预约或每天，统计周期使用UTC+8；已有商品内容计划仍保留原一次、每天或每周规则及明确的 IANA 时区。一次日期和可选截止日期使用输入框标注的本机时区，再在确认区展示计划时区的具体下一次时间。
新建日报切换为“每天”时，默认最多执行30次，可快捷选择7次、30次或填写自定义次数；仅一次仍只执行1次。执行期限集中展示次数与可选截止时间，先到哪个条件就结束。次数按实际启动计数，暂停和跳过不计次数，不能将30次解释成连续30个自然日。编辑沿原计划回填次数和截止时间，复制继续保留次数并清除原截止时间，不自动改动原计划。

4. 店铺日报点“核对计划”，核对店铺、下一次时间及次数后保存，不使用模型或展示AI消费预算。已有商品内容计划编辑时仍点“核对时间与预算”，核对对象、下一次时间、最大次数、单次及整个计划的 AI 积分上限，再确认保存。预算核对本身不调用模型。积分单位为 `ai-micropoint-v1`，1 AI 积分 = 1,000,000 微积分；来自原模型费率的最坏预留乘以已批准调用次数，不是模型参考币种报价，也不新增余额账本。
5. 保存成功仅表示计划事实已落库。只有准确 Temporal 规则读回匹配后才显示“已启用”；登记结果待核实时不重复创建。HTTP 503、超时或响应丢失后保留浏览器会话存储中的原命令，使用“核实原操作”沿同一键恢复。已经提交的控制操作按原回执读回，即使执行时间已过或执行配置后来变化；当前访问权限仍须有效。

   若原请求实际没有提交，只有服务器已持久化确定拒绝、并阻止旧在途请求稍后提交后，页面才会解除该原命令的待核实状态，允许调整后重新保存。普通报错、暂时依赖失败或撤权本身不是这个证明。
列表的“最近执行结果”复用现有当前用户权限下的执行历史，按预定时刻倒序只读取最近一条。显示结果及其时间，只有服务端当前返回获权报告编号时提供“查看日报”；“日报已生成”不表示资料完整，完整性仍在报告中说明。刷新、窗口重新聚焦、重连与读取失败均重新核实当前授权，读取过程中不展示旧报告链接；无记录与读取失败明确区分，不猜测更早的报告作为本次结果。

6. 关闭浏览器后由后台执行。计划详情显示每个预定时刻的跳过、执行前阻断、结果未知和原任务已核实记录；“查看原任务与人工审核”进入原任务详情和原 Review 路径。生成建议不等于采用、保存回商品或对外发布。
7. 未结束计划通过“编辑计划”调整未来的商品、任务目标、语言和处理字段，或日报店铺，以及时间和总次数。修改后重新核对时间与预算；已消耗次数不清零，次数上限必须大于已消耗次数，已开始任务和历史保持原设置。暂停的计划编辑后仍保持暂停，不自动恢复。计划类型不互换。
8. 已结束计划不能重新启用。只有店铺经营日报提供“复制新建”带入设置；商品内容的新建与复制入口已撤下，后台保留原计划执行、管理和原请求结果核实能力，不删除历史或停掉执行。日报复制时重新填写一次执行日期或截止日期，再核对并显式保存。新计划独立计数、不复制任务/报告/历史或预留；打开复制表单和核对本身不调用模型、不保存计划。
9. 暂停、恢复、编辑、结束仅影响未来执行。恢复前先持久化已过时刻的跳过记录，因此即使暂停同步失败、旧回调在恢复后才到达，也不会补付费执行。长期暂停的历史分批处理期间计划仍保持暂停；页面沿“核实原操作”继续原命令，补齐后才开放未来时刻。结束不能恢复；已经创建的原任务及其未知占用继续保留。修改沿服务端修订号比较，冲突后重新核对，不自动覆盖另一次更新。

完整编辑与复制的边界见[当前增量合同](../../architecture/scheduled-plan-edit-copy.md)。确认页的后续积分上限按新单次上限和剩余次数计算，不将新费率重新计入历史消费；保存不预留或扣点。

### 编辑权限的安装与回退

新安装沿现有`GrantRuntime`。保留实例仅使用原owner的现有`ai-workbench-schema-init`，明确`AI_WORKBENCH_SCHEMA_DSN`及准确database/server address/port，选择`--schedule-edit-permissions enable`；仅增加六个内容编辑列的UPDATE，已完整安装日报时另含report_spec。部分能力安装、部分列授权或其他权限漂移均拒绝，不运行全量schema初始化或改动业务行。

回退先停止新后台，使用同一准确目标的`--schedule-edit-permissions disable`恢复原列权限后，再启动旧镜像。未知新编辑请求须先由新版沿原键核实，不以旧UI重新创建请求；存在未核实的新命令时不降级。计划、原任务、报告、历史和原预留不回滚。本轮原35444只读试用停在保存前，无需为普通镜像更新重新全量备份。

同一计划有未决原任务时，后续触发记录为跳过，不积压付费执行。默认补触发窗口为 15 分钟；过窗及遗漏的历史时刻保留为跳过记录。暂停期间收到的旧回调恢复后仍是同一跳过记录。即使一次预约从未收到回调，既有恢复循环也会补记过窗时刻并结束已无未来日期的计划；不创建补跑任务、不增加次数、不释放未知占用。DST 缺失本地时刻跳过，重复本地时刻最多执行一次。

改期或结束前，也会先按原规则补齐已过时刻的跳过历史；原规则不会被替换后抹掉遗漏记录。长中断期间分批补记返回待核实时，保留原操作键继续核实，完成后才确认规则／状态变更。

## 配置与启动

沿用 [Chat / 内容任务运行说明](../ai-workbench-chat-trial.md) 的正常登录、企业 allowlist、当前 IAM 服务授权、内容 Agent、Collection/Source、Review、模型准入及原积分服务。定时任务不保存浏览器 JWT，不制造 HTTP 身份，逐次按冻结的企业、操作者、成员向原 IAM 和业务 owner 复核。

在**获准的新安装**的私有 current-application manifest 中，已有的 `aiWorkbench` 配置另外加入：

```json
{
  "enabled": true,
  "contentTasks": true,
  "conversationOnly": false,
  "schedules": {
    "temporalAddress": "127.0.0.1:7233",
    "temporalNamespace": "<当前已创建的 namespace>"
  }
}
```

该片段不能替代原数据库、企业、模型、积分与 IAM 配置。Temporal 地址必须为显式 literal loopback 地址；复用现有 Temporal SDK 和客户端拨号，不另外运行一个进程内计时器。正常启动命令：

```powershell
go run ./cmd/current-application -config C:\private\current-application.json
```

新安装由现有 Workbench schema installer 与 runtime grant 安装当前 schema。运行构造只验证 schema 和最小权限，缺失定时表／字段时拒绝启动，不自动迁移、双写或覆盖旧表。历史精确空库补列工具不构成本次旧实例升级路径；保留实例升级与数据库操作需要另外确定范围。worker 启动失败使启动失败；退出时先停原 worker，再由原应用 owner 关闭 Temporal client。既有有界后台恢复循环按游标扫描登记与原回执，未决计划不会饿死后面的待登记计划。

## 已验证与限制

代码级和隔离运行证据包含：DST/漏槽/长中断；真实 PostgreSQL 原子 occurrence+BusinessTask、来源互斥 FK、幂等与修订冲突；暂停后旧回调；20 个未决计划之后的登记扫描；真实 Temporal dev server 的登记、暂停、恢复、旧修订拒绝和准确 nominal slot；真实 PostgreSQL + 合成模型 transport 的无浏览器执行、default/read_only、拒绝自动模式、组织停用、权限撤销、项目范围与原来源、用量未知保留占用；HTTP 提交后最终读回 503 的同键恢复。

前端单元回归覆盖请求结果未知的原命令保留、重载恢复和输入保留；浏览器 UI fixture 只验证界面交互与视口，不作为真实 provider 或部署验收。

当前新建入口只开放无模型的单店经营日报。已有商品内容计划继续生成待人工审核建议，支持默认与只读模式，拒绝自动批准／完全访问。含知识库的 Chat 提案暂不提供定时入口，服务端也明确拒绝；不自动换成无知识库执行。来源版本或配置变化后阻断原计划，需要用户重新确认当前方案。没有新增平台发布、批量旧任务补跑、金额阈值调度、任意 Agent 调用或新的账务 owner。

准确源码、CI、独立复核及原实例执行范围记录在当前Issue与PR；不把代码检查或受控浏览器夹具等同于真实模型、平台数据接通或用户产品验收。原35444已有日报生成/保存/刷新/下载与历史只读验证分别沿用对应有效证据，未变化路径不重复创建计划或部署。
# 删除计划

任务中心 → 定时任务 → 打开计划 → 删除计划。确认后不再安排后续执行，计划从默认列表移除；已经开始的任务继续处理，报告和执行记录保留，费用及预留不因删除变化。已结束的计划也能删除。结束和删除均使用统一确认弹窗，取消或 Esc 不提交操作。

已有开发实例启用此版本前，由原 Workbench schema owner 使用现有 `ai-workbench-schema-init --schedule-deletion-only --runtime-role ai_workbench_runtime` 入口，并显式传入 `--expected-database`、`--expected-server-address`、`--expected-server-port`；连接凭据仍通过本机受控环境变量 `AI_WORKBENCH_SCHEMA_DSN` 注入，不写入日志或页面。该入口只添加删除标记、约束和该列的有限更新权限，不删除业务数据。运行服务只读校验，不自动安装；无扩展时不会误报可用。

本轮 #1288 只交付实现及既有夹具验证，不包含原 35444 更新或实际计划删除。不重复创建环境、计划或备份；已删除计划不提供还原，按 ID 查看历史仍受原权限约束。
