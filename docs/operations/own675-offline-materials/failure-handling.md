# 分阶段失败处置（仅准备）

本说明复用现有 owner，不是自动回滚程序。当前没有执行安装、DDL/grant、生成凭据、创建卷/服务或修改实例；以下仅适用于将来明确授权的准确目标及候选。

## 执行前停止条件

- 真实应用/回调/私密文件未齐备时，停在材料阶段；不先改 Product 权限再尝试按原 Completion-only manifest 启动。
- 后续维护前刷新实例/容器/镜像/配置/角色及 schema 状态，沿原私密备份方式保留数据库、ACL/owner、配置/凭据、图片和卷基线。不能用本包或旧快照代替当次保留证据。
- Product 只接受原基线合格且新增 13 表全部缺失或全部合格；Asset 首次只接受新专属空库。角色/数据库名/归属、已有卷或 `7233` 占用有差异即停止，不能选择另一个业务库或放宽验证。
- 维护环境缺时区库时先处理 helper 运行环境；不得把建连拒绝误判成密码失效而轮换原凭据。保留错误日志及实际阶段，不在公开日志中打印 DSN、manifest 或一次性回调。

## 各边界的结果与下一步

| 阶段 / 失败 | 可确认的结果 | 处置边界 |
| --- | --- | --- |
| Product 事务内失败或取消 | 同一事务内新表/精确 grant 回滚 | 保留原 14 表/ACL，核对实际状态，不 DROP/修复漂移或改用空库安装 |
| Product 提交响应丢失 | 可能已提交，不能凭错误推定回滚 | 经实际执行授权与新状态核对后，同准确命令：完整 13 表只读核实；零表才首次安装；部分表/漂移拒绝 |
| Product 成功，但其他阶段未齐备 | 新权限已扩大到 SupplyChain 集合 | 不按旧 Completion-only manifest 直接重启；保持维护停止点，按下节另行批准停用方案 |
| Asset 建库/角色准备失败 | 不在 Asset 安装事务内 | 记录哪些新资源存在并保留；不假称与 Product/建库原子提交，不重建原库或删角色 |
| Asset 安装事务明确失败 | 该事务内四表及 grant 回滚；预建库/角色仍在 | 只读核对新库确实为空且归属不变后，才由获准维护者决定重新首次安装 |
| Asset 提交响应丢失或已成功 | 可能已有四表/ACL；空库 flag 再次执行会拒绝 | 先沿现有 schema/runtime verifier 的只读合同或经批准的 catalog 核对确认结果；不盲重放空库命令、不删表清空 |
| Asset 已有 schema 需要维护授权 | 不带空库 flag 的工具仍会 REVOKE/GRANT | 这不是只读重入。仅新专属 Asset 库、另有相应维护授权时才能使用，不对其他业务库“补授权” |
| Temporal 卷准备/启动失败 | 可能已创建新卷/容器 | 保留卷及内容，记录实际 owner/权限/健康；不递归 chown 旧卷、不 `down -v`，不占用其他实例的 Temporal |
| 后台启动拒绝或 UI 不可用 | 新能力未证明可用 | 保留错误和已完成阶段，核对 schema/ACL/私密文件 mode/真实应用/Temporal；不绕过准入或开前端假入口 |

Product、Asset 建库/角色、Asset schema、Temporal 卷、应用配置不构成整实例原子事务。中途停止应报告已完成/未执行/结果不确定的准确边界，保留资源，不自行清理。原 Store 对齐及版本记录不回退或重跑。

## 停用不是删除或盲目恢复旧镜像

Product 精确 grant 已提交后，只有原 manifest/原 UI 开关不足以完成停用。需先停相应写入口、保留支持现有数据合同的同候选程序；若需恢复 Completion-only 权限集合，应另行确认并仅撤回本轮 12 表精确授权 delta，核实旧能力准入。原 14 表/列 ACL、owner、业务记录不改；本包不附自动 REVOKE 脚本，也不以此说明授权实际撤权。

所有新增表、Target/幂等命令/Review/Asset 记录、Temporal 卷、图片、配置和备份保留，不 DROP/TRUNCATE、覆盖还原或重建原环境。产生 `sheinImport` 数据后，保留能读取该 DTO 的同候选或后续程序，不能降回丢弃元数据的旧镜像。需要停止新服务时先核对执行中操作，UNKNOWN 交原 owner，不自动 retry/resolve。

真实商家连接、规则读取、新测试商品/批次、Target R1 保存及带入预览/确认 R2，均属于后续单独获准的业务试用。当前材料通过静态检查不代表这些步骤已执行，也不代表发布或用户验收通过。
