# 自有商品优选申请

本文说明[多商品产品决定](../product/selected-application-multi-product.md)及已达
`IMPLEMENTATION_READY` 的[冻结设计](../architecture/selected-application-multi-product-v1.md)
对应的流程。源码候选不表示保留实例已经安装此版本；本轮不进行真实上传、申请或发布。
原路径保留供既有文档引用，旧单件交互范围已由 2026-10-17 用户决定替代。

入口：正常登录并选择企业后，进入“供应市场 → 优选申请 → 发起申请”，
路径为 `/workbench/supply/applications/new`。

1. **选择商品**：多选合格自有商品，搜索和翻页保留选择，每批最多 20 件，可逐件移除。
   未优化或资料不完整的商品仍显示为不可申请；选择后不会自动替换其来源版本。
2. **公共信息和逐件供货**：公共发货省市、售后和通用资质可复用；每件可取消继承，
   填写自己的发货地/售后、选择不引用通用附件，并保存商品专属资质。
   库存/产能、起订量、交期和价格逐件填写，不自动复制商品来源的库存或报价。
   取消继承时以当前公共值开始编辑，后续公共修改仅影响仍继承的商品。
3. **核对本批申请**：重新读取每件精确商品/Apply资格，逐件显示最终供货值、
   公共继承关系和资质引用。任何资格读取失败或版本变化都阻止使用旧快照。
   用户核对每件资料后明确勾选披露确认，再点击写明商品数量的提交按钮。
   返回修改后须重新确认；当前编辑内容在离开/刷新后不承诺保存。
4. **逐件结果**：每件使用独立请求键，生成独立申请并接受原有人工审核、补充资料、
   批准流程；从每件成功回执打开其申请详情。提交和批准均不产生自动发布。

## 公共附件和逐件差异

通用附件只复用同一企业/身份/成员下已保存的私密附件引用。每件合并通用及专属附件，
去重后需 1–6 件，单件最多 20 MiB、总计最多 60 MiB；服务端继续核验真实对象、
摘要、类型、大小和授权。附件的移除只移除本次引用，不删除原文件。

每件的上传待确认记录绑定稳定商品 ID，不能由另一商品接收。任一已选商品或公共附件
未确认时暂停汇总和正常编辑目标切换；若原商品在其它页面产生待确认上传，可明确返回
该商品的原附件继续核实。上传结束只更新对应附件字段，保留较新的供货输入。

发货省市共用已有联动下拉：先选省再选其城市，切省清空城市，不默认代选。
直辖市使用同名城市，省直管地区显示真实地区名称。省市名称来自固定版本
[@vant/area-data 2.2.0](https://www.npmjs.com/package/@vant/area-data/v/2.2.0)
的离线数据（MIT 许可），提交的 `province` / `city` 仍为中文名称。

## 部分失败和原请求恢复

- 按明确确认的顺序逐件提交，同时最多一件在途。已提交、明确失败、结果待确认、
  尚未处理分别展示，不把未知结果显示为失败或成功。
- 明确校验/版本/不存在写响应独立报错，可继续其它商品；不回滚已成功申请。
  全批无未决项后只将明确失败商品交回编辑，成功项不进入新的提交集合。
- 网络错误、异常回执、身份/企业/权限变化时暂停后续。保留不可变的原键及原资料，
  不创建替代键、不自动后台重发。已读到成功回执后再查不到回执时也不会重新发送。
- 刷新页面不自动 POST。“核实本批结果”仅查询每项原回执；404 或查询错误不证明
  未执行，也不会清除原请求。“使用原请求继续”在同一锁内先查询原回执、跳过成功项，
  对尚未取得回执的项才使用完全相同的原键/载荷继续，由现有服务端事务和幂等负责。
- 已明确提交的原请求集沿原 user/org member 的 localStorage 槽保存，最多 20 件且
  总计不超过 1 MiB；它不保存业务状态游标，也不是审核事实或未提交草稿库。
  其它自营、补充、选品等当前单件操作遇到本批未决时锁定新写并导回本申请页。
  浏览器存储损坏/不可写、锁不可用或原请求被其它页面更改时暂停写入，保留数据。
- 关闭页面会中止本地等待，不能据此推定服务器取消成功；恢复后核实原结果。
  没有整批原子性、后台自动跑完或整批批准/发布能力。

只有已有真实优化 Apply 且投影完整的 own 商品可申请。1688 采集、市场选入、SDS
等来源不扩入本轮；只有手工保存资料不构成优化证据。没有自有商品时可从空状态进入
“添加自有商品”。资格、来源版本、私密附件、每件申请/审核/回执仍由当前
SupplyMarket/Collection/Catalog/Apply 与私密文件 owner 保存，没有新表、迁移、服务端
批次 owner、跨件事务或第二事实源。

布局沿当前 Figma `997:764` / `1004:892`；逐件供货差异、汇总和结果由本次产品决定
补充。无当前合同的 ERP/插件来源及分类/状态过滤器不伪装为可用。
开发测试使用隔离模拟与既有测试设施；CI、代码评审不代替用户试用或真实产品验收。
