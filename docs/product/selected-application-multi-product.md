# 多商品优选申请产品决定

状态：2026-10-17 用户已授权设计及准入后的开发；未授权本轮新 PR 合并、实例更新或真实申请/发布。

Authority：Issue #710 当前正文及本会话直接用户决定：先设计多商品申请，明确公共信息复用、逐商品供货差异、独立审核、部分失败处理，再开发；保留现有数据和配置，不实际提交或发布。

## 用户结果

同一企业成员一次选择多件符合当前资格的自有商品，公共信息填一次，每件核对供货差异，汇总确认后看到逐件申请结果。每件仍独立评估、补充、批准和明确发布。

流程：选择商品 → 公共信息与逐商品差异 → 确认本批申请 → 逐件结果。

- 每批最多 20 件，沿现有每页 20 件的读取边界；搜索/翻页保留已选，可逐件移除，不自动选中不可申请项。
- 只有已有真实优化 Apply 且资料完整的 own 商品可选；每件保留其精确商品/Apply/版本。
- 公共信息为默认发货省市、售后说明和通用资质附件。每件可改用自己的发货地/售后、选择不引用公共附件，并添加商品专属附件。
- 库存/产能、起订量、交期、价格说明逐商品填写和确认，不从来源库存自动推定当前可供库存，不把总量复制到所有商品。
- 汇总逐件展示最终值、继承或独立值、附件引用及资格问题。一次明确披露确认只针对当前已列出的每件商品及最终资料；返回修改后必须重新确认。
- 每件使用独立请求键生成原有单件申请，各自审核/补充/批准；选择多件不赋予整批批准或自动发布权限。
- 已成功、明确失败、待确认、尚未处理分别显示。明确的逐件校验失败不撤销已成功申请，可继续其它项；身份/企业/权限异常或结果未知暂停后续，先核实原结果。
- 已成功商品不进入“修改失败商品”列表。待确认商品保持原键与原载荷，刷新或查询结果不自动重发，不把查不到回执当作未执行。

## 当前边界

本轮交付当前 SupplyMarket 内的有界交互及原命令集合的浏览器待确认记录，不新增服务端批次事实、整批原子事务、后台执行者或通用批处理/草稿平台。未点击最终提交的编辑内容仍属于当前页面，不承诺离开后的草稿持久化；显式提交后的原意图沿现有本地待确认机制保留。

公共附件只复用同一 organization/actor/member 下已保存的私密 receipt，不跨企业、成员、商品申请权限或私密对象 owner；每件合并去重后仍遵守 1–6 件、单件 20 MiB/合计 60 MiB 及签名/大小/真实对象核验。

Must 是权限/来源/逐件供货声明和原键安全性。不能通过默认同意、伪造资质、放宽 Apply 资格或自动重试完成批量。

Out of Scope：新来源/批量优化、改变审核状态机、整批审批/发布、跨企业共用、真正后台批任务、旧数据迁移/清理、AI/provider/积分/资金动作、真实上传/提交/发布、本轮新 PR 合并或实例部署。
