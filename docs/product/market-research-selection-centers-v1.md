## 1. 使用者与本次结果

使用者是当前企业中有相应权限的本人研究项目成员。目标操作：从国家、平台及关键词/类目/ASIN 的研究目标出发，整理有来源的样本资料和候选；进入选品视图，查看证据分析、补充人工判断，再将选中商品转入原待适配流程。

本次交付是可编辑 Figma 候选及下面的产品范围和页面合同，不是业务实现完成或用户验收。尚未实现的入口和 AI 能力只出现在设计候选中，不添加到当前运行系统。

## 3. 导航与页面归属（产品已确认）

| 入口/页面 | 已确认目标路由，当前未注册 | 主要职责与动作 |
| --- | --- | --- |
| 数据服务 → 市场调研中心 | `/workbench/data/research` | 列出本人 PRODUCT_RESEARCH 项目，搜索/选择项目；主动作“新建研究”复用原项目创建，成功进入研究详情 |
| 市场调研 → 项目研究详情 | `/workbench/data/research/{projectID}` | 目标 → 取得/关联资料 → 选择样本并核对证据 → 样本研究 → “进入选品评审” |
| 供应市场 → 智能选品中心 | `/workbench/supply/selection` | 按同一研究项目查找候选及已有决定；主动作“打开候选评审”，无候选时回到市场调研 |
| 智能选品 → 项目候选评审 | `/workbench/supply/selection/{projectID}` | 所选证据 → 2–5 事实比较 → 可选证据分析 → 人工审阅/理由/历史 → 原批次核对转入 |

项目中心继续是项目名称、目标、类型与归档的唯一管理入口，也提供进入上述两个视图的链接。两个中心的列表都是当前项目和研究 owner 的授权投影，不建立第二套项目或候选。数据市场仍是独立取得资料的完整页面；“我的数据”仍保存批次并执行原转入确认。

“新建研究”与“编辑目标”复用原项目表单；取消不创建或修改。研究列表与创建表单不混排。研究详情和评审详情使用明确返回位置；返回保留本人/企业范围内的搜索、筛选和选中项。企业/账号切换清除旧选择并拒绝迟到响应。

## 4. 研究视图：有范围的事实汇总

输入始终来自当前可读的准确观察。V1 汇总范围限于用户明确选择的 **2–5 个候选，各自当前明确选定的一份证据**；“本次所选样本”固定显示数量、站点、原查询身份（可得时）、原采集时间、来源版本和资料缺项。不把当前分页结果写成全部项目/批次或市场总量。

同币种、同单位且观察到的价格参与最小值/最大值；显示可比数量/所选数量。缺价不填零，不同币种分组，不能跨币种排序或计算统一范围。属性仅列实际存在且语义可比的原值，缺失明确未知，不为形成“共同属性”推断匹配。

汇总是只读派生视图，不新增市场事实表、独立研究报告状态或自动更新作业。证据变更、不可读或选择变化立即使当前汇总失效，需要重新读取；保留原冻结合同中的决定重置及旧历史语义。

例如，设计中所选 A/B/C 三项只有 A=19.99 USD、B=24.99 USD 可比，则显示“19.99–24.99 USD，可比 2/3”；C 缺价。此为排版示例，不是运行数据、市场价格带或研究结论。

## 5. 两中心交接与人工决定

“进入选品评审”只切换同一项目的视图，并携带原候选 ID/revision、选定证据身份与 digest。接收页沿当前研究 Service 重读授权和准确绑定；浏览器参数不作为商品事实。失效项提示重新选择；不自动换成最新证据，不静默丢项后继续分析。

切换中心不新增“已送选品”持久化事实、同步任务或新状态机。已有候选初态/待人工确认/批准测试/否决继续由 research owner 唯一管理。人工决定必须有当前 revision、选定证据与理由；AI 完成不能自动提交或批准。

“回到研究证据”返回相同项目与可验证选择。归档后两视图只读。撤权后按原 owner 遮蔽证据和关联模型输出；不从旧报告、浏览器缓存或副本补回内容。

## 6. 市场证据 AI：下一实施阶段的独立设计输入

现有 `product.selection.agent` 仅比较 Catalog 事实。新增分析必须使用版本明确的研究证据合同，不向旧 prompt 临时拼接研究 JSON，也不把旧对比结果改名成市场研究结果。

| 环节 | 本产品候选要求 | 正式实施前需补足的合同 |
| --- | --- | --- |
| 输入 | 当前用户明确选中 2–5 项，准确观察/版本/digest、样本范围、原值及 missing/warnings | 原授权 reader → 有界、冻结的 disclosure snapshot → 现有 Agent 准入/注入；字段和字节上限沿实际复用能力确定 |
| 输出 | 有证据引用的观察摘要、候选差异、待核实问题和建议；缺成本/需求证据不能推导盈利或畅销 | 版本化 proposal schema、受支持证据引用校验、原 run/result/history owner 和消费者 |
| 启动 | 显示将发送的资料范围、模型配置、最大用量/预算，由用户明确确认 | 原 Agent/Resource 的 prepare/run、权限、预算冻结、原键 lookup/retry/UNKNOWN；无第二计费或调度入口 |
| 保存与变化 | 把原 run 引用和准确 evidence digest 对应显示，建议与人工决定分开 | 原 run 持久化边界、来源/配置变化时的新披露拒绝及历史授权；不建立研究 AI 结果副本 |

上述产品方向已确认，公共接口和实施准入仍以新增技术合同及适用评审为准。新增 AI/披露边界采用 Independent Architecture；必须在正式代码前形成独立设计增量及适用评审并达到 IMPLEMENTATION_READY。原冻结合同不重审；仅导航/只读视图若完全复用其边界，可按 Reuse Existing Architecture 给出轻量依据。

## 7. 页面状态与正常恢复

| 状态 | 页面表达与可继续操作 |
| --- | --- |
| 无项目 | 列表显示空态；新建研究走原项目流程，不生成虚假候选或统计 |
| 无证据 | 研究详情允许“打开数据市场”或“关联已保存资料”；汇总/分析/转入不展示成功 |
| 采集未完成/挑战/失败 | 指向原任务的真实状态；已保存项仍沿原合同可查看，无自动补采或扩量 |
| 缺价/混币种/字段不足 | 明确缺项和可比范围；允许人工审阅，不生成总体需求/利润结论 |
| 未配置模型/额度不足 | 显示原因及原配置入口；证据、事实比较和人工决定仍可用 |
| 来源变化/撤权/读取超时 | 遮蔽或停止使用该证据，要求刷新/重新选择；不静默替换或标记分析成功 |
| 研究写或 AI/转入结果未知 | 分别沿 research、Agent、Preparation 原键核实；无自动重发、换键或重新扣费 |
| 跨批转入 | 按原批次分别核对非空子集，显示各自原回执；不承诺整体原子成功 |
