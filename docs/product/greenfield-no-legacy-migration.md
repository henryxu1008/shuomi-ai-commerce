# 全新系统开发基线：不兼容、不迁移历史数据

Product Decision: **PD-GREENFIELD-NO-LEGACY-MIGRATION-2026-09-08**<br>
Status: **APPROVED / ACTIVE**<br>
Authority: [Issue #365](https://github.com/qq550723504/task-processor/issues/365)

## 当前产品基线

后续业务任务一律按**全新安装、空业务数据、当前模型和当前产品需求**设计。历史 A/B1/B2、#364/PR #366、旧 C/D 分期和旧设计/测试仅保留为历史证据；它们不是未来迁移授权、实现前置或验收要求。

新系统不得承接旧业务历史：不开发旧数据迁移、导入或 backfill，旧 ID 映射，旧任务/结果续跑或恢复，旧 profile/登录态/目录复用，旧套餐、账务或权益承接。新用户、Organization、源账号、店铺连接、profile/登录态和权益都必须按当前合法创建、认证和初始化流程建立。

不得为了旧设计继续存在而新增旧 Service 包装、compatibility adapter、fallback、双读、双写、同步或第二事实源，也不得新增 tenantbridge consumer。发现旧代码时仍只按 Hard-Cut 的 `EXTRACT | RETIRE` 处理：可复用行为抽取到当前 owner，否则退休；没有 Compatibility 类别。

合格的现有能力和成熟开源组件可以复用，条件是它们符合当前职责、依赖和正确性，而不是它们曾属于旧设计。新系统自身正常的 Schema 演进不等于承接旧系统历史数据，也不能据此恢复旧数据迁移项目。

## 例外与真实环境边界

若新任务声称存在兼容义务，必须先提供**具体、当前的外部可观察契约证据**并报告用户；历史 Issue、PR、设计、测试或既有代码不能单独构成该证据，不能默认预建兼容路径。当前没有可执行的旧系统迁移/兼容 Exception；只有用户新的明确产品决定可以改变本禁令，Reviewer 或 Agent 无权自行放行。正常第三方 API、数据库驱动、平台 adapter 或当前模型供应商集成不属于旧系统历史迁移。

本决定不授权访问、迁移、删除或清理任何既有客户数据库、IAM、profile、账务、订单、对象存储或外部平台状态；环境隔离、归档或删除仍需独立范围和授权。新系统仍必须满足自身的授权、租户隔离、幂等、事务、审计、资源限制和凭据安全要求。

## Agent 开发依据（2026-11-02 用户决定）

项目按全新系统设计和开发，当前没有旧系统兼容、迁移、历史数据承接或旧执行续跑义务。Agent 从当前产品决定、已批准领域合同、真实源码入口及当前执行 Issue 读取本次范围，不从旧计划倒推需求。

当前工作树不保留 `docs/archive`、旧阶段计划或重复历史导航；原件通过固定 Git 提交追溯。正常开发不默认加载历史归档，不把旧文档、旧测试、旧实现或历史验收结果当作当前 Authority。具体排查需要引用历史时，明确其版本及用途，不能据此恢复已撤销要求。

本次决定替代此前要求归档资料常驻工作树、把旧迁移/阶段材料作为正常开发或验收前置的安排。仅检查已退出历史文本的断言随材料退出；对现行产品、安全、权限、事务、幂等、资源和恢复行为的检查继续保留。

现有代码能否复用，按当前需求、职责和正确性判断；发现不符合当前合同的代码仍需修复或退休。按全新系统开发不等于假定当前代码没有缺陷，也不授权删除现有数据、实例、凭据或外部资源。

## 退休工程完成后的文档基线

旧代码退休工程已完成。当前工作树只维护当前产品依据、领域合同、开发和运行说明；不保留退休矩阵、Legacy Register、阶段报告、旧方法版本和被完整替代的合同来作为开发前置。原件留在固定 Git 历史，正常开发不默认读取。

仍有效的规则直接写入当前合同。只检查旧过程资料、历史数字、排版或文档正文冻结的断言随资料退出；当前行为、安全、权限、事务、幂等、恢复、源码缺席和依赖禁入检查继续有效。原生安全测试本身不因文档清理改变。
